# 《万户天工》UI Prototype 项目概览

《万户天工》UI Prototype 是《万户天工》的独立交互式 UI 美术与流程原型。它用于在 Unity UI Toolkit 正式实现前，快速验证界面视觉、空间关系、交互层级和完整玩家流程。

## 项目定位

本仓库不是最终游戏客户端，也不是独立产品。它承担以下职责：

- 验证《万户天工》的 UI 美术语言与信息层级；
- 验证 Gameplay、Management、Workspace、Tool、Pause、Archive、Settings 等 UI Space 的空间关系；
- 验证交互流程、Esc 优先级、模式切换、Flyout、工具面板等行为；
- 通过固定 Review Scenario 和自动截图支持快速视觉审查；
- 为后续 Unity UI Toolkit 实现提供稳定的设计与交互参考。

最终实现仍以 Unity 项目中的 UI Toolkit 代码、UXML / USS 和运行时逻辑为准。本仓库负责先把设计问题解决清楚。

## 最终实现与 Web 原型边界

项目最终运行时 UI 明确使用 **Unity UI Toolkit**。

本仓库的 React / TypeScript / CSS 只负责快速表达：

- 美术效果；
- 构图与尺寸；
- 信息层级；
- 交互语义；
- 状态变化；
- 动效节奏；
- 图片、模糊、Tone、Glow 等目标视觉。

网页使用 CSS Grid、Gradient、Shadow、Filter、Pseudo Element、Keyframe 等能力，不表示 Unity 必须采用同样技术实现。

正式 Unity 应将这些视觉意图翻译为合适的：

- UXML；
- USS；
- C# 状态 / 事件；
- Sprite / 9-slice；
- Texture / RenderTexture；
- Painter2D / 自定义 Mesh；
- 必要的 URP 渲染能力。

当前计划使用 **URP 全屏 Blur Pass** 作为场景级模糊能力。Web 中的 `backdrop-filter` 仅作为视觉参考，不要求一比一迁移。

所有后续 UI 设计必须遵守：`Documentation/UI Toolkit落地规范.md`。

## 固定画布

原型使用固定 `1920 × 1080` 逻辑画布，并根据浏览器窗口进行整体等比缩放。这个约束用于模拟游戏 UI 的实际布局关系，而不是制作普通响应式网页。

这个 `1920 × 1080` 同时是 Unity UI Toolkit 正式实现的设计参考分辨率；正式项目通过统一 PanelSettings 缩放策略适配 1440p、4K 和其它常见分辨率，而不是手工复制多套 USS 数值。

## 当前主要 UI Space

### 顶层 Screen

- Main Menu
- New Game
- Load / Archive
- Settings
- Gameplay

### Gameplay 内部空间

#### Gameplay

默认经营状态使用统一 **Gameplay Top Shell**：

- 第一层 Persistent Status Row：资源、人口、天气、时间、相机、速度、菜单；
- 第二层 Management Navigation Row：纯图标的概况、户籍、财政、政策、商贸、治理、军务、图层；
- 右下 World Utility Toolbar；
- Main Dock；
- GameplayOperationHints。

此前独立的左侧 City Management Rail 和右上 Quick Controls 已退出运行布局，顶部导航和状态控制统一收束为一个控制岛。

World Utility Toolbar 是独立的全局世界编辑工具条，目前包含地图解锁、区域编辑、地形编辑、配色、网格吸附、网格显示、范围复制、范围移动、撤销和重做。它不承载建造分类，也不承载完成 / 取消等任务流程按钮。

#### Management

用于财政、户籍、政策、商贸、治理、军务等复杂系统。

- 中央大型阻挡式管理面板；
- 世界作为压暗 / 轻模糊背景继续存在；
- Gameplay Top Shell 两层保留；
- 一级管理系统由顶部 Management Navigation Row 直接切换；
- Management Surface 内不再重复一级分类 Tab；
- Main Dock、World Utility Toolbar 和世界操作提示隐藏。

Management 不使用 Right Edge Flyout。

#### Workspace

用于浏览和选择内容，例如 Building Workspace。

- Gameplay Top Shell 仅保留 Persistent Status Row；
- Workspace；
- Main Dock；
- World Utility Toolbar；
- Management Navigation Row 隐藏。

#### Tool

用于具体编辑工具，例如 Building Placement。

- Gameplay Top Shell 仅保留 Persistent Status Row；
- ToolOverlay；
- Tool Bottom Dock；
- World Utility Toolbar；
- GameplayOperationHints；
- Management Navigation Row 与 Main Dock 隐藏。

World Utility Toolbar 在 Tool 中继续保留全局 Grid / Undo 等状态；Tool Bottom Dock 只负责当前任务专用模式、参数、完成与取消。

#### Pause

Pause Layer 及其 Save / Settings 二级空间。

### 辅助空间

- Camera Right Edge Flyout；
- Weather Right Edge Flyout；
- Information Views Palette；
- Archive Space；
- Settings Space。

Camera / Weather 的入口已经并入 Gameplay Top Shell。Information Views 由顶部“图层”打开轻量 Palette。Right Edge Flyout 只服务轻量场景上下文，不承载复杂城市管理系统。

完整空间职责与互斥关系见：`Documentation/UI空间与状态架构.md`。

## 当前设计基调

- 黛墨 / 深青灰半透明 Surface；
- 浅纸色主文字；
- 暖金只用于 Selected、Focus 和高价值状态；
- 弱边界、小圆角或近直角；
- 游戏世界画面优先，不使用繁复古风装饰；
- 常驻 UI 信息尽量精简，解释性内容优先进入 Hover Tooltip；
- 信息做减法，但通过 Tone、材质、真实游戏内容、排版节奏和轻动效增加视觉层级；
- 同屏原则上只保留一个重面板，复杂管理进入 Management Space 后不再与建设工具同时争抢空间；
- Gameplay 顶部负责状态 / 管理；Main Dock 负责“建造什么”；World Utility Toolbar 负责“如何编辑世界”；Operation Hints 只负责输入说明。

## 当前底部方向

底部系统仍在继续调整，但职责已经分开：

- **Main Dock**：建造 / 内容分类；
- **World Utility Toolbar**：稳定放在右下，承载跨分类世界工具；
- **Tool Bottom Dock**：进入 Building Placement 等 Tool 后负责当前任务专用参数和完成 / 取消；
- **Operation Hints**：位于 World Utility Toolbar 上方，独立显示快捷键和当前操作说明。

后续优化 Main Dock 比例与美术时，不再把 World Utility Toolbar 合并回 Main Dock，也不在 Building Placement 内复制 Grid / Undo 工具。

## Visual Review

仓库通过 GitHub Actions 自动运行 Playwright 截图审查。Review Scenario 由 `src/app/scenarios.ts` 定义，并可通过 `?review=<scenario>` 直接进入稳定 UI 状态。

当前场景覆盖 Main Menu、New Game、Gameplay Top Shell、World Utility Toolbar、Management Space、Information Views、Building Workspace、Building Placement 多模式、Camera、Weather、Pause、Pause Save、Pause Settings、Load / Archive 等。

视觉修改完成后至少应满足：

1. `npm run build` 成功；
2. Visual Review 全部场景成功截图；
3. AI / 开发者实际打开并人工检查关键截图，不能只确认 Workflow 成功；
4. 截图发现问题后先修复并重新截图；
5. 对新增的重要结构确认其 Unity UI Toolkit 落地方式没有明显冲突。
