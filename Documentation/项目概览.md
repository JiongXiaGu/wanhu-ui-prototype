# 《万户天工》UI Prototype 项目概览

《万户天工》UI Prototype 是《万户天工》的独立交互式 UI 美术与流程原型。它用于在 Unity UI Toolkit 正式实现前，快速验证界面视觉、空间关系、交互层级和完整玩家流程。

## 项目定位

本仓库不是最终游戏客户端，也不是独立 Web 产品。它承担：

- 验证 UI 美术语言与信息层级；
- 验证 Gameplay、Management、Workspace、Tool、Pause、Archive、Settings 等 UI Space 的空间关系；
- 验证 Launcher、Esc 优先级、模式切换、Context Surface、工具面板等行为；
- 通过固定 Review Scenario 和自动截图支持快速视觉审查；
- 为最终 Unity UI Toolkit 提供稳定设计与交互参考。

最终实现仍以 Unity 项目中的 UXML / USS / C# 运行时逻辑为准。本仓库负责先把设计问题解决清楚。

## Web Prototype 与 Unity 边界

React / TypeScript / CSS 只负责快速表达：

- 美术效果；
- 构图与尺寸；
- 信息层级；
- 交互语义；
- 状态变化；
- 动效节奏；
- 图片、模糊、Tone、Glow 等目标视觉。

正式 Unity 应把这些视觉意图翻译为合适的：

- UXML；
- USS；
- C# 状态 / 事件；
- Sprite / 9-slice；
- Texture / RenderTexture；
- Painter2D / 自定义 Mesh；
- 必要的 URP 渲染能力。

当前计划使用 URP 全屏 Blur Pass 作为场景级模糊能力。Web `backdrop-filter` 仅作为视觉参考。

所有 UI 设计必须遵守：`Documentation/UI Toolkit落地规范.md`。

## 固定画布

原型使用固定 `1920 × 1080` 逻辑画布，并根据浏览器窗口整体等比缩放，用于模拟游戏 UI 实际空间关系，而不是制作普通响应式网页。

该分辨率也是 Unity UI Toolkit 的设计参考；正式项目通过统一 PanelSettings Scale Mode 适配其它分辨率，而不是复制多套 USS。

## Gameplay 当前屏幕分区

Gameplay 不再按“哪里有空就放哪里”的方式追加 UI，而是使用稳定槽位：

- **左上 Compass HUD**：常驻方向 / 南北轴判断；
- **顶部中央 Top Shell**：持续状态、资源、时间速度、场景 / 管理 / 数据一级入口；
- **右上 System / Notification Zone**：低存在感 Menu，未来事件、提醒和目标；
- **左下 Context Surface**：Camera / Weather，未来 Selection Inspector；
- **中下 Work Zone**：Main Dock、Design Workspace、Tool Bottom Dock；
- **右下 Utility Zone**：Operation Hints + World Utility Toolbar。

外围 HUD 默认遵守 `16px` Safe Edge，同级 Surface 常用约 `12px` 间距。

完整规则见 `Documentation/UI空间与状态架构.md`。

## Gameplay Top Shell

第一层 Persistent Status Row：

`天气 / 时间 │ 钱粮 / 人口 / 木材 / 石料 │ 模拟时间速度`

资源保持屏幕几何居中，速度使用纯图标的暂停 / 正常 / 加速 / 高速。

第二层 Control Tray：

`Camera / Weather │ 城市 / 经济 / 政策 / 军事 / 宫殿 │ Information Views`

所有入口常驻只显示图标，Hover Tooltip 提供名称。Menu 不再属于第二层。

## Compass HUD 与 System Menu

左上只保留约 `76×76px` 的简化指南针，不再保留常驻城市缩略图 / 小地图。四向使用中文 `东 / 南 / 西 / 北`，北向使用克制暖金强调；Building Placement 中会增强南北轴清晰度。正式 Unity 应接入实际相机水平朝向，让 Compass 随镜头旋转正确变化。

右上是独立低存在感 System Menu Button，用于进入 Pause。右上其它区域保留给未来 Notifications / Pending Events / Objectives。

这个分区遵循：**左侧是玩家主动查看的上下文，右侧是游戏主动推送的信息。**

## Context Surface

Camera / Weather 已不再使用 Right Edge Flyout，而是共用左下 Context Surface。

- Camera 宽约 360px；
- Weather 宽约 400px；
- 左 / 下都锚定 `16px` Safe Edge；
- 面板高度由内容决定，最大约 `720px`，即 1080p 逻辑画布 2/3；
- 超出高度只滚动 Body；
- 当前宽度与居中 Main Dock 横向不重叠，所以不再为了 Main Dock 向上留一整段空白；
- Camera / Weather 互斥，同入口再次点击关闭；
- 打开 Context Surface 会关闭 Design Workspace；
- 打开 Design Workspace 会关闭 Context Surface。

未来选中建筑 / 居民等对象时，左下优先承担 Selection Inspector；世界中可同时显示轻量 Anchor Label 表达对象指向。

## Management

复杂财政、政策、军务等系统进入中央大型阻挡式 Management Space。

- Top Shell 两层保留；
- 世界作为压暗 / 轻模糊背景；
- 顶部五个一级管理域直接切换；
- Management Surface 内不重复一级 Tab；
- Compass HUD、Main Dock、World Utility、Context Surface 和 Operation Hints 隐藏。

Management 不使用 Context Surface。

## Workspace

设计模式八个入口：

`道路 / 桥梁 / 建筑 / 台基 / 城墙 / 围墙 / 装饰 / 树木`

全部共用一个配置驱动的 Design Workspace。

打开 Workspace 后：

- Compass HUD 保留；
- Top Shell 两层保留；
- Main Dock 保留；
- World Utility / Operation Hints 保留；
- 点击 Camera / Weather 会先收起 Workspace，再打开左下 Context Surface。

Design Workspace 稳定结构：

`Header + Primary Rail + Context Filter + Search + 4×2 Asset Grid + Pager`

Asset Card 是 Action Button，不是 Toggle。Hover / Focus 详情使用共享 Asset Inspector。

## Tool

具体编辑任务进入 Tool，例如 Building Placement。

Tool 保留：

- Compass HUD；
- Top Shell 第一层；
- ToolOverlay；
- Tool Bottom Dock；
- World Utility Toolbar；
- Operation Hints；
- 右上 System Menu。

Tool 隐藏 Control Tray / Main Dock / Workspace / Context Surface。

World Utility 保留全局 Grid / Undo 等状态；Tool Bottom Dock 只承担当前任务专用模式、参数、完成与取消。

## Main Dock

Main Dock 左侧模式：

`设计 / 蓝图`

设计分类：

`道路 / 桥梁 / 建筑 / 台基 / 城墙 / 围墙 / 装饰 / 树木`

蓝图分类：

`全部 / 民居 / 商业 / 工坊 / 管理 / 科学 / 信仰 / 军事 / 宫殿`

默认 `dockCategory=null`，没有玩家明确选择就没有分类 Selected；切换设计 / 蓝图时清空分类，也不记忆两个模式上一次选择。

## World Utility Toolbar

右下 World Utility Toolbar 是跨分类世界辅助工具：

- 地图解锁；
- 区域编辑；
- 地形编辑；
- 配色；
- 网格吸附；
- 网格显示；
- 范围复制；
- 范围移动；
- 撤销；
- 重做。

不承载建造分类，不承载完成 / 取消等当前任务流程动作。

## Pause / Archive / Settings

Pause 是全局 UI Space，由右上 System Menu 或无局部 Surface 时的 Esc 打开。

Archive 与 Settings 是顶层全局管理空间，不属于 Gameplay Context Surface。

Settings 在 Main Menu 与 Pause 复用同一组件：

`显示 / 图形 / 音频 / 操作 / 游戏`

普通设置即时保存；危险显示设置使用 Safe Confirmation。

## 当前设计基调

- 深墨 / 玉青半透明 Surface；
- 浅纸主文字；
- 暖金只用于 Selected / Focus / On / Primary；
- `10 / 14 / 18px` 三档圆角家族；
- 世界画面是视觉主体；
- 常驻信息简洁，解释性内容进入 Tooltip / Inspector；
- 信息做减法，Tone、真实游戏内容、材质与轻动效负责增加层级；
- 不使用粗金边、卷轴、木纹、云纹等仿古装饰；
- 不把界面做成 SaaS Dashboard。

## Visual Review

仓库通过 GitHub Actions + Playwright 运行 1920×1080 Visual Review。

重要 UI 修改完成至少满足：

1. `npm run build` 成功；
2. Visual Review 场景成功；
3. AI / 开发者实际打开关键截图人工检查；
4. 截图有问题先修复，再重新 Review；
5. 新结构确认可合理迁移到 Unity UI Toolkit。

用户直接从 GitHub Actions 获取完整 Artifact；聊天中不需要重复打包完整 Review，只提供必要关键截图。
