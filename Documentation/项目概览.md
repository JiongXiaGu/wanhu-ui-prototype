# 《万户天工》UI Prototype 项目概览

《万户天工》UI Prototype 是《万户天工》的独立交互式 UI 美术、构图、信息架构与交互验证原型。它用于在 Unity UI Toolkit 正式实现前，把视觉和空间问题解决清楚。

## 项目定位

本仓库不是最终游戏客户端，也不是独立 Web 产品。它负责：

- 验证 UI 美术语言与信息层级；
- 验证 Gameplay / Management / Workspace / Tool / Pause / Archive / Settings 等 UI Space；
- 验证 Launcher、Esc、Context Surface、工具面板和主导航行为；
- 通过固定 Review Scenario 与自动截图支持持续视觉审查；
- 为 Unity UI Toolkit 提供稳定参考。

正式运行时仍使用 Unity：

- UXML；
- USS；
- C# 状态与事件；
- New Input System；
- Sprite / Texture / RenderTexture；
- Painter2D / Mesh；
- 必要的 URP 渲染能力。

Web `backdrop-filter` 只表达目标视觉。正式场景 Blur 使用共享 URP Blur Service / Fullscreen Pass，不给每个 Panel 单独建立 RenderTexture Blur。

## 当前视觉方向

正式材质母版为 **Smoked Graphite / 烟墨石质 + Paper White / 暖纸 + Aged Brass / 熟铜**。

- Design Workspace 当前视觉作为 Work Surface 锚点；
- Gameplay 结构 Surface 使用中性或略暖 Graphite，不维护独立绿色 / 蓝色面板主题；
- Context / Work / Blocking / Elevated 通过视觉重量、Density、Shadow 与 Occlusion 区分，不通过 Hue 区分；
- Context 更轻不等于必须更透明，尤其不能让植被背景把面板染绿；
- Paper White 负责阅读；
- Aged Brass 只用于 Selected / Focus / On / Primary / Current；
- Cinnabar 仅用于真正 Warning / Danger；
- 世界画面负责主要色彩，UI 主动退后；
- Blur 保留低频世界环境感，但 Surface 自身保证可读；
- Header 使用 Bare Icon + Title；
- 昼夜使用同一 Palette，不建立独立 Night Theme。

权威材质规范：`Documentation/Wanhu 烟墨熟铜视觉材质规范.md`。

## Gameplay 屏幕分区

稳定槽位：

- **左上 Compass HUD**：方向 / 南北轴；
- **顶部中央 Top Shell**：持续状态、快捷指标、模拟速度、一级入口；
- **右上 System / Notification Zone**：System Menu，未来事件 / 目标 / 通知；
- **左下 Context / Parameter Zone**：Camera / Weather；Tool 中为参数面板；未来 Selection Inspector；
- **中下 Work Zone**：Main Dock / Design Workspace / Placement Action Bar；
- **右下 Utility Zone**：Operation Hints + World Utility Toolbar。

外围 HUD 默认 `16px` Safe Edge，同级 Surface 常用约 `12px` 间距。

## Gameplay Top Shell

### Persistent Status Row

左：当前天气 + 季节 / 时间。

中：四个仅显示 **Icon + Number** 的 Metric Shortcut：

- 人口 → 城市；
- 金钱 → 经济；
- 贸易值 → 库存；
- 军事值 → 军事。

顶部四项只负责摘要和快捷打开，不拥有 Selected / Active；真正的当前 Management 状态由下方主导航表达。

右：纯图标模拟速度 `暂停 / 正常 / 加速 / 高速`。

### Control Tray

正式顺序：

`Camera / Weather │ 城市 / 经济 / 库存 / 政策 / 军事 │ Information Views`

- 左侧是场景观察 / 调整；
- 中间是一级管理主导航；
- 右侧是数据观察；
- 常驻只显示图标，Tooltip 提供名称；
- Control Tray 才拥有 Management 的 Selected / Active 状态。

## Compass / System Menu

Compass：

- 约 `76×76px`；
- 中文东南西北；
- 北向熟铜强调；
- 不做复杂风水罗盘；
- 正式 Unity 绑定真实 Camera Heading。

右上 System Menu Button 进入 Pause；与顶部模拟时间暂停严格区分。右上余量留给 Notification / Pending Event / Objective。

## Context Surface

Camera / Weather 共用左下 Context Surface：

- Camera 约 `360px`；
- Weather 约 `400px`；
- 左 / 下 `16px`；
- 最大高度 `720px`；
- 超高只滚 Body；
- 与 Design Workspace 当前互斥；
- Tool / Management / Pause 中关闭。

Environment 与 Workspace Header 共用 Bare Icon + Title 语言，图标略大于文字但视觉上不形成 Button Chip。

未来 Selection Inspector 优先落在同一槽位，可配合世界 Anchor Label。

## Management

当前 Control Tray 一级域：

`城市 / 经济 / 库存 / 政策 / 军事`

复杂管理进入中央 Blocking Management Space：

- 世界轻度弱化后仍可见；
- Top Shell 保留；
- Main Dock / Context / Utility 等竞争区域隐藏；
- Management 内不重复一级导航。

### Topic Header Variant

Management 各专题共享同一个 Blocking Body，只在 Header / Data Accent 上建立轻量主题身份：

- `overview`：城市概况，Warm Stone；
- `civic`：户籍民生，Muted Clay；
- `economy`：财政 / 商贸，Aged Brass Economy；
- `resource`：库存 / 资源，Muted Olive；
- `governance`：政策 / 城市治理，Muted Slate；
- `defense`：军务，Muted Cinnabar。

主题色不扩散到整个 Body，不改变基础 Button / Toggle / Focus 语义。Panel Root、Section、Row、Paper Text 继续使用统一 Smoked Graphite / Paper 系统。

### Inventory

库存用于查看城市和附近村庄的物资存储与供应关系。

当前三页：

- **总览**：资源总量、城市库存、村庄专项储量、日变化、资源状态；
- **城市仓库**：仓库容量、占用、用途、入出库、实际存储内容；
- **周边村庄**：每个村庄一种专项资源，显示储量、日产、距离、路线、目标仓库和运输状态。

顶部“贸易值”以商货总值作为摘要，点击进入库存。

## Information Views

属于“观察城市”而不是“管理城市”。当前：

`默认 / 地价 / 人口 / 商业 / 道路 / 治安 / 水利`

入口位于 Control Tray 最右；Palette 轻量展开，具体信息主要表现到世界地图。

## Main Dock

模式：`设计 / 蓝图`

设计：`道路 / 桥梁 / 建筑 / 台基 / 城墙 / 围墙 / 装饰 / 树木`

蓝图：`全部 / 民居 / 商业 / 工坊 / 管理 / 科学 / 信仰 / 军事 / 宫殿`

默认 `dockCategory=null`。切换设计 / 蓝图清空分类，不记忆两模式的上一次分类。只有用户明确点击分类才 Selected。

Blueprint Workspace 尚未实现。

## Design Workspace

设计八类共用配置驱动 Workspace：

`Header + Primary Rail + Context Filter + 4×2 Asset Grid + Pager`

稳定基线：

- Workspace 约 `1240×370`；
- Primary Rail 约 `146px`；
- 8 项 / 页；
- Preview `64×64`；
- Asset Card 是 Action Button，不是 Toggle；
- Workspace 使用烟熏 Graphite Glass；
- Header 比 Body 更轻，Body 保证阅读稳定；
- Header 裸图标约 `18px`，标题约 `16px`；
- 不使用黑色桌面应用窗口、Icon Chip、梁头或完整外框。

Asset Inspector 使用 Elevated Surface，并保留清楚的方向性边缘与阴影。

## Tool / Placement

当前已有 Building / Road Placement，以及直接从 World Utility 进入的 Terrain Edit World Tool。

稳定空间职责：

- 左：Tool Parameter Panel；
- 中下：共享 Tool Action Bar；
- 右下：Context Utility Toolbar。

Building：Terrain Mode + 位置 / 楼身 / 屋顶 / 立面 + Rotate / Mirror + 完成 / 取消。

Road：智能曲线 / 曲线 / 直线 + 反转方向 + 完成 / 取消。

Terrain Edit：抬高 / 降低 / 整平 / 平滑 / 坡面 + 笔刷参数 + 完成；右下提供等高线 / 坡度视图 / 保护已建区域 / Undo / Redo。

Building / Road 的 Grid / Undo / Redo 通过 Context Utility 提供；Terrain 使用自己的 Context Utility Definition，不强行保留 Grid Snap。

## Bottom Command Visual System

Gameplay 底部三个 Toolbar 是同一视觉家族：

- Main Dock = L；
- Placement Action Bar = M；
- World Utility = S。

共享材质、Radius、Hover / Active、Divider、Tooltip 与图标语言；尺寸、Surface Tier 和 Shadow 用于建立层级。

### Motion

UI 动效统一由 Motion System 表达空间归属：

- Bottom：向下收起；
- Left：向左收起；
- Top：向上收起；
- Center：轻微向下收起；
- 业务状态立即切换，Presentation 使用短 Exit 后再卸载；
- 大型 Surface 不动画 Width / Height。

完整规则见 `Documentation/UI Motion System设计规范.md`。

## 状态与 Esc

Gameplay 主空间优先级：

`Pause > Tool > Workspace > Management > Gameplay`

主要 Launcher 状态集中在 `GameplayUiState` / reducer。顶部 Metric Shortcut 是单向快捷入口，不维护第二份导航状态。

Esc 当前顺序：

1. Dialog / Safe Confirmation；
2. Context Surface；
3. Information View Palette；
4. Tool；
5. Workspace；
6. Management；
7. 非默认 Map View；
8. Pause。

## 样式与维护

当前正式视觉已稳定，但历史开发产生过多 `Pass vN` 覆盖文件。维护目标是把它收束为：

`Theme Tokens → Surface System → Control System → Component Geometry`

当前 P0 原则：

- Runtime 不常驻 A/B/C Study CSS；
- Review Study 放在 `src/review/styles/`，仅 Review URL 动态加载；
- 已退出运行结构的旧 Selector 删除；
- 当前 Smoked Graphite / Paper / 熟铜是统一 Theme 的正式迁移基线。

详见：`Documentation/代码审查/2026-09-17-统一皮肤与可维护性审查.md`。

### Unity Migration Guard

仓库现在执行 `npm run audit:unity`：

- 阻止 Runtime CSS `:has()`；
- 阻止未声明属性的 Transition shorthand；
- 追踪 backdrop-filter / Grid / pseudo-element / filter / Browser API 债务；
- 输出当前 Lucide Source Icon 清单；
- 新 backdrop-filter Owner 不在审核列表时直接失败。

这套 Guard 用于防止后续 Web Demo 功能继续增长时引入无法解释的 Unity 实现，而不是要求原型立刻变成 USS。

## 验证流程

重要 UI 修改默认：

1. 更新代码与对应设计文档；
2. 执行 `npm run audit:unity`；
3. 执行 Build；
4. 检查受影响的状态、交互、样式所有权与 Unity UI Toolkit 映射；
5. 有问题先修，再提交到 `main`。

GitHub Actions Visual Review 与自动截图 Artifact 已退出默认流程。现有 Playwright capture 脚本仅作为手动调试工具保留，不自动运行。

## New Game Global Space

New Game 与 Settings / Load / Save 同属全屏 Global Space：

- Root 必须挂载 `.wanhu-global-space`；
- Header / Footer / Smoked Graphite Material 直接消费共享 Global Space Visual System；
- 地图浏览 + 右侧开局方案的双栏信息架构保留；
- 地图 Card 默认中性，Selected 使用弱 Brass Tone + 2px 状态线，不使用完整金边；
- “随机地图”Badge 只是中性 Metadata，不使用熟铜做分类；
- 游戏模式 / 地图尺寸使用中性 Segmented Field，Active 才使用熟铜；
- 城市名称 / 随机种子只显示 Value Button，实际输入进入统一 Dialog。
