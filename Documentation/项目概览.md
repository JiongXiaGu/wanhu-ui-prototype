# 《万户天工》UI Prototype 项目概览

《万户天工》UI Prototype 是《万户天工》的独立交互式 UI 美术与流程原型。它用于在 Unity UI Toolkit 正式实现前，快速验证界面视觉、空间关系、交互层级和完整玩家流程。

## 项目定位

本仓库不是最终游戏客户端，也不是独立 Web 产品。它承担：

- 验证 UI 美术语言与信息层级；
- 验证 Gameplay、Management、Workspace、Tool、Pause、Archive、Settings 等 UI Space；
- 验证 Launcher、Esc 优先级、模式切换、Context Surface、工具面板等行为；
- 通过固定 Review Scenario 和自动截图支持持续视觉审查；
- 为最终 Unity UI Toolkit 提供稳定设计与交互参考。

最终实现仍以 Unity 项目中的 UXML / USS / C# 运行时逻辑为准。本仓库负责先把设计问题解决清楚。

## Web Prototype 与 Unity 边界

React / TypeScript / CSS 负责快速表达：

- 美术效果；
- 构图与尺寸；
- 信息层级；
- 交互语义；
- 状态变化；
- 动效节奏；
- 图片、Blur、Tone、Glow 等目标视觉。

正式 Unity 应翻译为：

- UXML；
- USS；
- C# 状态 / 事件；
- Sprite / 9-slice；
- Texture / RenderTexture；
- Painter2D / 自定义 Mesh；
- 必要的 URP 渲染能力。

Web `backdrop-filter` 仅作为视觉参考。正式 Blur 使用共享 URP Blur Service / Fullscreen Pass，不给每个 Panel 单独建立 RenderTexture Blur。

正式约束：

- `Documentation/UI Toolkit落地规范.md`
- `Documentation/UI Surface与Control视觉规范.md`

## 固定画布

原型使用固定 `1920 × 1080` 逻辑画布，并根据浏览器窗口整体等比缩放，用于模拟游戏 UI 实际空间关系，而不是制作普通响应式网页。

正式 Unity 使用统一 PanelSettings Scale Mode 适配其它分辨率，不复制多套 USS。

## Gameplay 当前屏幕分区

Gameplay 使用稳定槽位：

- **左上 Compass HUD**：常驻方向 / 南北轴判断；
- **顶部中央 Top Shell**：持续状态、资源、时间速度、场景 / 管理 / 数据入口；
- **右上 System / Notification Zone**：低存在感 Menu，未来事件 / 提醒 / 目标；
- **左下 Context / Parameter Zone**：Camera / Weather；Tool 中为参数面板；未来 Selection Inspector；
- **中下 Work Zone**：Main Dock、Design Workspace、Placement Action Bar；
- **右下 Utility Zone**：Operation Hints + World Utility Toolbar。

外围 HUD 默认 `16px` Safe Edge，同级 Surface 常用约 `12px` 间距。

完整规则：`Documentation/UI空间与状态架构.md`。

## Gameplay Top Shell

第一层 Persistent Status Row：

`天气 / 时间 │ 钱粮 / 人口 / 木材 / 石料 │ 模拟时间速度`

资源保持屏幕几何居中，速度使用纯图标的暂停 / 正常 / 加速 / 高速。

第二层 Control Tray：

`Camera / Weather │ 城市 / 经济 / 政策 / 军事 / 宫殿 │ Information Views`

所有入口常驻只显示图标，Hover Tooltip 提供名称。Menu 不属于第二层。

## Compass HUD 与 System Menu

左上只保留约 `76×76px` 的简化指南针，不保留常驻城市缩略图 / 小地图。四向使用中文 `东 / 南 / 西 / 北`，北向克制暖金强调。正式 Unity 接实际 Camera Heading。

右上独立低存在感 System Menu Button 进入 Pause；其它区域留给 Notifications / Pending Events / Objectives。

原则：**左侧是玩家主动查看的上下文，右侧是游戏主动推送的信息。**

## Context Surface

Camera / Weather 共用左下 Context Surface：

- Camera 约 360px；
- Weather 约 400px；
- 左 / 下 16px；
- 高度内容驱动，最大约 720px；
- 超高只滚动 Body；
- Camera / Weather 互斥，同入口再次点击关闭；
- Context Surface 与 Design Workspace 当前互斥；
- 使用 Context Surface Tier，比 Tool Parameter 更透明地保留世界画面。

未来选中建筑 / 居民时，左下优先承担 Selection Inspector，世界中可同时显示轻量 Anchor Label。

## Gameplay Glass Surface

Workspace / Context / Tool Parameter Panel / Top Shell / Bottom Command 都使用“玉青 Tint + 弱 Blur”的共享视觉方向，并按任务强度固定分成四档：

- Ambient：约 `.66–.74`，用于 Compass、System Menu、World Utility、Operation Hints 等低干扰 HUD；
- Context：约 `.76–.82`，用于 Camera / Weather、Top Control Tray、Workspace Header；
- Work：约 `.82–.88`，用于 Top Status、Main Dock、Workspace Body、Tool Parameter、Placement Action Bar；
- Blocking：约 `.92–.94`，用于 Management、Pause、Settings、Archive 等重空间。

稳定规则：

- 只降低 Surface Tint / Alpha，不给整个组件设置统一 `opacity`；
- Text / Icon / Border / Active 状态保持固定对比度；
- Blur 只提供低频环境色；
- 昼夜使用同一套 Surface Tier，不增加独立 Night Theme；
- Surface 自己承担基础明度、Tint 与文字对比；
- 夜景下不让 UI 跟世界一起黑下去。

详细规则：`Documentation/UI Surface与Control视觉规范.md`。

## Management

复杂财政、政策、军务等进入中央大型 Management Space：

- Top Shell 两层保留；
- 世界压暗 / 轻模糊后继续可见；
- 顶部五个一级管理域直接切换；
- Management 内不重复一级 Tab；
- Compass、Main Dock、World Utility、Context、Operation Hints 隐藏。

## Design Workspace

设计模式八个入口：

`道路 / 桥梁 / 建筑 / 台基 / 城墙 / 围墙 / 装饰 / 树木`

全部共用配置驱动 Design Workspace：

`Header + Primary Rail + Context Filter + Search + 4×2 Asset Grid + Pager`

- Primary Rail 约 146px；第一项 `所有`；每组最多 7 项；
- Content Grid 8 项 / 页；
- Preview 64×64、1:1；
- 名称约 14.2px；
- Asset Card 是 Action Button，不是 Toggle；
- Hover / Focus 使用共享 Asset Inspector；
- Header 使用 Context Tier，Body 使用 Work Tier。

正式规则：`Documentation/Design Workspace设计规范.md`。

## Tool / Placement

当前已有：

- Building Placement；
- Road Placement。

Tool 稳定职责：

- 左：Tool Parameter Panel；
- 中下：Placement Action Bar；
- 右下：World Utility Toolbar。

Building Action Bar：地形模式 + 位置 / 楼身 / 屋顶 / 立面 + 旋转 / 镜像 + 完成 / 取消。

Road Action Bar：智能曲线 / 曲线 / 直线 + 反转方向 + 完成 / 取消。

详细数值只放左参数面板，Grid / Undo 等全局能力继续留在 World Utility。

正式规则：`Documentation/Placement Tool设计规范.md`。

## Bottom Command Visual System

Gameplay 底部三类 Toolbar 共用一套美术：

- Main Dock = L，76px；
- Placement Action Bar = M，68px；
- World Utility = S，56px。

共享 Tint / Border / Radius / Hover / Active / Divider / Tooltip；尺寸、密度、Shadow 与固定 Transparency Tier 建立层级。当前 Main Dock 使用较轻 Work、Placement 使用稳定 Work、World Utility 使用 Ambient。

正式规则：`Documentation/Bottom Command Visual System设计规范.md`。

## Main Dock

模式：`设计 / 蓝图`

设计：`道路 / 桥梁 / 建筑 / 台基 / 城墙 / 围墙 / 装饰 / 树木`

蓝图：`全部 / 民居 / 商业 / 工坊 / 管理 / 科学 / 信仰 / 军事 / 宫殿`

默认 `dockCategory=null`；切模式清空分类；不记忆两模式上一次分类。

## World Utility Toolbar

当前：

- 地图解锁；
- 区域编辑；
- 地形编辑；
- 配色；
- 网格吸附；
- 网格显示；
- 范围复制；
- 范围移动；
- 撤销；
- 重做。

不承载建造分类和完成 / 取消。

## Segmented Control

Camera / Weather / Building Placement / New Game 等局部互斥模式共用 Segmented Control 视觉：

- 外壳 10px Radius；
- Option 8px Radius；
- 弱 Surface / Border；
- 明确 Hover；
- 暖金 Active Tone。

不能再做成只靠文字颜色区分的“假按钮”。

## Pause / Archive / Settings / New Game Footer

Settings / New Game / Load / Save 的底部 Action 使用共享：

- `global-space-footer`；
- `global-space-primary`；
- `global-space-secondary`；
- Utility Action。

Primary / Secondary 使用 10px 轻圆角，Utility 通常 8px；Footer 使用轻玉青半透明 Surface + Blur。单页不再复制 `1px / 2px` 旧按钮样式。

Settings 在 Main Menu 与 Pause 复用同一组件：

`显示 / 图形 / 音频 / 操作 / 游戏`

普通设置即时保存；危险显示设置使用 Safe Confirmation。

## 当前设计基调

- 深墨 / 玉青半透明 Surface；
- Ambient / Context / Work / Blocking 固定透明度层级；
- 浅纸主文字；
- 暖金只用于 Selected / Focus / On / Primary；
- `8 / 10 / 14 / 18px` 常用圆角层级；
- 世界画面是视觉主体；
- 常驻信息简洁，解释进入 Tooltip / Inspector；
- 信息做减法，Tone、真实游戏内容、材质与轻动效负责层级；
- 不使用粗金边、卷轴、木纹、云纹等仿古装饰；
- 不做 SaaS Dashboard。

## Visual Review

重要 UI 修改至少满足：

1. `npm run build` 成功；
2. Visual Review 成功；
3. AI / 开发者实际打开关键截图人工检查；
4. 截图有问题先修复再重新 Review；
5. 新结构能合理迁移到 Unity UI Toolkit。

当前 Review 额外覆盖共享 Visual System：Gameplay Panel Blur、Building Segmented、Settings / New Game / Load / Save Footer Radius / Blur、昼夜背景硬切，以及白天 / 夜晚 Surface Transparency Hierarchy。

用户直接从 GitHub Actions 获取完整 Artifact；聊天不重复打包，只提供必要关键截图。
