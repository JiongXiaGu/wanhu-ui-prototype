# 《万户天工》UI Prototype 项目概览

《万户天工》UI Prototype 是《万户天工》的独立交互式 UI 美术与流程原型。它用于在 Unity UI Toolkit 正式实现前，快速验证界面视觉、空间关系、交互层级和完整玩家流程。

## 项目定位

本仓库不是最终游戏客户端，也不是独立产品。它承担以下职责：

- 验证《万户天工》的 UI 美术语言与信息层级；
- 验证 Gameplay、Management、Workspace、Tool、Pause、Archive、Settings 等 UI Space 的空间关系；
- 验证交互流程、Esc 优先级、模式切换、Flyout、工具面板等行为；
- 通过固定 Review Scenario 和自动截图支持快速视觉审查；
- 为后续 Unity UI Toolkit 实现提供稳定的设计与交互参考。

最终实现仍以 Unity 项目中的 UI Toolkit 代码、UXML / USS 和运行时逻辑为准。本仓库负责先把设计问题解决清楚。

## 最终实现与 Web 原型边界

项目最终运行时 UI 明确使用 **Unity UI Toolkit**。

本仓库的 React / TypeScript / CSS 只负责快速表达：

- 美术效果；
- 构图与尺寸；
- 信息层级；
- 交互语义；
- 状态变化；
- 动效节奏；
- 图片、模糊、Tone、Glow 等目标视觉。

网页使用 CSS Grid、Gradient、Shadow、Filter、Pseudo Element、Keyframe 等能力，不表示 Unity 必须采用同样技术实现。

正式 Unity 应将这些视觉意图翻译为合适的：

- UXML；
- USS；
- C# 状态 / 事件；
- Sprite / 9-slice；
- Texture / RenderTexture；
- Painter2D / 自定义 Mesh；
- 必要的 URP 渲染能力。

当前计划使用 **URP 全屏 Blur Pass** 作为场景级模糊能力。Web 中的 `backdrop-filter` 仅作为视觉参考，不要求一比一迁移。

现有网页不因为纯技术差异而大规模返工。只有当结构、交互、性能成本或信息架构本身不适合 Unity 时，才修改 Web 设计。

所有后续 UI 设计必须遵守：`Documentation/UI Toolkit落地规范.md`。

## 固定画布

原型使用固定 `1920 × 1080` 逻辑画布，并根据浏览器窗口进行整体等比缩放。这个约束用于模拟游戏 UI 的实际布局关系，而不是制作普通响应式网页。

这个 `1920 × 1080` 同时是 Unity UI Toolkit 正式实现的设计参考分辨率；正式项目通过统一 PanelSettings 缩放策略适配 1440p、4K 和其它常见分辨率，而不是手工复制多套 USS 数值。

## 当前主要 UI Space

### 顶层 Screen

- Main Menu
- New Game
- Load / Archive
- Settings
- Gameplay

### Gameplay 内部空间

#### Gameplay

默认经营状态：

- Global HUD；
- Quick Controls；
- City Management Rail；
- Information Views；
- Utility Toolbar；
- Main Dock。

#### Management

用于财政、户籍、政策、商贸、治理、军务等复杂系统。

- 中央大型阻挡式管理面板；
- 世界作为压暗 / 轻模糊背景继续存在；
- Global HUD 保留并弱化；
- 隐藏 Normal Gameplay 的管理 Rail、Dock 与其它场景操作控件；
- 管理系统在同一 Management Space 内通过 Tab 切换。

Management 不使用 Right Edge Flyout。

#### Workspace

用于浏览和选择内容，例如 Building Workspace。

- Workspace；
- Main Dock；
- City Management Rail 隐藏。

#### Tool

用于具体编辑工具，例如 Building Placement。

- ToolOverlay；
- Tool Bottom Dock；
- GameplayOperationHints；
- City Management Rail 与 Main Dock 隐藏。

#### Pause

Pause Layer 及其 Save / Settings 二级空间。

### 辅助空间

- Camera Right Edge Flyout；
- Weather Right Edge Flyout；
- Information Views Palette；
- Archive Space；
- Settings Space。

Right Edge Flyout 只服务轻量场景上下文，不承载复杂城市管理系统。

完整空间职责与互斥关系见：`Documentation/UI空间与状态架构.md`。

## 当前设计基调

- 黛墨 / 深青灰半透明 Surface；
- 浅纸色主文字；
- 暖金只用于 Selected、Focus 和高价值状态；
- 弱边界、小圆角或近直角；
- 游戏世界画面优先，不使用繁复古风装饰；
- 常驻 UI 信息尽量精简，解释性内容优先进入 Hover Tooltip；
- 信息做减法，但通过 Tone、材质、真实游戏内容、排版节奏和轻动效增加视觉层级；
- 同屏原则上只保留一个重面板，复杂管理进入 Management Space 后不再与建设工具同时争抢空间。

详细规则见：

- `Documentation/UI设计原则.md`
- `Documentation/UI Toolkit落地规范.md`

## Visual Review

仓库通过 GitHub Actions 自动运行 Playwright 截图审查。Review Scenario 由 `src/app/scenarios.ts` 定义，并可通过 `?review=<scenario>` 直接进入稳定 UI 状态。

当前场景覆盖 Main Menu、New Game、Gameplay、Management Space、Information Views、Building Workspace、Building Placement 多模式、Camera、Weather、Pause、Pause Save、Pause Settings、Load / Archive 等。

视觉修改完成后至少应满足：

1. `npm run build` 成功；
2. Visual Review 全部场景成功截图；
3. AI / 开发者实际打开并人工检查关键截图，不能只确认 Workflow 成功；
4. 截图发现问题后先修复并重新截图；
5. 对新增的重要结构确认其 Unity UI Toolkit 落地方式没有明显冲突。
