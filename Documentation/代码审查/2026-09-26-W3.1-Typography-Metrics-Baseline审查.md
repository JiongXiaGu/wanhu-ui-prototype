## 结果

### 缩放不是根因

所有进入 1080p / 4K 对照的样本在以下项目上完全一致：

- font-size
- line-height
- 归一化 element height
- 归一化 text center offset
- 归一化 Icon/Text offset

因此当前 Web 的固定 1920×1080 Canvas 缩放不会产生这轮观察到的文字偏移。

### 普通控件基本居中

代表样本：

| Consumer | Font | Vertical Offset |
| --- | ---: | ---: |
| Top HUD Resource | 11px | -0.5px |
| Parameter Label | 11px | 0px |
| Parameter Value | 11px | 0px |
| Settings Tab | 12px | 0px |
| Settings Label | 12px | -0.5px |
| Resolution | 12px | 0px |
| Binding | 12px | 0px |
| Archive Group | 13px | 0px |
| Archive Save | 14px | 0px |

Main Dock / Secondary Action 的 +15.172px 是预期 Icon Top / Label Bottom 布局，不作为居中缺陷。

### 标题是下一批重点

16px Left Context / Design Workspace Title：

- CSS line-height：17.28px
- 元素逻辑高度约 17.27px
- CJK Range text rect：约 24px
- 中心偏移约 -0.63px
- Canvas TextMetrics actualAscent / descent：14 / 2

这类“字形墨迹框明显大于 CSS line box”的情况更容易在 Unity TextCore / Font Asset 中出现不同 baseline 感知，因此 W3.2 应先对齐标题，而不是先扫全仓小字号。

### Computed Style 权威

Design Building Card：

- 较早通用规则存在 14.2px
- 实际 Computed Style 为 11.5px
- 原因是更具体的 `.building-card b` 最终生效

后续审查必须从真实 DOM + Cascade + Computed Style 出发，不把单条 CSS 搜索结果当最终视觉。
