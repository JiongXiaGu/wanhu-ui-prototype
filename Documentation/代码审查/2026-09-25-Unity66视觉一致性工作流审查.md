# 2026-09-25 Unity 6.6 Visual Parity 工作流代码审查

## 审查范围

本次只审查 wanhu-ui-prototype 的 Visual Parity 修改流程、CI、Guard 和模块边界，不重新评价具体页面美术。

## 主要发现

1. 模块分支已经出现，但 PR 仍运行完整串行 UI Review，拆分没有真正降低等待时间。
2. `test-tool-usability.mjs` 同时承担长期功能不变量与临时阶段范围，固定文件 SHA 会把合法模块修改误判为越界。
3. `capture-ui-review.mjs`、Tool、Dialog、Readability、HUD、Selection 已有明显职责边界，适合拆成并行 Review Group。
4. `src/styles.css`、`GameplayScreen.tsx` 等热点文件仍可能让 Feature PR 跨模块；应逐步抽离，而不是靠更大的 PR 解决。
5. `audit:unity` 是存量分类工具，不是机械施工队列。Hue、Loading Scrim、Map Heatmap 等功能视觉必须先确定共同实现方式，再处理计数。
6. 当前仓库没有 package lockfile，`package.json` 仍包含 `latest`，构建可复现性不足，应在单独 W0.2 冻结。

## 新工作流

Feature 修改先由 `ui-review-modules.mjs` 分类。PR Scope Guard 禁止未分类 Runtime 文件、跨模块 Feature、Feature + Toolchain 混合、超过 1 个 capture review 脚本以及超过 6 个 Runtime 文件。

PR 只运行模块映射的 Targeted Review Group：

- core：综合页面/工具流程；
- hud：HUD 前景与屏幕固定层；
- dialog：共享 Dialog；
- readability：Global Space / Typography / Color / Loading；
- tools：Workspace / Dock / Placement / Hover / Tool；
- selection：Building Selection。

main 仍运行六组，但六组并行，最后由 UI Review Gate 汇总。模块可以并行开发，但 merge 必须串行。
