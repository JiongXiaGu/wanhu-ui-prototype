# 2026-09-17 统一皮肤与可维护性审查

## 审查目标

本轮不先改视觉结果，而是确认当前新配色与 UI 逻辑稳定后，哪些历史层已经可以收束，避免继续以“后加 Pass 覆盖前一版”的方式维护。

目标：

- 以当前 **冷黛黑 / Graphite + Paper White + 熟铜** 为唯一正式 Gameplay 皮肤基线；
- 保留现有空间模型、交互逻辑、布局几何和已经通过 Visual Review 的视觉结果；
- 删除已退出运行结构的旧 UI 与旧 Selector；
- 将 Review Study 与正式 Runtime 样式分离；
- 明确 Theme / Surface / Control / Component Geometry 的样式所有权；
- 降低 CSS import 顺序对最终结果的隐式依赖；
- 降低 Management / Top HUD 等模块的数据与导航元信息重复。

## 结论摘要

当前实现功能与视觉可以继续迭代，但样式层已经出现明显的 **Override Stack**：同一 Surface 会依次被基础 CSS、Mist Glass、HUD Glass、Contrast、Edge、Character、Tonal Material、Tonal Roles、Workspace Integration、Icon Header 等多层重新定义。

这意味着当前“最后看起来正确”很大程度依赖 `src/main.tsx` 的 import 顺序，而不是清晰的样式所有权。继续在此基础上追加新 Pass，会显著增加 Unity UI Toolkit 迁移与后续维护成本。

本轮建议按 **P0 安全清理 → P1 皮肤所有权统一 → P2 组件/数据拆分** 三阶段处理。P0/P1 的目标都应是 **视觉零回归**，通过现有 Visual Review 证明重构前后截图一致或仅存在预先批准的细微差异。

# P1：统一皮肤所有权

## 5. 当前最大的技术债：同一 Surface 被多个 Pass 重复定义

以下文件都在不同阶段直接修改相同 Gameplay Surface：

- `ui-visual-system.css`
- `gameplay-hud-layout.css`
- `wanhu-mist-glass.css`
- `wanhu-hud-glass.css`
- `wanhu-contrast-identity.css`
- `wanhu-edge-elevation.css`
- `wanhu-character.css`
- `wanhu-tonal-material.css`
- `wanhu-tonal-hud-roles.css`
- `wanhu-workspace-integration.css`
- `wanhu-icon-led-header.css`
- `wanhu-top-resource-shortcuts.css`

尤其：

- `.gameplay-top-status`
- `.gameplay-top-navigation`
- `.command-bar`
- `.workspace--design`
- `.gameplay-context-panel`
- `.gameplay-system-menu-button`

会在多个文件中连续被覆盖。

### 风险

1. 改一个旧文件可能完全无效，因为后面还有覆盖；
2. 改 import 顺序就可能改变皮肤；
3. AI 很容易在错误的“所有者”里继续追加样式；
4. 最终迁移 USS 时无法明确哪些规则是正式值；
5. Review 通过只能证明“当前叠加结果正确”，不能证明系统易维护。

## 6. 建议建立唯一正式 Theme 层

建议整理为三层，而不是继续增加新的 `Pass vN` 文件。

### A. `wanhu-theme-tokens.css`

只定义语义 Token，不写具体组件 Selector。

建议包含：

```text
Palette
- ink-950 / ink-900 / ink-800
- paper-primary / secondary / tertiary
- brass / brass-hi / brass-soft
- cinnabar

Surface Tier
- ambient
- context
- work
- blocking

Edge / Elevation
- directional light/dark edge
- borderless surface
- elevated contour

Blur / Noise / Shadow
- scene blur
- soft blur
- noise texture
- shadow tiers
```

当前 `wanhu-tonal-material.css` 已经有最接近正式答案的 Palette，应作为迁移起点，而不是再重做一套颜色。

### B. `wanhu-surface-system.css`

负责把 Theme Token 组合成稳定的 Surface recipe：

```text
Ambient
Context
Work
Blocking
Elevated
```

Surface recipe 决定：

- background color / alpha；
- shared noise；
- blur；
- edge mode；
- shadow。

### C. `wanhu-control-system.css`

只负责交互状态：

- Default
- Hover
- Selected / Active
- Focus
- Disabled
- Danger
- Tooltip

控制层只消费 Theme Token，不再硬编码多套 Gold / Green / Grey。

## 7. Component CSS 只负责组件结构和必要的局部语义

长期目标：

```text
Theme      → 颜色 / 材质 / Surface Tier
Component  → 几何 / 排版 / Layout
State      → Hover / Active / Focus
Review     → 实验样式
```

例如：

### `gameplay-top-shell.css`

保留：

- 宽高；
- Grid；
- Slot；
- 图标尺寸；
- Tooltip 几何；
- 控件间距。

不再拥有另一套 Graphite / Gold 色值。

### `gameplay-hud-layout.css`

- Surface alpha；
- Gold；
- Icon Color；
- Blur。

建议只保留 Geometry Token，视觉 Token 转移到 Theme。

## 8. 将“已经稳定的 Pass”折回正式所有者，然后删除 Pass 文件

以下文件本质上是迭代历史，而不是理想的长期模块：

- `wanhu-hud-glass.css`

## 9. 全局基础视觉仍有旧配色硬编码

`styles.css`、`ui-visual-system.css`、`gameplay-hud-layout.css` 等早期文件仍大量使用：

- `#c9a55f`
- `rgba(201,165,95,...)`
- 旧绿灰 Surface
- 旧 `--gold / --hud / --workspace` Token

当前 Gameplay 因为后置 Tonal Material 覆盖而没有明显显示旧色，但：

- Full-screen flow；
- Segment；
- Settings / Archive；
- 某些 legacy / low-frequency state

仍可能直接消费旧值。

### 建议

建立统一 Token 后，所有共享 Control 只引用：

```css
var(--wanhu-accent)
var(--wanhu-paper-primary)
var(--wanhu-paper-secondary)
var(--wanhu-surface-*)
```

而不是在组件文件里继续写 RGB 常量。

# P2：组件和逻辑维护性

## 10. Management 导航元信息有重复来源

当前：

- `GameplayHUD.tsx` 自己定义 `MANAGEMENT_PRIMARY`；
- `GameplayHUD.tsx` 自己定义 `STATUS_QUICK_ENTRIES`；
- `management-model.ts` 又定义 Management Navigation / Panel metadata。

这会导致新增 `inventory` 时必须同步多处。

### 建议

建立单一 registry，例如：

```text
management-registry.ts
```

统一维护：

- id；
- title；
- shortLabel；
- icon；
- 是否出现在 Primary Tray；
- 是否有 Top Shortcut；
- shortcut value key / label。

Top HUD 和 Management Space 都从 registry 派生，不各自维护数组。

### 不变量

Top Shortcut **不继承 Management Active 状态**。

它只是 action source：

```text
click shortcut → SET_MANAGEMENT(target)
```

Active / Selected 仍只由 Primary Control Tray 表达。

当前同一个文件同时承担：

- Management Shell；
- Generic Overview；
- Finance；
- Inventory；
- Finance prototype data；
- Warehouse prototype data；
- Village prototype data；

随着库存、人口、军事继续完善，这个文件会快速恶化。

```text
  views/

```

`ManagementSpace.tsx` 只负责：

- Shell；
- Header；
- Metrics；
- 按 `view` 路由具体内容；
- Close。

# 推荐执行顺序

目标：**截图零变化**。

1. 更新 `工作交接 / 项目概览 / UI空间与状态架构`；

目标：**皮肤保持当前结果，但 CSS 所有权唯一**。

1. 建立 canonical Theme Token；
2. 建立 Surface recipe；
3. 共享 Controls 改用 Token；
4. component CSS 只保留布局；
5. 将 Tonal / Header / Workspace Integration 的最终值折回正式 Owner；
6. 删除冗余 Pass 文件；
7. 全套 Visual Review 与昼夜对比。

## Phase 3 — Management Structure Cleanup

1. Management registry 单一化；
2. 拆 `ManagementSpace.tsx`；
3. 拆 Management CSS；
4. 保留 Top Shortcut 与 Primary Nav 的职责边界；
5. Build + 交互 Review。

# 本次审查建议的验收标准

重构结束后应满足：

1. `src/main.tsx` 不再靠十余个 Wanhu Pass 的 import 顺序构造最终皮肤；
2. 当前正式 Palette 只有一个权威 Token 来源；
3. 同一个 Surface 的 background / blur / edge / shadow 有明确唯一 Owner；
4. Review A/B/C 样式不参与默认 Runtime cascade；
5. 已废弃架构 Selector 从生产 CSS 删除；
6. `GameplayHUD` 与 Management 不重复维护管理入口表；
7. `ManagementSpace.tsx` 不再同时承载多个复杂业务视图与 mock data；
8. 文档与当前 Top Shortcut / Inventory 逻辑一致；
9. 重构前后关键 Visual Review 无非预期视觉回归；
10. 新增一个颜色、Surface Tier 或 Management 入口时，不需要在 4～6 个文件同步修改。

## 最终判断

现在是进行这次清理的合适时间。

当前视觉方向已经从早期玉青灰玻璃逐步收敛到新的 Tonal Material，Header、Workspace、Top Metric、Inventory 等核心语法也已基本稳定。继续添加功能前先把历史 Pass 折叠成正式系统，可以显著降低后续 UI Toolkit 迁移、AI 接手和大规模功能扩展的维护成本。
