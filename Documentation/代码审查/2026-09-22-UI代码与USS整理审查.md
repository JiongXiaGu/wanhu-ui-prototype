# 2026-09-22 UI代码与USS整理审查

本次审查面向 Web Prototype 向 Unity 6.6 UI Toolkit 迁移前的代码与样式收口。代码仍是具体实现权威；本文件只记录结构问题、职责边界和后续整理顺序，不把 React / CSS 逐字当成 Unity 产品实现。

审查基于当前 Gameplay HUD、Workspace、Shared Control、Surface、Tool、Selection、Settings、Archive 与现有迁移审计脚本。

## 一、总体判断

最近几轮已经把新的公共结构建立起来：

- Main Dock V2 已有独立 `src/gameplay/main-dock.css`；
- Secondary Action Bar 已有独立 `src/tools/secondary-action-bar.css`；
- Context Utility 已形成单一 Host；
- Operation Hints 已形成 Gameplay 常驻 Host；
- LeftContextPanel / Workspace / Dialog / Shared Control / Surface 已有明确公共组件；
- 图标已经切换为 Source SVG → 64×64 PNG → Runtime Adapter；
- Build 已有 `audit:scale`、`audit:unity` 和相关结构回归。

因此不需要推翻现有 UI。

现在最主要的问题是：**新所有权已经建立，但旧层仍在同时生效**。部分样式依靠 import 顺序和更高 specificity 形成最终结果，Web 页面可以稳定，但这正是迁移 USS 前应清理的内容。

当前 Build 审计基线：

- Runtime 文件：135；
- CSS Grid：117 处 / 22 个文件；
- pseudo-element：94 个选择器；
- backdrop-filter：62 处；
- CSS filter：28 处；
- Browser API：80 处；
- hardcoded px font-size：107 处；
- token-backed font-size：201 处；
- 低于 10px 字号：11 处，其中没有新增低于 9.5px 的正文违规。

这些数字不是“全部必须归零”，但公共 Runtime Primitive 的迁移债务应优先下降。

## 二、第一优先级：先清理 CSS / USS 所有权

### 1. Operation Hints 仍有两套 Runtime 样式

当前同时导入：

- `src/operation-hints.css`
- `src/gameplay/operation-hints-refined.css`

两者都直接定义：

- `.gameplay-operation-hints`
- `.operation-hints__group`
- `.operation-hints__row`
- `.operation-hints__binding`
- `.operation-hints__description`

旧文件仍定义旧版 context / footer、旧宽度、旧材质和旧 backdrop；refined 文件再覆盖成当前版本。

而当前 `GameplayOperationHints.tsx` 已经采用 task / group / row / binding / description，旧版 `operation-hints__context` / `operation-hints__footer` 不再是当前稳定结构。

建议：

- 合并成唯一 `src/gameplay/operation-hints.css`；
- 删除根目录旧 `src/operation-hints.css`；
- 删除 refined 命名；
- Geometry 只保留在 Gameplay HUD / Operation Hints owner；
- Material 仍由 `wanhu-surface-system.css` 消费；
- 更新 `audit-unity-migration.mjs`，从 approved backdrop owner 中移除旧文件。

### 2. ui-visual-system 与 wanhu-surface-system 仍重复持有 Surface

`src/ui/ui-visual-system.css` 当前仍直接给 Workspace、Gameplay Context Panel、Bottom Command Surface 设置 border / shadow / backdrop-filter。

但 `src/ui/wanhu-surface-system.css` 已经被定义为正式 Material Owner，并再次给同一类 Surface 设置 Background / Border / Shadow / Backdrop Filter / L-M-S Bottom Command Material。

当前最终结果依赖“ui-visual-system 先加载，wanhu-surface-system 后加载”。

建议：

- `ui-visual-system.css` 只保留真正的 Control / 全屏 Action 视觉语言；
- Gameplay Surface 的 background / border / shadow / backdrop-filter 全部只留在 `wanhu-surface-system.css`；
- Review Study 需要的 fallback 单独放 review-only 样式，不通过 Runtime 双所有者维持。

整理后应满足：**一个 Surface 属性只有一个正式 Runtime Owner。**

### 3. styles.css 仍然承担过多业务样式

Main Dock 已经从 `styles.css` 移出，但该文件仍然包含：

- Workspace base geometry；
- Workspace header / body / catalog；
- Building Card；
- Segment；
- Pause base；
- Main Menu；
- App Shell / Reset。

其中 Workspace 与 Segment 已经分别存在 `workspace.css`、`workspace/workspace-catalog.css`、`ui-visual-system.css`、`ui-control-system.css`。

建议把 `styles.css` 最终压缩到 Root / Reset / App fixed canvas 等极少量全局基础；Main Menu、Workspace、Segment、Pause 回到各自领域 owner。

### 4. gameplay-refine.css 已经失去独立职责

Main Dock 从该文件移出后，`gameplay-refine.css` 主要剩 Workspace 视觉、局部圆角、Card 等规则。

这些规则已经分别存在于：

- `workspace.css`
- `workspace/workspace-catalog.css`
- `workspace/workspace-world-first-glass.css`
- `wanhu-surface-system.css`

建议：

- Geometry 回到 Workspace owner；
- Foreground / Character 回到 Workspace visual owner；
- Material 回到 Surface owner；
- 文件清空后删除。

## 三、第二优先级：Shared Control 当前仍被 Feature 反向覆盖

### 1. LeftContextPanel 仍重画 Numeric Slider 内部

`src/gameplay/gameplay-context-panel.css` 的注释已经声明共享参数控件应通过 inherited tokens 适配，但实际代码仍直接修改：

- `.ui-numeric-slider-field`
- `.ui-stepper-button`
- `.ui-value-button`
- `.ui-slider__track`
- `.ui-slider__thumb`
- `.segment`

其中很多属性已经由 `src/ui/ui-control-system.css` 正式持有。

建议改成：

- LeftContextPanel 只提供 label width、density、spacing 等语义变量；
- compact / standard / context 等 Variant 全部由 `ui-control-system.css` 定义；
- Feature 不直接改 Slider Track / Thumb / Stepper / ValueButton 的基础皮肤；
- Segment 同理，不在 Context Panel 中重画一套。

### 2. Placement Context Adapter 仍重复 Body 规则

`placement-context-panel.css` 的职责应只是 Placement Adapter。

现在仍定义 Body 的 max-height、overflow、padding、scrollbar-width，其中 padding / overflow / scrollbar 已与 LeftContextPanel / ui-scroll-region 重叠。

建议 Placement Adapter 最终只剩 width、max-height 或 semantic size variable，以及必要的 Placement-specific host modifier。

### 3. Archive 仍有旧 Scrollbar / Input 兼容桥

`archive-panel.css` 仍手工定义 Archive scrollbar；`ui-control-system.css` 又用带 `!important` 的兼容桥覆盖 Archive input。

这表明 Archive 还没有真正消费 Shared Control。

建议第二批处理：

- Archive List 使用 `ui-scroll-region`；
- Rename / Input 使用共享 Input Component / Class；
- 删除 `ui-control-system.css` 末尾 Archive compatibility bridge；
- 避免 Shared Control 通过业务 selector 认识 Archive。

## 四、第三优先级：把 Web 结构改得更像可解释的 UXML

### 1. Main Dock 新实现仍用了 CSS Grid

`main-dock.css` 中 Category Strip 当前使用 `display:grid / grid-auto-flow / grid-auto-columns`。

这里完全可以改成：

- Category Strip = `display:flex`
- 每个 Category Button = `flex:1 1 0; min-width:0`

视觉不会变化，Unity 映射更直接。作为刚新增的公共 Primitive，不应继续增加 Grid 债务。

### 2. Shared Parameter Row / Numeric Slider 仍使用 Grid

`ui-control-system.css` 与 `gameplay-context-panel.css` 中的 Label + Field、Stepper + Slider + Stepper + Value、Labeled Control 都能直接表达为嵌套 Flex。

不建议一次性改全仓库 Grid；先从这些共享 Primitive 开始下降。

### 3. Context Utility 的结构标记仍使用 pseudo-element

Secondary Action Bar / Main Dock 已经把 Selected Line 做成真实 Element，但 Context Utility 仍有：

- Row Divider = `::after`
- Toggle / Selected Line = `::before`

建议后续改成真实 React Element，对应未来 UXML VisualElement。

不要求本轮清掉全部 94 个 pseudo-element，优先清共享 Primitive。

## 五、React / C# 迁移边界也需要开始整理

### 1. ContextUtilityToolbar 组件职责过多

当前约 277 行 / 20KB，同时负责 Context Definition、Context Resolver、Label Resolver、State Resolver、Visibility Resolver、Presence Animation 和 JSX Render，内部约 45 个 if。

建议拆成：

```text
context-utility-definitions.ts
context-utility-resolver.ts
ContextUtilityToolbar.tsx
```

未来 Unity 可直接对应 UtilityToolbarDefinition / UtilityToolbarViewModel / UtilityToolbarHost。

### 2. GameplayOperationHints 的数据与 View 混在一起

当前约 385 行，大量内容是 Hint Preset 数据。

建议拆成：

```text
operation-hints-definitions.ts
operation-hints-resolver.ts
GameplayOperationHints.tsx
```

View 只负责 Task / Binding / Description / persistent host render。

### 3. GameplayScreen 仍承担过多流程编排

当前约 568 行，内部约 46 个 if，同时负责 Escape、Tool Exit、Selection、Dialog、HUD Composition、Utility Action Dispatch、Tool / Workspace / Management Presence 和多个业务 Adapter。

不建议立刻拆成很多 React 小组件。先抽出纯 Resolver / Command Adapter：

- Utility Command Dispatch；
- Gameplay Presence Resolution；
- Selection command adapter。

GameplayScreen 保持 Composition Root，不再继续吸收 Definition 与业务分发。

### 4. ui-state.ts 暂时不要先动

`ui-state.ts` 当前约 755 行、63 个 reducer case。

它承担跨 Tool / Workspace / Selection 的生命周期，贸然拆 reducer 容易破坏 Esc / Origin / 返回逻辑。

建议在 CSS / Shared Primitive / Resolver 清理完成后再处理。第一阶段只做类型分区和 pure helper extraction，不改变 reducer ownership。

## 七、建议新增所有权护栏

现有 `audit:unity` 主要发现语法迁移债务。建议再加入源码级 Ownership Guard。

### Shared Control Ownership

禁止 Feature CSS 出现：

- `.ui-slider__track`
- `.ui-slider__thumb`
- `.ui-stepper-button`
- `.ui-select__menu`
- `.ui-toggle>i`

除 approved shared owner 外直接失败。

### Surface Ownership

禁止除 Surface System / Review Study 外新增：

- `backdrop-filter`
- Shared Workspace / Context / Bottom Command 的 background material；
- Feature 对公共 Surface root 的 box-shadow / border recipe。

整理后不会再慢慢长回去。

## 九、整理完成后的目标

核心原则不是减少文件数量，而是：

> 一个视觉属性、一个业务状态、一个生命周期都能明确回答“谁拥有”。

完成上述整理后，再迁 Unity UXML / USS 时就不需要复制 Web 的 Cascade 层，而可以直接按 Theme → Surface → Control → Shared Component → Feature 映射。

## 十一、Global Hover Framework 收口

原先存在两套悬浮路径：

- Toolbar / Utility / Top HUD 的 `data-tooltip + ::after`；
- DesignWorkspace 私有 `AssetInspector`。

现已收敛到 `src/ui/hover/`：

- `HoverOverlayProvider / HoverOverlayHost`；
- `hover-placement.ts`；
- Tooltip；
- Hover Card。

旧 AssetInspector 三文件退休，Toolbar / Utility / Top HUD 不再持有 Tooltip pseudo-element。该改动同时减少公共 Primitive pseudo-element，并建立 Unity UI Toolkit 可直接映射的 OverlayRoot / Controller / Manipulator 边界。
