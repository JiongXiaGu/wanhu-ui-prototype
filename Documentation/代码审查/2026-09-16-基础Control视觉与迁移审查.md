# 2026-09-16 基础 Control 视觉与迁移审查

## 审查目标

本轮审查集中在可长期复用的基础交互控件：

- Slider / Range；
- Stepper `- / +`；
- 数值输出；
- Select / Dropdown；
- Toggle；
- Text Input / Search Input；
- Segmented Control 与上述控件的边界；
- Gameplay Tool Parameter Panel、Camera / Weather、Settings、Archive / Dialog 等不同空间中的视觉一致性；
- 最终 Unity UI Toolkit 的 UXML / USS / C# 迁移方式。

本轮不调整 Gameplay 空间架构，不改变业务数据规则，重点是确认“同一种控件是否只维护一套语义与视觉契约”。

## 现状结论

当前项目已经有稳定的 Surface / Segmented / Footer / Bottom Command 视觉体系，但基础表单控件仍存在明显重复实现。若直接迁移 Unity，容易形成多套 USS 与多份 C# 控件逻辑。

最需要处理的不是颜色微调，而是 **Control Ownership**：同一种控件的结构、视觉状态和交互应集中维护，业务页面只负责布局、标签、范围和数据绑定。

## 1. Slider 当前存在至少三套实现

### Settings Slider

位置：

- `src/settings/SettingsPanel.tsx`
- `src/settings/settings-panel.css`

特点：

- 自定义 Pointer Drag；
- 键盘 Arrow / Home / End；
- 独立 Track / Fill / Thumb；
- 独立 Hover / Focus / Dragging；
- 独立 Output。

这是当前交互完整度最高的一套 Slider，但实现完全锁在 Settings 页面内部。

### Runtime Slider

位置：

- `src/ui/Controls.tsx` 的 `RuntimeParameterRow`；
- `src/gameplay/advanced-parameter-panels.css` 的 `.runtime-slider-*`。

问题：

- Component 已经在共享 `Controls.tsx`，视觉却放在已经退役的 `advanced-parameter-panels.css`；
- `advanced-parameter-panels.css` 同时还保留 RightEdgeFlyout 旧结构；
- 控件归属不清晰。

### Building Placement Slider

位置：

- `src/tools/building-placement/BuildingPlacementOverlay.tsx`；
- `src/tools/building-placement/building-placement.css`。

当前 `ParameterControl` 自己维护 `value + fill`，视觉使用 `.bp-track`。

问题：

- Track 看起来像 Slider，但当前只能依靠 `- / +` 修改，Track 本身并不是真正可拖动 Slider；
- 与 Settings / Runtime Slider 的 Thumb、Hover、Focus 尺寸均不同；
- 同一“数值参数”语义出现第三套实现。

### Road Placement

`RoadParameterControl` 当前甚至没有 Slider，只保留 `- / 数值 / +`。

这不是一定错误，但说明道路参数与建筑 / Weather / Settings 没有共用统一 Numeric Field 结构。

## 2. Select 目前只有 Settings 拥有完整实现，但不应继续页面私有

位置：

- `SettingsPanel.tsx::SelectControl`；
- `.settings-select-*`。

已经支持：

- 鼠标打开 / 关闭；
- 点击外部关闭；
- 上下键；
- Enter / Space；
- Escape；
- 当前项 Selected；
- 上下展开方向判断。

这已经接近共享控件，不应长期留在 Settings 内部。

正式方向应抽为类似：

```text
UISelectField
├ Trigger
├ Popup
└ Option*
```

Settings 只提供 `value / options / disabled / onChange`。

## 3. Toggle 当前至少两套视觉

Settings：

- `.settings-toggle`

Archive：

- `.archive-hide-outdated > i > em`

二者本质都是布尔开关，但 Radius、Track、Thumb、On 状态分别维护。

Archive 可以保留“Label + Toggle”整体布局，但内部开关视觉应共用 Toggle Token / Class。

## 4. Text Input 当前没有共享契约

当前可以确认至少存在：

- Dialog 输入框：`.ui-dialog-input input`；
- Archive 历史 Inline Rename CSS：`.archive-group-card input / .archive-save-card input`；
- Workspace Search：`.workspace-search__field input`。

这三者语义并不完全相同，因此不应该强制长得一模一样，但应共享：

- Text Color；
- Placeholder；
- Caret；
- Border / Focus Ring；
- Disabled；
- Radius Token。

建议正式分为：

```text
TextField       常规文本输入
SearchField     搜索容器，允许更轻 / 更扁平
InlineRename    列表内原地编辑，可弱化外框
```

它们共享 Token，而不是共享完全相同的 Box。

## 5. Stepper / Value Field 需要正式成为基础控件

Gameplay 参数面板反复出现：

```text
Label │ - │ Slider │ + │ Value
```

这是非常稳定的游戏参数编辑结构，应正式定义为共享 `NumericSliderField / RuntimeParameterRow`。

建议结构：

```text
NumericSliderField
├ Label
├ DecreaseButton
├ Slider
├ IncreaseButton
└ ValueField
```

其中：

- `ValueField` 默认可只读；
- 如果以后需要直接数字输入，再增加 `editable` 变体；
- Building / Camera / Weather / Road 只提供不同的 `min / max / step / formatter`。

## 6. Segmented Control 已经基本完成共享，不应再复制

当前 `SegmentedControl` 已存在于 `src/ui/Controls.tsx`，并且 `ui-visual-system.css` 已建立统一视觉。

但 Building Placement 仍有自己的 `SegmentRow + bp-segment`，属于重复结构。

应逐步改成共用 `SegmentedControl`，业务层只保留 Label 与当前 Value。

## 7. Legacy CSS 仍在影响 Control Ownership

`src/gameplay/advanced-parameter-panels.css` 仍被 `main.tsx` 加载，但其中大量选择器属于已经退出运行结构的 RightEdgeFlyout。

同时真正仍在使用的 Runtime Slider 样式又被放在这个文件里。

建议：

1. 将 Runtime Slider / Parameter Row 视觉迁入共享 Control USS/CSS；
2. 停止加载 `advanced-parameter-panels.css`；
3. 确认无依赖后删除该 Legacy 文件。

`src/tool-overlay.css` 同样保留旧 `.parameter-row / .segment / .track` 规则。当前新 Building / Road CSS 在局部覆盖它们，长期容易产生 Specificity 竞争，应在 Control 统一后继续清理。

## 8. 推荐 Web 代码结构

建议新增：

```text
src/ui/ui-control-system.css
```

负责低层控件视觉，不负责页面几何。

建议共享 Component：

```text
src/ui/Controls.tsx
├ SegmentedControl
├ SliderControl
├ RuntimeParameterRow / NumericSliderField
├ SelectControl
├ ToggleSwitch
└ TextInput
```

当前不建议为了“组件化”把 Label、Section、Settings Row 等页面结构也塞进共享组件；共享边界只到基础控件。

## 9. 推荐 Unity UI Toolkit 映射

Web 语义应能直接翻译成：

```text
UIControls.uss

.ui-slider
.ui-slider__track
.ui-slider__fill
.ui-slider__thumb

.ui-stepper-button
.ui-value-field

.ui-select
.ui-select__trigger
.ui-select__popup
.ui-select__option
.ui-select__option--selected

.ui-toggle
.ui-toggle--on

.ui-text-field
.ui-search-field

.ui-segmented
.ui-segmented__option
.ui-segmented__option--active
```

UXML / C# 建议：

- Slider 使用 UI Toolkit `Slider / SliderInt` 或共享自定义 `WanhuSliderField`；
- `NumericSliderField` 组合 Slider + 两个 Button + Label；
- Select 优先用共享 PopupField / DropdownField 包装层，不在各页面重复 Popup 逻辑；
- Toggle 使用统一 Toggle Wrapper；
- TextField 使用共享 USS Class；
- 业务 C# 只配置范围、数据绑定、Disabled / ReadOnly / Active，不写颜色和圆角。

## 10. 状态规范

所有基础 Control 至少覆盖：

```text
Default
Hover
Focus
Pressed / Dragging（适用时）
Selected / On（适用时）
Disabled
ReadOnly（适用时）
Error / Conflict（适用时）
```

不要用不同页面的自定义颜色表达同一个状态。

## 11. 本轮建议执行顺序

### 第一阶段：建立共享 Control System

- 新建 `ui-control-system.css`；
- 固化 Field / Slider / Toggle / Select / Text Input Token；
- 不改变业务布局。

### 第二阶段：迁移 Gameplay 参数控件

- RuntimeParameterRow 归入共享 Control System；
- Building `ParameterControl` 改为共享 Numeric Slider；
- Building `SegmentRow` 改用共享 SegmentedControl；
- Road 参数改用同一 Numeric Field。

### 第三阶段：迁移 Settings

- 抽出 Settings 的 Slider / Select / Toggle 逻辑；
- SettingsPanel 只保留 Settings 数据与布局；
- 保留现有 Keyboard / Gamepad 能力。

### 第四阶段：Input / Archive 清理

- Dialog Text Input 接共享 TextField；
- Archive / Search 使用对应语义变体；
- 删除不再运行的旧 Control CSS。

## 12. 视觉建议

统一后建议保持以下方向：

- Slider Track 视觉高度约 `3–4px`，实际 Hit Area 至少约 `22–24px`；
- Thumb 约 `10–12px`，Hover / Focus 扩大视觉反馈而不是增加厚边；
- Stepper Button 使用 `8px` Radius，尺寸约 `27–30px`；
- Select / Text Field 常规外框使用 `10px` Radius；
- Toggle 允许使用接近胶囊的短 Track，因为它是独立 Control 语义，不影响全局低圆角原则；
- 暖金只表示 Fill / Selected / Focus，不把整条 Slider 做成高亮金色；
- 夜景下 Track / Border 不能完全消失，但也不要依赖 Glow 保证可见性。

## 审查结论

当前最合理的下一步不是继续逐页“调 Slider 颜色”，而是正式建立 **基础 Control Visual System**。

Surface / Command / Segmented 已经开始统一；Slider、Select、Toggle、Text Input、Stepper、Value Field 是目前剩余最大的共享视觉缺口。

完成这层抽象后，Web Prototype 与最终 Unity UI Toolkit 的映射会明显更直接，也能减少后续 Settings、Tool、Selection Inspector、蓝图参数、道路 / 城墙 / 围墙工具继续复制样式的风险。
