# 城墙门洞放置工具设计规范

`CityWallGateTool` 是城墙四套独立业务 ToolOverlay 中的第二套，负责可独立存在的城门 / 门洞构件。

## 1. 核心原则

城门不是“必须先有城墙，再在墙上 Boolean 挖一个洞”。

正式世界语义：

```text
CityGateModule
├ OpeningWidth
├ OpeningHeight
├ BuildingDepth
├ Front / Back
├ Position / Rotation
└ ConnectedWalls[]
```

城门本身是独立建筑构件；城墙只是可选连接对象。

## 2. 放置模式

```ts
CityWallGatePlacementMode =
  | 'free'
  | 'wall-connected'
```

### Free

- 没有城墙也能直接放置；
- 玩家控制位置和旋转；
- Front / Back 为城门自身语义；
- 后续可以再让城墙连接到城门两侧。

### Wall Connected

- Hover / 查询已有墙段；
- 自动吸附墙中心关系；
- 自动对齐墙方向；
- 默认继承墙体 Front / Back；
- 左右两端建立 Wall Connection；
- 城门纵深保持玩家设置，不被 Wall Thickness 覆盖。

## 3. 核心尺寸

首轮只开放三个高价值参数：

- 洞口净宽；
- 洞口净高；
- 建筑纵深。

建筑纵深表示整个城门构件从 Front 到 Back 的深度。

例如：

```text
Wall Thickness = 6 m
Gate Building Depth = 10 m
```

允许城门在墙体前后突出；系统不自动把 Gate Depth Clamp 到 Wall Thickness。

## 4. Front / Back

城门使用和城墙统一的语义：

```text
Front = 城外正面
Back  = 城内背面
```

Free Mode：

- Rotate 改变 Transform；
- Facing Flip 改变 Front / Back 语义；
- 两者不是同一件事。

Wall Connected：

- Rotation 由墙体连接关系自动决定，因此自由左转 / 右转按钮隐藏；
- Facing 默认继承墙体；
- 仍保留“交换正反面”用于特殊城门。

## 5. 左侧 Overlay

共享 `PlacementContextPanel` 外壳。

共同：

```text
门洞尺寸
洞口净宽
洞口净高
建筑纵深
```

Free 额外显示：

- 模式；
- 当前 Rotation；
- Front；
- Back；
- “可独立于城墙存在”的说明。

Connected 额外显示：

- 当前城墙体系；
- Wall Thickness；
- Wall Height；
- Gate Building Depth；
- Facing；
- “纵深不被墙厚覆盖”的说明。

## 6. Bottom Action Bar

Free：

```text
[自由放置] [城墙连接]
      │
[左转] [右转] [交换正反面]
      │
[完成] [取消]
```

Wall Connected：

```text
[自由放置] [城墙连接]
      │
[交换正反面]
      │
[完成] [取消]
```

Connected Mode 不显示自由旋转按钮。

## 7. Context Utility

Free：

- 网格吸附；
- 网格显示；
- 门洞净空；
- Undo；
- Redo。

Wall Connected：

- 网格显示；
- 墙体连接点；
- 门洞净空；
- Undo；
- Redo。

“吸附城墙”不是 Toggle。进入 Wall Connected 后，连接墙体就是工具本身的强制规则。

## 8. World Visualization

Free Preview 必须表达：

- 城门建筑体积；
- 正面门洞；
- Building Depth；
- Ground Footprint；
- Front / Back；
- Clearance。

Connected Preview 必须表达：

- Existing Thick Wall；
- Gate Volume；
- 左右两个连接锚点；
- Gate Depth 与 Wall Thickness 的差异；
- 门洞净空；
- Front / Back。

正式 Unity：

```text
CityWallGateWorldRenderer
├ GateGhost
├ GateVolume
├ OpeningClearance
├ FrontBackFacing
├ WallSnapTarget
├ WallConnectionAnchors
└ InvalidPlacement
```

Web Preview 只验证表达，不迁 UI Toolkit。

## 9. 合法性规则

例如：

```text
Opening Height > Available Wall Height
```

必须显示 Invalid Preview，不允许静默 Clamp 用户参数。

玩家可以：

- 降低洞口高度；
- 调整城墙；
- 切回 Free Mode。

## 10. 世界数据关系

不推荐“完整 Wall Mesh + Boolean Opening”作为长期数据结构。

推荐：

```text
Wall Segment A
   ↘
    City Gate
   ↗
Wall Segment B
```

Gate 是城墙路径中的独立 Module / Entity，便于后续扩展：

- 城门楼；
- 双门洞；
- 水门；
- 闸门；
- 瓮城入口。

## 11. Visual Review

至少检查：

- Workspace 门洞 Card 能进入 `city-wall-gate`；
- Free 默认存在；
- 三项尺寸全部存在；
- Free 有 Rotate Left / Right / Facing Flip；
- Free Preview 是有纵深的独立建筑体，不是门图标；
- Connected 后自由旋转消失；
- Connected Utility 出现墙体连接点；
- Gate Depth 10m 与 Wall Thickness 6m 同时可见；
- Connected Preview 有两个连接 Anchor；
- Facing Flip 不依赖 Rotate；
- 完成后返回城墙 Workspace。
