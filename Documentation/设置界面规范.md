# 设置界面规范

《万户天工》的设置界面最终用于 Unity UI Toolkit。Web Prototype 只用于验证视觉、布局、信息结构和交互节奏。

## 1. 总体结构

设置界面使用全屏 Settings Space，采用常见 PC / 主机游戏的单列设置结构。

固定结构：

```text
Header
Category Tabs
Single-column Scroll View
Footer
```

顶部分类当前为：

`显示 / 图形 / 音频 / 操作 / 游戏`

中间内容区域使用一列纵向滚动列表，不使用双栏 Card、不使用左右两张功能卡，也不把每个 Section 包成独立大面板。

推荐内容宽度约 840～900 px（以 1920×1080 设计基准计）。

## 2. Section

每个设置分类由若干 Section 组成，例如：

- 显示：显示输出 / 界面；
- 图形：图形质量 / 城市细节 / 光照与特效；
- 音频：音量 / 播放行为；
- 操作：鼠标与镜头 / 按键绑定；
- 游戏：存档 / 游戏体验 / 语言与菜单。

Section 规则：

- Section Title 使用中性浅灰文字；
- Title 后可以使用一条非常弱的分隔线；
- 普通 Section 不使用暖金左边线；
- 不增加常驻 Section Description；
- 说明内容进入 Tooltip。

暖金不用于普通分组装饰。

## 3. 设置行

普通设置项采用：

```text
设置名称                              控件 / 当前值
```

视觉规则：

- Label 左对齐；
- Control 右对齐；
- 同类 Control 尽量共享固定宽度；
- 不给每行增加完整 Card；
- 默认背景透明；
- Hover 时仅出现极弱 Tone；
- 行与行之间只允许极弱分隔，不形成表格网格。

## 4. 暖金使用

暖金只用于高价值状态：

- 当前 Category Tab；
- Slider 已填充部分；
- Toggle On；
- Focus / Selected；
- 正在监听新的按键；
- Footer Primary Action。

禁止：

- 每个 Section 都有金边；
- 大面积金色背景；
- 普通静态文字全部使用金色。

## 5. 控件

### Select

默认表现为轻量文字值 + 下拉箭头。

- 不使用厚重输入框；
- 可使用极弱底线；
- Hover / Focus 才加强边界。

### Slider

建议结构：

```text
设置名称          ━━━━━━━━━●━━━━     100%
```

- Track 低对比；
- Fill 使用低饱和暖金；
- Value 独立显示；
- 不将 Slider 放进额外 Card。

### Toggle

- Off 使用中性灰；
- On 使用暖金；
- 不额外常驻“开启 / 关闭”文字，除非语义需要。

### Input Binding

操作设置中的按键绑定必须同时支持 **主要按键 + 次要按键**，不能退回单一 Keycap 展示。

标准结构：

```text
操作名称             主要按键          次要按键          恢复
```

每个绑定行的 UI Toolkit 对应结构应保持简单：

```text
InputBindingRow
├ Label
├ PrimaryBindingButton
├ SecondaryBindingButton
└ ResetButton
```

视觉规则：

- 主要按键和次要按键使用相同尺寸、相同权重的轻量矩形 Binding Cell；
- 不做传统表格网格，不给整行增加完整边框；
- 次要按键为空时显示 `+ 添加`，而不是 `None`；
- 行级恢复按钮默认弱化或隐藏，Hover / Focus 当前行时出现；
- 正在监听按键时使用暖金 Focus 状态，文字显示 `按下新的按键…`；
- 绑定冲突使用克制的暖红边界和就地提示，不使用大弹窗；
- 绑定说明仍通过 Tooltip 提供，不在每行常驻说明文字。

交互规则：

- 点击主要/次要按键进入监听；
- Esc 取消本次监听；
- Delete / Backspace 清除当前槽位；
- 检测到冲突时不应静默覆盖另一个操作；
- 单行恢复只恢复该操作默认绑定；
- 设置页底部仍可提供恢复当前分类默认值。

Web Prototype 只验证这套交互和视觉。最终 Unity 实现必须读取和写入 Input System 实际绑定，并使用正式 Rebinding 流程。

## 6. 配置内容基准

当前 Web Prototype 的配置内容参考原 `SettingsWorkspace.uxml`，并按正式游戏需求扩充。

### 显示

显示输出：

- 显示模式；
- 显示器；
- 分辨率；
- 屏幕刷新率；
- HDR 输出；
- 垂直同步；
- 帧率限制。

界面：

- 界面缩放；
- 安全区域。

### 图形

图形质量：

- 综合质量；
- 渲染比例；
- 抗锯齿；
- 超分辨率；
- 帧生成；
- 低延迟模式。

城市细节：

- 建筑细节距离；
- 居民显示距离；
- 植被质量；
- 植被显示距离；
- 阴影质量；
- 阴影距离；
- 地形质量；
- 水体质量。

光照与特效：

- 反射质量；
- 环境光遮蔽；
- 体积雾；
- 云层质量；
- 动态云影；
- Bloom；
- 景深；
- 动态模糊。

注意：最终 Unity 设置项必须和实际渲染功能保持一致。Prototype 可以提前验证信息架构，但不要为了“配置看起来丰富”保留最终项目不存在的功能。

### 音频

音量：

- 主音量；
- 音乐音量；
- 游戏音效；
- 环境声音；
- 界面声音。

播放行为：

- 失去焦点时静音；
- 界面提示音；
- 城市环境声；
- 平滑切换场景音乐。

### 操作

鼠标与镜头：

- 指针灵敏度；
- 滚轮灵敏度；
- 水平反转；
- 垂直反转；
- 滚轮反转；
- 键盘移动速度；
- 键盘旋转速度；
- 屏幕边缘滚动；
- 边缘滚动速度。

按键绑定使用可折叠分组，当前基准：

- 基础操作；
- 营造与道路；
- 时间控制；
- 镜头操作；
- 快捷栏。

默认只展开“基础操作”。每个分组展开后使用统一的 `操作 / 主要按键 / 次要按键 / 恢复` 四列语义。

最终 Unity 使用 Input System Rebinding，并复用项目原有 `InputBindingField` 的主绑定 / 备用绑定模型。

### 游戏

存档：

- 自动保存间隔；
- 自动存档数量。

游戏体验：

- 显示营造教程；
- 操作提示；
- 重要操作二次确认；
- 居民故事提示；
- 重要事件自动暂停。

语言与菜单：

- 界面语言；
- 主菜单镜头运动。

## 7. 应用策略

不是所有设置都必须等待 Footer 的“应用”。

建议最终 Unity 实现区分：

### 可即时生效

例如：

- 音量；
- 灵敏度；
- 大部分 Toggle；
- 常规图形质量项；
- 按键重绑定。

### 需要确认

例如：

- 显示模式；
- 分辨率；
- 刷新率；
- HDR 输出。

影响画面可见性的显示设置建议采用“确认保留 / 超时自动恢复”流程。

Footer 仍保留：

- 恢复当前分类默认值；
- 取消；
- 应用。

## 8. UI Toolkit 落地

推荐结构：

```text
SettingsRoot
├ Header
├ CategoryTabs
├ ScrollView
│  └ SettingsList
│     ├ Section
│     │  ├ SectionHeader
│     │  └ SettingRows
│     ├ InputBindingSection
│     │  ├ BindingColumnHeader
│     │  └ CollapsibleBindingGroups
│     └ ...
└ Footer
```

不要为了复制 Web CSS 使用复杂布局。

优先：

- Flex Column；
- Flex Row；
- ScrollView；
- 共享 SettingRow；
- 共享 Select / Slider / Toggle；
- 共享 InputBindingField；
- Class 切换表达 Active / Focus / On / Listening / Conflict 状态。

场景背景模糊最终由项目统一的 URP 全屏 Blur Pass 提供，不由每个设置面板单独实现。

## 9. 禁止回退

不要恢复：

- 双栏设置 Card；
- 每个 Section 左侧金边；
- 常驻说明性小字；
- 每行完整边框；
- 右侧无意义 Preview / Summary；
- 大面积暖金；
- 只有“一个按键槽”的键位设置；
- 把主要按键和次要按键合并成一串不可编辑 Keycap。
