# 设置界面规范

《万户天工》的设置界面最终用于 Unity UI Toolkit。Web Prototype 只用于验证视觉、布局、信息结构、控件状态和交互手感。

## 1. 总体结构

设置界面使用全屏 Settings Space，采用常见 PC / 主机游戏的单列设置结构。

固定结构：

```text
Header
Category Tabs
Single-column Scroll View
Footer
```

顶部分类当前为：

`显示 / 图形 / 音频 / 操作 / 游戏`

中间内容区域使用一列纵向滚动列表，不使用双栏 Card、不使用左右两张功能卡，也不把每个 Section 包成独立大面板。

推荐内容宽度约 840～900 px（以 1920×1080 设计基准计）。

## 2. Section

每个设置分类由若干 Section 组成，例如：

- 显示：显示输出 / 界面；
- 图形：图形质量 / 城市细节 / 光照与特效；
- 音频：音量 / 播放行为；
- 操作：鼠标与镜头 / 按键绑定；
- 游戏：存档 / 游戏体验 / 语言与菜单。

Section 规则：

- Section Title 使用中性浅灰文字；
- Title 后可以使用一条非常弱的分隔线；
- 普通 Section 不使用暖金左边线；
- 不增加常驻 Section Description；
- 说明内容进入 Tooltip。

暖金不用于普通分组装饰。

## 3. 设置行

普通设置项采用：

```text
设置名称                              控件 / 当前值
```

视觉规则：

- Label 左对齐；
- Control 右对齐；
- 同类 Control 尽量共享固定宽度；
- 不给每行增加完整 Card；
- 默认背景透明；
- Hover 时仅出现极弱 Tone；
- 行与行之间只允许极弱分隔，不形成表格网格；
- Disabled 行整体降低对比度，但必须仍然可读，不能直接消失。

## 4. 暖金使用

暖金只用于高价值状态：

- 当前 Category Tab；
- Slider 已填充部分；
- Slider Dragging / Focus；
- Toggle On；
- Select Open / Selected；
- Focus / Selected；
- 正在监听新的按键；
- Dirty 状态下的 Footer Primary Action。

禁止：

- 每个 Section 都有金边；
- 大面积金色背景；
- 普通静态文字全部使用金色。

## 5. 控件交互

Web Prototype 中的设置控件必须是真实可操作控件。不能只绘制 Slider / Select / Toggle 的外观然后把交互留到 Unity 阶段。

原因：Web Prototype 的职责之一是让开发阶段能直接观察 Hover / Pressed / Focus / Open / Dragging / Disabled / Dirty 等状态是否舒服。

### Select

默认表现为轻量文字值 + 下拉箭头。

收起：

```text
显示模式                         无边框全屏  ˅
```

展开：

```text
                                 ┌──────────────┐
                                 │ 独占全屏     │
                                 │ 无边框全屏 ✓ │
                                 │ 窗口         │
                                 └──────────────┘
```

规则：

- 不使用浏览器原生 Select 视觉；
- 不使用厚重输入框；
- 默认可使用极弱底线；
- Hover / Focus 才加强边界；
- Open 时底线和 Chevron 使用暖金 Focus；
- 当前值在菜单中使用低饱和暖金 Selected；
- 菜单使用不透底的深墨 Surface，避免下方设置文字穿透菜单；
- 点击菜单外关闭；
- Esc 关闭；
- `↑ / ↓` 切换当前候选；
- Enter / Space 确认；
- 接近 ScrollView 底部时允许向上展开；
- 最终 UI Toolkit 可映射到 `ChoicePickerField` / 自定义 Dropdown 行为。

### Slider

结构：

```text
设置名称          ━━━━━━━━━●━━━━     100%
```

视觉规则：

- Track 低对比；
- Fill 使用低饱和暖金；
- Value 独立显示；
- 不将 Slider 放进额外 Card；
- 视觉轨道可以只有约 4 px，但实际 Pointer Hit Area 应明显更高，避免难拖。

交互规则：

- 点击 Track 可以直接跳到对应值；
- 按住 Thumb / Track 后可以连续拖动；
- 拖动时 Thumb 和暖金 Fill 稍微增强，允许极弱 Halo；
- `← / ↓` 递减一个 Step；
- `→ / ↑` 递增一个 Step；
- Shift + 方向键可以按更大步长调整；
- Home / End 跳到最小 / 最大值；
- 修改时数值实时刷新；
- 设置页本身需要纵向滚动，因此不要默认使用鼠标滚轮调整 Slider，避免误操作。

最终 Unity 映射到 Slider / SliderInt 或项目共享 SliderField，行为应保持同一语义。

### Toggle

视觉规则：

- Off 使用中性灰；
- On 使用暖金；
- 不额外常驻“开启 / 关闭”文字，除非语义需要；
- Hover 只提高边界和底色亮度；
- Pressed 时 Thumb 允许短暂压缩 / 降亮；
- Focus 使用克制的暖金焦点反馈。

交互规则：

- 点击立即切换 Draft Value；
- 状态切换动画约 120～150 ms；
- Disabled 时必须不可点击，并使用统一 Disabled 视觉。

### Input Binding

操作设置中的按键绑定必须同时支持 **主要按键 + 次要按键**，不能退回单一 Keycap 展示。

标准结构：

```text
操作名称             主要按键          次要按键          恢复
```

每个绑定行的 UI Toolkit 对应结构应保持简单：

```text
InputBindingRow
├ Label
├ PrimaryBindingButton
├ SecondaryBindingButton
└ ResetButton
```

视觉规则：

- 主要按键和次要按键使用相同尺寸、相同权重的轻量矩形 Binding Cell；
- 不做传统表格网格，不给整行增加完整边框；
- 次要按键为空时显示 `+ 添加`，而不是 `None`；
- 行级恢复按钮默认弱化或隐藏，Hover / Focus 当前行时出现；
- 正在监听按键时使用暖金 Focus 状态，文字显示 `按下新的按键…`；
- 绑定冲突使用克制的暖红边界和就地提示，不使用大弹窗；
- 绑定说明仍通过 Tooltip 提供，不在每行常驻说明文字。

交互规则：

- 点击主要/次要按键进入监听；
- Esc 取消本次监听；
- Delete / Backspace 清除当前槽位；
- 检测到冲突时不应静默覆盖另一个操作；
- 单行恢复只恢复该操作默认绑定；
- 设置页底部仍可提供恢复当前分类默认值。

Web Prototype 只验证这套交互和视觉。最终 Unity 实现必须读取和写入 Input System 实际绑定，并使用正式 Rebinding 流程。

## 6. Draft / Applied / Dirty

Web Prototype 的 Settings 使用三层模型：

```text
SettingDefinition
        ↓
AppliedSettings
        ↓ 打开设置时复制
SettingsDraft
```

规则：

- Slider / Select / Toggle / Binding 编辑 Draft；
- Draft 与 Applied 不同则 Settings 进入 Dirty；
- Dirty 时 Footer “应用”按钮从 Disabled 转为暖金 Primary；
- 没有修改时“应用”必须 Disabled，不要常驻高亮；
- 点击应用：Draft 写入 Applied；
- 点击取消 / 返回：丢弃 Draft；
- 恢复当前分类默认值：只重置当前分类的 Draft；
- 如果恢复后的 Draft 与 Applied 再次一致，应自动退出 Dirty。

Web 使用这一模型主要用于验证状态反馈。最终 Unity 可以根据设置类型决定即时生效、暂存后 Apply 或需要额外确认。

## 7. Disabled 与设置依赖

相关设置之间允许存在依赖关系。Disabled 不是纯视觉状态，控件必须真的不可操作。

示例：

- 超分辨率不是 DLSS 时，可以禁用只属于 DLSS 的帧生成设置；
- 关闭屏幕边缘滚动后，禁用“边缘滚动速度”；
- 不支持 HDR 的设备可以禁用 HDR；
- 不支持特定显卡能力时禁用对应设置。

视觉规则：

- 整行整体降对比度；
- Label、Value、Track、Toggle 同步弱化；
- 不删除条目，用户仍应知道该功能存在；
- Tooltip 可解释为什么当前不可用。

## 8. 配置内容基准

当前 Web Prototype 的配置内容参考原 `SettingsWorkspace.uxml`，并按正式游戏需求扩充。

### 显示

显示输出：

- 显示模式；
- 显示器；
- 分辨率；
- 屏幕刷新率；
- HDR 输出；
- 垂直同步；
- 帧率限制。

界面：

- 界面缩放；
- 安全区域。

### 图形

图形质量：

- 综合质量；
- 渲染比例；
- 抗锯齿；
- 超分辨率；
- 帧生成；
- 低延迟模式。

城市细节：

- 建筑细节距离；
- 居民显示距离；
- 植被质量；
- 植被显示距离；
- 阴影质量；
- 阴影距离；
- 地形质量；
- 水体质量。

光照与特效：

- 反射质量；
- 环境光遮蔽；
- 体积雾；
- 云层质量；
- 动态云影；
- Bloom；
- 景深；
- 动态模糊。

注意：最终 Unity 设置项必须和实际渲染功能保持一致。Prototype 可以提前验证信息架构，但不要为了“配置看起来丰富”保留最终项目不存在的功能。

### 音频

音量：

- 主音量；
- 音乐音量；
- 游戏音效；
- 环境声音；
- 界面声音。

播放行为：

- 失去焦点时静音；
- 界面提示音；
- 城市环境声；
- 平滑切换场景音乐。

### 操作

鼠标与镜头：

- 指针灵敏度；
- 滚轮灵敏度；
- 水平反转；
- 垂直反转；
- 滚轮反转；
- 键盘移动速度；
- 键盘旋转速度；
- 屏幕边缘滚动；
- 边缘滚动速度。

按键绑定使用可折叠分组，当前基准：

- 基础操作；
- 营造与道路；
- 时间控制；
- 镜头操作；
- 快捷栏。

默认只展开“基础操作”。每个分组展开后使用统一的 `操作 / 主要按键 / 次要按键 / 恢复` 四列语义。

最终 Unity 使用 Input System Rebinding，并复用项目原有 `InputBindingField` 的主绑定 / 备用绑定模型。

### 游戏

存档：

- 自动保存间隔；
- 自动存档数量。

游戏体验：

- 显示营造教程；
- 操作提示；
- 重要操作二次确认；
- 居民故事提示；
- 重要事件自动暂停。

语言与菜单：

- 界面语言；
- 主菜单镜头运动。

## 9. 最终 Unity 应用策略

不是所有设置都必须等待 Footer 的“应用”。

建议最终 Unity 实现区分：

### 可即时生效

例如：

- 音量；
- 灵敏度；
- 大部分 Toggle；
- 常规图形质量项；
- 按键重绑定。

### 需要确认

例如：

- 显示模式；
- 分辨率；
- 刷新率；
- HDR 输出。

影响画面可见性的显示设置建议采用“确认保留 / 超时自动恢复”流程。

Footer 仍保留：

- 恢复当前分类默认值；
- 取消；
- 应用。

## 10. UI Toolkit 落地

推荐结构：

```text
SettingsRoot
├ Header
├ CategoryTabs
├ ScrollView
│  └ SettingsList
│     ├ Section
│     │  ├ SectionHeader
│     │  └ SettingRows
│     ├ InputBindingSection
│     │  ├ BindingColumnHeader
│     │  └ CollapsibleBindingGroups
│     └ ...
└ Footer
```

不要为了复制 Web CSS 使用复杂布局。

优先：

- Flex Column；
- Flex Row；
- ScrollView；
- 共享 SettingRow；
- 共享 Select / Slider / Toggle；
- 共享 InputBindingField；
- Class 切换表达 Active / Focus / Open / Dragging / On / Disabled / Listening / Conflict / Dirty 状态。

场景背景模糊最终由项目统一的 URP 全屏 Blur Pass 提供，不由每个设置面板单独实现。

## 11. Visual Review

Settings 的自动审图不能只覆盖 Default 状态。长期至少覆盖：

- 默认显示页；
- 图形页；
- 操作页；
- 游戏页；
- 按键绑定展开；
- Binding Listening；
- Select Open；
- Slider Changed / Drag；
- Toggle On / Off；
- Disabled Control；
- Dirty Footer；
- Restore Defaults。

交互状态测试应该验证行为，而不是只截图。

## 12. 禁止回退

不要恢复：

- 双栏设置 Card；
- 每个 Section 左侧金边；
- 常驻说明性小字；
- 每行完整边框；
- 右侧无意义 Preview / Summary；
- 大面积暖金；
- 只有“一个按键槽”的键位设置；
- 把主要按键和次要按键合并成一串不可编辑 Keycap；
- 只有控件外观、实际不能拖动 / 点击 / 展开的静态 Prototype。
