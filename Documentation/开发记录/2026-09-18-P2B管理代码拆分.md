# P2-B Management Code Cleanup

## 目标

在 P2-A 已统一管理面板皮肤之后，继续清理管理系统代码结构，不改变现有视觉、DOM 语义和交互行为。

重点解决原 `ManagementSpace.tsx` 同时承担 Shell、财政逻辑、库存逻辑、原型数据与通用管理视图，以及 `GameplayHUD.tsx` 重复维护管理入口的问题。

## 本轮拆分

正式代码集中到 `src/gameplay/management/`：

- `ManagementSpace.tsx`
  - 只负责 Management Shell、标题、关键指标与 View 路由。
- `management-registry.ts`
  - 统一维护 ManagementSection、标题、图标、关键指标、通用列表与观察项。
- `management-navigation.ts`
  - 统一维护顶部五个管理主入口，以及顶部四个状态快捷入口。
- `OverviewManagementView.tsx`
  - 承担城市、人口、政策、商贸、治理、军事等当前共用的概览结构。
- `FinanceManagementView.tsx`
  - 独立财政图表、收入构成、税赋设置和财政判断。
- `InventoryManagementView.tsx`
  - 独立库存总览、城市仓库、周边村庄三个页签及其局部交互状态。
- `prototype-data.ts`
  - 集中存放当前 Web Prototype 的财政趋势、库存资源、仓库与村庄样例数据。

## 调用关系

- `GameplayScreen.tsx` 直接引用 `./management/ManagementSpace`。
- `GameplayHUD.tsx` 直接引用 `management-navigation.ts`。
- 旧的 `src/gameplay/ManagementSpace.tsx` 与 `src/gameplay/management-model.ts` 已删除，不保留永久兼容层。

## 边界规则

- Shell 不继续吸收具体业务页面实现。
- Registry 只放稳定的管理模块元数据，不放页内交互状态。
- Navigation 只负责“从哪里进入”，不承担面板内容。
- Prototype Data 与 View 分开，之后接真实模拟数据时可以替换数据源而不重写 UI。
- Inventory 自己拥有页签、选中仓库、选中村庄等局部 UI 状态。
- Finance 税率状态暂时仍由 Shell 持有，保持切换管理页后再返回时的现有状态行为。
- CSS 类名和 DOM 结构保持兼容，P2-B 不做美术调整。
