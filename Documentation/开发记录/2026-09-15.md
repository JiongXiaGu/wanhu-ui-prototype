# 2026-09-15

## Visual Cleanup Pass 2

在第一轮“文字减法”完成后，开始处理容器、边界、Typography 与视觉聚合。

目标不是继续删除功能，而是减少网页 / SaaS 感，同时避免界面因为过度极简而失去设计层级。

### Settings

- 减少逐行分隔线；
- Select / 数值不再使用重输入框；
- Toggle 只保留开关本体；
- Slider 减少框套框；
- 提高核心参数字号和对比度；
- 保留全屏空间，但避免把控件摊到屏幕两端。

审图结论：方向正确，但后续不能继续单纯删框，需要增加 Tone、材质和空间聚合。

### Building Workspace

- 保留一个主 Workspace Surface；
- 减弱侧栏、筛选条和内容项的盒子感；
- 建筑条目从“网页 Card”转向“游戏内容目录”；
- 提升建筑名与核心属性可读性；
- 暂时用不同线性图标区分建筑，后续应替换为真实建筑缩略图 / RenderTexture。

### BuildingPlacement

- 减少内部摘要 Card；
- Parameter Value 不再逐项套框；
- Segmented Control 减少完整外框；
- 通过对齐、留白和状态色组织层级。

### GameplayOperationHints

进一步收敛为 Shortcut Rail：

- 当前模式；
- 当前主要输入；
- 旋转 / 反转；
- 撤销 / 重做 / Esc 等次级快捷键。

不承担教程说明。

## 当前美术判断

经过减法后，项目已从“信息过密”进入新的阶段：部分界面出现“过于简约、略显单调”的风险。

下一阶段原则：

**信息继续做减法，视觉层级开始做加法。**

优先增加：

- 2%～5% 的明暗 Tone 层级；
- 极弱材质、渐变、内高光；
- Selected / Focus 暖金氛围；
- 真实游戏内容图像；
- 更丰富但克制的排版节奏；
- Hover / Tab / Flyout / Preview 的轻动效。

明确不回退到：

- 说明小字；
- 框套框；
- 装饰编号；
- 大量金边；
- 云纹、卷轴、木纹等仿古装饰。

## Visual Language Pass 3

使用 Settings、Building Workspace、BuildingPlacement 三个代表页面建立新的视觉基准。

### Settings

从单列设置表进一步调整为“一个主 Surface + 两个真实功能组”。

- 左右两栏都承载实际设置项，不恢复无意义 Preview；
- 通过主 Surface、组内 Tone、极弱内高光和 Active 氛围增加层级；
- 当前 Tab 使用暖金微染和轻量下划线聚焦；
- Slider、Select、Toggle 保持轻量控件，不恢复重输入框；
- 参数组保持信息简洁，但不再呈现 Wireframe 式空旷感。

审图结论：方向成立。全屏 Settings 可以丰富，但丰富来源应是功能组、Tone 和空间聚合，而不是额外摘要。

### Building Workspace

将建筑条目正式改为“图像为主、文字为辅”的内容目录。

- 缩略图占建筑条目主要面积；
- 暂时直接裁切项目已有真实游戏截图，而不是生成 AI 建筑图；
- 不同条目使用不同截图和裁切区域，减少纯图标占位感；
- 图标退居缩略图右上角，只作为轻量类型标识；
- 名称与一条核心属性放在底部；
- Hover 使用图片轻提亮、轻缩放、底部暖金细线。

当前真实截图裁切只是过渡方案。最终仍应由真实建筑 RenderTexture / 建筑预览截图替换，不能把当前城市截图裁切当最终建筑素材。

### BuildingPlacement

继续保持工具面板的信息密度不增加，但加强“当前状态正在工作”的感觉。

- Terrain Summary 升级为较明确的状态带；
- Position / Massing / Roof 根据模式切换局部 Ambient Tone；
- 当前参数区增加极弱暖金侧向焦点；
- 参数行与 Segmented Control 增加轻 Hover；
- 模式切换使用短 Fade + 约 5px Slide；
- Tool Dock 的 Active / Toggle / Complete 状态比普通状态更清楚；
- 未恢复任何说明段、重复标题或 Card 堆叠。

审图结论：位置、楼身、屋顶三个状态均保持清楚，面板没有因视觉丰富而变重。

## Workspace Browser Pattern

在继续审查 Building Workspace 后，重新确定所有内容型 Workspace 的统一信息架构：

`Primary Rail + Context Filter + Content Grid`

### Primary Rail

左侧只负责一级内容类别，采用“小型线性图标 + 简短文字”。

建筑当前一级分类：

- 全部；
- 塔；
- 殿；
- 楼阁；
- 屋舍；
- 门；
- 廊榭；
- 特殊。

Selected 使用左侧暖金细线、图标 / 文字提亮和弱暖金 Tone，不再使用旧方案的大方块分类按钮。

### Context Filter

顶部改为纯文字二级筛选，视觉权重低于左侧一级分类。

建筑筛选会随一级形制变化，例如：

- 塔：攒尖 / 楼阁式 / 密檐 / 覆钵；
- 殿：庑殿 / 歇山 / 悬山 / 硬山 / 卷棚；
- 屋舍：悬山 / 硬山 / 卷棚 / 歇山。

这个顶部区域是“上下文筛选”，不是固定屋顶控件。未来围墙、城墙、桥梁 Workspace 可以复用同一位置，但使用自己的结构 / 构件 / 类型词汇。

### Content Grid

建筑内容由 3 列大 Card 改成 4 列紧凑目录项。

- 矩形预览为主；
- 名称 + 一条核心属性；
- 不显示常驻用途说明；
- 不再使用大型方形 Icon Block；
- Hover 只使用轻提亮、微位移和暖金细线。

Visual Review 截图检查后，新的 Building Workspace 密度、导航层级和内容识别均比旧版更合理。

这套 Pattern 已写入 `Documentation/组件设计规范.md`，之后围墙、城墙、桥梁、道路、装饰等 Workspace 默认从该结构出发，不再各自重新设计一级 / 二级导航。
