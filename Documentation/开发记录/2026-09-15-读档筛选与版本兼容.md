# 2026-09-15 读档筛选与版本兼容

## 本轮目标

继续收敛全屏读档界面，不增加搜索和人工排序功能，把顶部区域改成真正与读取流程有关的筛选，并验证大量游戏组 / 存档下的滚动手感。

## 已完成

- 删除右侧顶部的游戏组重复信息总览；
- 顶部改为 `全部 / 自动存档 / 快速存档 / 玩家存档` 类型筛选；
- 不提供搜索框；
- 不提供排序控件；
- 默认数据顺序按真实保存时间，最新存档始终位于列表最上方；
- 增加 `隐藏过时存档` Toggle，默认关闭；
- 打开后隐藏旧版与不兼容存档；
- 存档类型统一为 Auto / Quick / Manual，默认命名示例：`自动存档.001 / 快速存档.008 / 玩家存档.025`；
- 自动 / 快速 / 玩家存档使用不同的轻量类型图标；
- 类型图标从名称区域移动到 Card 右上状态区；
- 每个存档显示版本号；
- 每个游戏组显示其最新存档版本，并提示是否包含旧版 / 不兼容存档；
- 兼容状态拆分为 Current / Outdated / Incompatible；
- Outdated 可读取；
- Incompatible 的读取按钮真正 Disabled；
- 单个存档的重命名 / 读取 / 删除继续使用 Card 自身图标操作；
- Footer 继续只管理游戏组：左侧重命名 / 删除游戏组，右侧返回。

## 压力测试数据

Web Prototype 当前故意使用大量模拟条目：

- 12 个游戏组；
- 当前默认游戏组 32 个存档；
- 其它游戏组约 18～30 个存档；
- 同时覆盖自动 / 快速 / 玩家三种类型；
- 同时覆盖当前版 / 旧版 / 不兼容状态。

目的不是最终游戏固定这些数量，而是确保滚动、Hover、Selected、状态标签和 Footer 在真实密度下仍然成立。

## Unity UI Toolkit 落地注意

- 左侧游戏组和右侧存档列表都属于高数量集合，正式版优先评估 `ListView` 固定高度虚拟化；
- 顶部类型筛选是普通互斥按钮组，不需要复杂控件；
- `隐藏过时存档` 使用共享 Toggle；
- SaveType / Version / Compatibility 应来自存档元数据，而不是 UI 自行推断；
- 不兼容判断应由 Save Migration / Version Compatibility 系统给出；
- Card 右上状态区、Card Action 区可以继续使用普通 Flex VisualElement 实现，不需要自定义绘制。
