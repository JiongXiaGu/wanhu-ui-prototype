# 《万户天工》UI 设计原则

## 1. 核心原则：信息做减法，层级做加法

常驻 UI 只显示玩家此刻完成当前任务所必须知道的信息，但简洁不等于平淡。

不要为了“解释清楚”“填满空间”或“显得完整”而常驻显示说明性副文案、重复摘要、英文眉题、统计摘要、装饰编号或无操作价值的 Preview。

信息减法之后，通过以下方式补足设计感：

- 明暗与 Tone 层级；
- 真实游戏内容与缩略图；
- Selected / Focus 的暖金微染；
- 排版节奏与留白；
- 极弱材质、内高光和环境渐变；
- 轻量 Hover / Tab / 面板切换动效。

一句话标准：**不增加无意义信息，但允许增加有意义的视觉层级。**

默认判断：

1. 玩家不看这行文字，是否仍然知道这个控件是什么、能否正确操作？如果可以，删除。
2. 这条信息是否只是把标题换一种说法重复一次？如果是，删除。
3. 这条信息是否只在第一次理解功能时有价值？如果是，移动到 Hover Tooltip / Help。
4. 这块区域是否没有新的决策、状态或反馈，只是在占空间？如果是，删除整个区域。
5. 同一事实是否已经在同屏另一位置出现？原则上只保留一次。
6. 删除信息后是否变得过于平、缺乏视觉焦点？如果是，优先增加 Tone、材质、内容图像或动效，而不是把文字和框加回来。

## 2. 说明文本

解释性信息默认不常驻显示。

优先级：

- 控件名称本身可以表达含义：不增加说明；
- 需要补充解释：Hover 约 400 ms 后显示 Tooltip；
- 复杂机制：使用专门 Help / 详情；
- 只有直接影响玩家当前决策的信息才允许常驻副文案。

例如：

- `自动保存数量` 的“每个游戏组保留的自动存档历史”不常驻；
- `游戏` Tab 下的“存档与提示”不常驻；
- 参数错误、冲突、危险结果等影响当前决定的信息可以临时常驻。

## 3. 禁止的装饰性信息

除非承担明确导航或状态意义，否则不要使用：

- `01 / 02 / 03 / 04` 等装饰编号；
- 无必要的 `>` / `→` 箭头；
- `OPTIONS`、`GAMEPLAY`、`DISPLAY OUTPUT` 等仅为气氛存在的英文眉题；
- 重复的页面副标题；
- 为填空创建的 Preview / Summary / Statistics；
- 无交互价值的品牌尾标；
- 每个项目都包一层 Card。

## 4. 信息层级

每个 UI Space 原则上最多保留三层常驻信息：

1. 当前空间 / 任务：页面标题、当前工具、当前城市；
2. 当前可操作项：按钮、参数、模式、列表；
3. 必要状态反馈：选中、错误、危险、进度、不可用原因。

解释、教程、背景知识不作为常驻第四层。

## 5. Surface、Tone 与留白

留白本身就是设计，不因为存在空白就增加内容。

- 世界画面优先于 UI 填满屏幕；
- 大面板内部允许明显留白；
- 同屏最多一个重面板；
- 能用对齐、留白、局部 Tone 解决层级时，不增加 Card / Box；
- 不为了“视觉平衡”增加没有信息价值的右栏；
- 主背景、操作区、活动区可以只有 2%～5% 的明度差；
- Selected / Focus 可使用极弱暖金染色或细金线；
- 真实游戏截图、建筑缩略图、地图预览优先于装饰纹样。

## 6. 材质与动效

材质必须弱到玩家不会直接把它当作图案。

允许：

- 极弱渐变；
- 轻微玻璃模糊；
- 很弱的内高光；
- 暖冷色温变化；
- Hover 背景淡入；
- Tab 金线滑入；
- 面板或参数内容 2～5 px 的轻微 Fade / Slide。

避免：

- 云纹、竹叶、回纹；
- 仿木纹、仿卷轴；
- 粗金边；
- 大面积 Glow；
- 为“古风”而添加的装饰元素。

## 7. Typography

目标是 1080p 下不需要努力辨认。

建议基线：

- 一级标题：18～28 px；
- 面板标题：14～18 px；
- 核心正文 / 参数：11～12 px；
- 次级信息：9.5～10 px；
- 极少数 Caption：9 px。

避免大量 7～8 px 常驻文字。字号小不能替代信息层级。

## 8. Tooltip

用于图标、缩写、低频参数和解释性细节。

- Hover 延迟约 400 ms；
- 深墨 Surface + 极弱边界；
- 第一行说明“是什么 / 做什么”；
- 必要时第二行补充影响或快捷键；
- 默认不放图片；
- 不可交互；
- Tooltip 不能成为完成基本操作的必要步骤。

项目后续应实现共享 Tooltip Component，不使用浏览器原生 Tooltip 作为最终方案。

## 9. 颜色与状态

Palette 与材质身份以 `Documentation/Wanhu 烟墨熟铜视觉材质规范.md` 为权威来源。

稳定语义：

- 结构 Surface：中性或略暖 Smoked Graphite；
- 主文字：Paper White；
- Secondary / Muted：中性暖灰；
- Selected / Current / Focus / Toggle On / Primary：Aged Brass；
- Danger：Cinnabar；
- Disabled：降低亮度和对比，不依赖额外说明。

不要使用明显青绿 / 墨绿 Surface 作为 Context 身份；也不要让所有边界、图标、标题同时发金。

## 10. 审查清单

每次新增或修改 UI 前检查：

- 是否存在标题与副标题重复表达？
- 是否存在控件下方不必要的解释小字？
- 是否存在同一信息重复出现？
- 是否为了填空增加 Preview / Statistics / 装饰？
- 是否存在无意义编号、箭头、英文眉题？
- 是否能把低频解释移动到 Tooltip？
- 当前状态是否只强调一处？
- 页面是否仍让主要游戏内容成为视觉主体？
- 删除约 20% 文字后是否仍然完全可用？如果是，应删除。
- 减法后是否过于平淡？如果是，是否优先使用 Tone、真实内容、排版和动效补层级，而不是重新增加文字/边框？

## 11. 当前视觉方向

《万户天工》不是仿古 UI，也不是 SaaS Dashboard。

目标是“现代东方策略游戏 UI”：

- Smoked Graphite / 烟墨石质 Surface；
- Paper White / 暖纸前景；
- Aged Brass / 熟铜只表达状态与主操作；
- 世界画面承担主要色彩；
- Surface 通过 Density / Elevation / Shadow 建立身份；
- Context 与 Workspace 保持同一 Hue 家族；
- 功能信息简洁；
- 材质、Tone、真实游戏内容和轻动效负责丰富画面。

视觉锚点：当前 Design Workspace。
