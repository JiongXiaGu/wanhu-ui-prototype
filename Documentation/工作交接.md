# 工作交接

这是新对话、新 AI 或新开发者接手《万户天工》UI Prototype 时的首要入口。

## 当前目标

继续完成《万户天工》的 UI 美术与交互原型，使其成为后续 Unity UI Toolkit 正式实现的可靠设计参考。

当前阶段重点不是增加更多功能，而是把已经形成的视觉语言推广到剩余页面：**信息保持精简，视觉通过 Tone、真实内容图像、材质、排版节奏与轻动效增加层级。**

## 已确认的视觉基准

### Settings

- 一个全屏 Settings Space；
- 一个主 Surface，内部按真实功能组组织；
- 可以双栏，但两栏都必须承担真实设置功能；
- 不增加无意义 Preview / Summary；
- 当前 Tab 使用弱暖金 Tone 与细线；
- 控件本身轻量，不恢复重边框。

### Workspace Browser

建筑、围墙、城墙、桥梁、道路、装饰等内容型 Workspace 统一从以下结构出发：

`Primary Rail + Context Filter + Content Grid`

#### Header

- 左上使用 Workspace 类型小图标 + 主标题；
- 不增加英文眉题或长副标题；
- 关闭按钮在右侧。

#### Primary Rail

- 位于左侧；
- 使用小型线性图标 + 简短文字；
- 只承担稳定的一级类别；
- Active 使用左侧暖金细线 + 弱暖金 Tone；
- 不使用旧方案的大方块分类按钮；
- `全部` 固定在顶部；
- 其余一级分类进入独立滚动窗口，正常只显示约 5 个，不允许一口气把所有类别铺开；
- 底部使用弱渐隐提示仍有内容，不增加上下翻页按钮。

建筑当前一级形制：

`全部 / 塔 / 殿 / 楼阁 / 屋舍 / 门 / 廊榭 / 亭 / 牌坊 / 特殊`

#### Context Filter

- 位于内容区顶部；
- 只使用纯文字；
- Active 使用文字强调 + 底部暖金细线；
- 根据当前 Primary Rail 类别动态变化；
- 不使用图标、胶囊 Tab 或完整按钮框；
- 筛选项过多时单行横向滚动，不换行。

建筑中主要用于屋顶 / 形制变体，例如：

- 塔：攒尖 / 楼阁式 / 密檐 / 覆钵；
- 殿：庑殿 / 歇山 / 悬山 / 硬山 / 卷棚；
- 屋舍：悬山 / 硬山 / 卷棚 / 歇山。

未来围墙、城墙、桥梁复用同一位置，但筛选词改为自身结构 / 构件 / 类型，不强行使用屋顶语义。

#### Content Grid

建筑当前正式基准为 **3 列横向短卡，最多同时显示 2 行**：

```text
[矩形预览]  建筑名称
            一条核心属性
```

- 建筑名称是主要识别信息；
- 矩形预览只做辅助，不再占据 Card 大部分面积；
- Card 高度约 88 px，适合快速扫描；
- 默认同时只显示 `3×2 = 6` 个建筑；
- 第三行不能露出半截，只能滚动后出现；
- 主内容区独立纵向滚动，Header / Primary Rail / Context Filter 固定；
- Prototype 数据量应足够触发真实滚动，验证密度和滚动条，而不是只预留 overflow；
- Hover 使用轻提亮、轻位移和暖金细线；
- 不使用大型方形 Icon Block；
- 不做展示型大 Card。

当前 Prototype 使用现有真实游戏截图不同裁切作为过渡缩略图。最终必须替换为真实建筑 RenderTexture / 建筑预览截图，不允许使用 AI 生成建筑图冒充实际游戏资产。

### BuildingPlacement

- 保持一个主 ToolOverlay；
- Terrain Summary 是明确但轻量的状态带；
- 当前 Position / Massing / Roof 参数区通过局部 Tone 区分；
- 模式切换允许短 Fade / Slide；
- Dock Active / Toggle / Complete 状态可以比普通状态明显；
- 不恢复说明段、重复标题或 Card 堆叠。

## 不要回退

不要重新加入：

- 说明性小字；
- 01/02/03/04 装饰编号；
- 右侧 `>` 箭头；
- 为气氛存在的英文眉题；
- 无意义 Summary / Preview；
- 每个参数 / 内容项都套 Card；
- 粗金边、卷轴、木纹、云纹等仿古装饰。

### 当前视觉原则

- 信息做减法，层级做加法；
- 世界画面优先；
- 黛墨 / 深青灰 Surface；
- 浅纸主文字；
- 暖金仅用于 Selected / Focus / 高价值状态；
- 低圆角、弱边界；
- 优先通过 Tone、留白、材质、真实内容图像和动效丰富画面；
- 如果界面显得单调，先增加内容图像、明暗层级和状态反馈，不要先加文字和边框。

详见 `Documentation/UI设计原则.md` 和 `Documentation/组件设计规范.md`。

## 下一步任务

Workspace Browser Pattern 已确定，下一步按以下顺序推广视觉语言。

### 1. Archive

目标：让“游戏组 → 存档时间线 → 存档详情”更像城市档案，而不是三栏文件管理器。

建议：

- 强化 Game Group 的真实城市截图；
- 降低栏与栏之间的硬边界；
- 时间线节点使用更清楚的 Selected / Current Tone；
- Preview 只保留真正需要的存档信息；
- 不增加种子、版本等低频常驻信息。

### 2. Camera / Weather

目标：降低均匀参数表感，增加状态与参数组的节奏。

建议：

- 保持 Right Edge Flyout；
- 使用局部 Tone 区分模式 / 参数组；
- 相机模式和天气状态成为视觉焦点；
- Slider / Segmented / Toggle 继承 Settings 与 BuildingPlacement 的控件语言；
- 不增加说明段。

### 3. New Game

目标：从当前原型卡片升级为正式世界预设选择界面。

建议：

- 世界预设图片优先；
- 河谷平原 / 江南水网 / 北地丘陵需要真实游戏世界截图槽；
- 名称与一行真正影响选择的描述保留；
- 步骤 `世界 / 地形 / 规则 / 开始` 保持简洁；
- 后续从 `App.tsx` 拆成专用 New Game 组件。

### 4. Shared Tooltip

实现正式共享 Tooltip，替换：

- 浏览器原生 `title`；
- BuildingPlacement Dock 当前 CSS 自制 Tooltip；
- 其他组件各自的提示实现。

规则：约 400 ms 延迟、深墨 Surface、弱边界、纯文本为主、不可成为完成基础操作的必要步骤。

### 5. Visual Token / CSS Cleanup

等 Archive / Camera / Weather / New Game / Tooltip 的视觉语言稳定后，再建立系统级 Token，并最后受控整理历史 CSS。

不要在视觉语言尚未完全稳定时提前大规模重构 CSS。

## 验证工作流

每轮重要 UI 修改：

1. 修改 GitHub `main`；
2. 确认代码无明显构建风险；
3. 等待 GitHub Actions Visual Review；
4. 下载 `visual-review` Artifact；
5. 人工检查相关状态截图；
6. 若局部修复影响其他 Space，必须继续迭代，不只看目标页面。

Review Scenario 可通过 `?review=...` 直接进入，不应依赖完整点击流程。

## 原始 Unity UI Toolkit 参考

早期用户提供过 `com.jiongxiaxia.wanhu-ui.zip`，其中 Building Placement、GameplayOperationHints、Input Binding 等实现是功能语义参考。

原则：

- 功能与交互语义应参考原 Unity 包；
- 不要盲目复制其旧视觉布局；
- 最终 Unity 实现的 Input Hint 应读取真实 Input System 绑定；
- Web Prototype 的代表性快捷键只用于验证界面。
