# 工作交接

这是新对话、新 AI 或新开发者接手《万户天工》UI Prototype 时的首要入口。

## 当前目标

继续完成《万户天工》的 UI 美术与交互原型，使其成为后续 Unity UI Toolkit 正式实现的可靠设计参考。

当前阶段重点不是增加更多功能，而是确定最终美术语言：在已经完成的信息减法基础上，增加 Tone、材质、真实内容图像、排版节奏和轻动效，避免界面因为过度极简而显得单调。

## 当前设计结论

### 不要回退

不要重新加入：

- 说明性小字；
- 01/02/03/04 装饰编号；
- 右侧 `>` 箭头；
- 为气氛存在的英文眉题；
- 无意义 Summary / Preview；
- 每个参数 / 内容项都套 Card；
- 粗金边、卷轴、木纹、云纹等仿古装饰。

### 当前视觉原则

- 信息做减法，层级做加法；
- 世界画面优先；
- 黛墨 / 深青灰 Surface；
- 浅纸主文字；
- 暖金仅用于 Selected / Focus / 高价值状态；
- 低圆角、弱边界；
- 优先通过 Tone、留白、材质、真实内容图像和动效丰富画面。

详见 `Documentation/UI设计原则.md`。

## 下一步任务

先做三个代表页面，建立最终视觉基准：

### 1. Settings

目标：在不恢复说明文字和卡片堆叠的前提下增加设计感。

建议：

- 内容宽度更聚合；
- 功能组之间增加弱 Tone / 节奏；
- Slider 使用更完整的横向空间；
- 加极弱材质和 Active 氛围；
- 增加轻量 Tab / Hover 动效。

### 2. Building Workspace

目标：从“原型目录”升级为真正游戏内容浏览器。

建议：

- 建立真实建筑缩略图槽；
- 后续接 Unity RenderTexture / 游戏截图；
- 图片为主、文字为辅；
- Hover / Selected 通过 Tone 和轻动效表达。

不要生成 AI 建筑图替代真实游戏资产。

### 3. BuildingPlacement

目标：保持无 Card 堆叠，同时增加局部视觉层级。

建议：

- 地形状态与当前参数组通过局部 Tone 区分；
- ToolOverlay 模式切换加入轻 Fade / Slide；
- Tool Dock 增强 Selected / Toggle 状态反馈；
- 不恢复冗余说明和重复标题。

完成这三个基准后，再推广到：

- Archive；
- Camera / Weather；
- New Game；
- 共享 Tooltip。

## 验证工作流

每轮重要 UI 修改：

1. 修改 GitHub `main`；
2. 确认 `npm run build`；
3. 等待 GitHub Actions Visual Review；
4. 下载 `visual-review` Artifact；
5. 人工检查相关状态截图；
6. 若局部修复影响其他 Space，必须继续迭代，不只看目标页面。

Review Scenario 可通过 `?review=...` 直接进入，不应依赖完整点击流程。

## 原始 Unity UI Toolkit 参考

早期用户提供过 `com.jiongxiaxia.wanhu-ui.zip`，其中 Building Placement、GameplayOperationHints、Input Binding 等实现是功能语义参考。

原则：

- 功能与交互语义应参考原 Unity 包；
- 不要盲目复制其旧视觉布局；
- 最终 Unity 实现的 Input Hint 应读取真实 Input System 绑定；
- Web Prototype 的代表性快捷键只用于验证界面。
