## UI Toolkit 落地约束（必须先读）

本仓库的网页只是 **UI 美术 / 构图 / 信息架构 / 交互验证原型**，不是最终 Web 产品。

正式游戏 UI 最终由 Unity UI Toolkit 实现：

- UXML：稳定结构；
- USS：布局、视觉状态、Transition；
- C#：状态、事件、数据绑定、输入与运行时控制；
- Sprite / Texture / RenderTexture：视觉资产；
- Painter2D / Mesh：必要的自定义绘制；
- URP：需要的场景级渲染效果。

当前已确认计划使用 **URP 全屏 Blur Pass** 处理需要明显背景模糊的空间。Web 中的 `backdrop-filter` 只是视觉参考，不要求 Unity 复制其 CSS 实现。

后续 AI / 开发者必须遵守：

1. 不要为了 Web CSS 写起来方便而设计 Unity 难以维护的核心结构；
2. 不要因为 Web CSS 与 USS 不同，就把视觉效果简单删掉；
3. 视觉合理但实现不同，应在 Unity 中换成合适的 Sprite / VisualElement / RenderTexture / URP 方案；
4. 只有结构、交互、性能或信息架构本身不适合 Unity 时，才回头修改 Web 设计；
5. 新增重要 UI 时，要能说明其 `UXML + USS + C# + 资产 + Input` 对应关系；
6. 鼠标设计不能成为唯一输入逻辑，必须考虑键盘与手柄；
7. 1920 × 1080 是设计基准，不代表 Unity 只支持该分辨率。

正式规范见：`Documentation/UI Toolkit落地规范.md`。

迁移审查记录见：`Documentation/代码审查/2026-09-15-UI Toolkit迁移可行性审查.md`。

## 当前视觉原则

- 信息做减法，层级做加法；
- 世界画面优先；
- 黛墨 / 深青灰 Surface；
- 浅纸主文字；
- 暖金只用于 Selected / Focus / 高价值状态；
- 低圆角、弱边界；
- 能靠 Tone、留白、材质和真实内容图像组织时，不增加框；
- 如果界面显得单调，先增加真实内容、明暗层次和状态反馈，不先加说明文字；
- 解释性副文案默认移到 Tooltip，不常驻。

## Workspace Browser 当前正式基准

统一结构：

`Primary Rail + Context Filter + Content Grid`

### Header

- 左上：Workspace 类型小图标 + 主标题；
- 右侧：关闭；
- 不增加英文眉题和长副标题。

### Primary Rail

建筑当前一级筛选：

`全部建筑 / 塔 / 殿 / 楼阁 / 屋舍 / 门 / 廊榭 / 亭 / 牌坊 / 特殊`

规则：

- 所有一级筛选使用同一种 Item 视觉；
- `全部建筑` 不再使用特殊入口、特殊卡片或分隔区；
- 每组显示 5 个一级筛选；
- 组分页使用左侧竖向刻度：弱圆点 + 当前暖金短条；
- 刻度可点击切换可见分类组；
- 切组只改变 Rail 里当前显示哪些分类，不自动选择某个分类；
- Primary Rail 上滚轮向下 / 向上分别切下一组 / 上一组。

Unity 正式实现可对应成固定 5 个 Category Slot + `PagedCategoryRail<T>`，不需要为全部分类同时创建可见节点。

### Context Filter

建筑当前顶部二级筛选：

`全部 / 庑殿 / 歇山 / 悬山 / 硬山 / 攒尖 / 卷棚 / 其他`

它与 Primary Rail 是**正交筛选维度**：

- 切换 `塔 / 殿 / 楼阁 / 全部建筑` 不得重置顶部筛选；
- `全部建筑` 只表示取消一级类别限制；
- 顶部 Context Filter 保持当前选中项；
- 两个筛选共同决定 Content Grid 内容。

这个原则以后同样用于其它 Workspace：左侧是一级内容类别，顶部是独立的上下文维度，不应该因为一级筛选变化而偷偷替换逻辑。

### Content Grid

建筑当前固定：

`3 列 × 2 行 = 6 个建筑 / 组`

Card：

```text
[矩形预览]  建筑名称
            一条核心属性
```

- 文字是主要识别信息；
- 矩形预览是辅助；
- 不做展示型大 Card；
- 不使用大型方形 Icon Block；
- Hover 只做轻提亮、轻位移和暖金细线。

Unity 正式实现优先采用固定 6 个 Card Slot / Pool；真实建筑预览可使用 Texture / RenderTexture，但只更新当前可见内容。

### Content Pager

底部使用：

```text
·   ·   ━   ·   ·
```

- 当前组 = 暖金短横；
- 其他组 = 弱圆点；
- 不显示数字页码、`1 / N` 或传统左右箭头；
- 指示项可点击；
- 页数较多时最多显示当前附近 5 个。

### Wheel Paging

滚轮是**分页快捷输入**，不是取消分页 UI。

- 鼠标在 Content Grid：下滚下一组，上滚上一组；
- 鼠标在 Primary Rail：下滚下一组分类，上滚上一组分类；
- Context Filter / 搜索区不响应组分页滚轮；
- 当前实现使用滚动距离累计阈值 + 约 220 ms 锁定；
- 一次有效手势只允许翻一组；
- 边界不循环；
- 滚轮切分类组不会自动改变当前选中的一级筛选。

Unity Runtime 应用 UI Toolkit 对应滚轮事件实现相同语义，并同时提供键盘 / 手柄导航。

### Search

- 默认只显示 `搜索图标 + 搜索`；
- 点击后展开轻量输入槽；
- 不常驻完整 Web input；
- 搜索与 Primary Rail / Context Filter 共同参与筛选。

## BuildingPlacement 当前基准

- 一个主 ToolOverlay；
- Terrain Summary 是轻量状态带；
- Position / Massing / Roof 通过局部 Tone 区分；
- 模式切换允许短 Fade / Slide；
- Dock Active / Toggle / Complete 比普通状态清楚；
- 不恢复重复说明、分组标题或 Card 堆叠。

Unity 正式实现应优先复用既有 BuildingPlacement 功能语义，Web 只作为新的视觉与布局参考。

## Blur 约束

统一原则：

- Blur 是场景级渲染能力，不是每个 UI Element 自己做的局部 CSS 效果；
- Pause / Settings / Archive 等需要明显背景压制时可以请求统一 Blur；
- 普通 Gameplay 面板优先使用透明 Surface + Tone；
- Unity 中统一由 URP 全屏 Blur Pass 管理模糊半径、降采样和性能档位；
- 不为每个面板建立自己的 RenderTexture Blur 链路。

## 不要回退

不要重新加入：

- 常驻说明性小字；
- 01 / 02 / 03 / 04 装饰编号；
- 无意义右箭头；
- 英文气氛眉题；
- 无意义 Summary / Preview；
- 参数 / 内容项层层 Card；
- 粗金边、卷轴、木纹、云纹等仿古装饰；
- `全部建筑` 的特殊入口设计；
- 切换一级筛选时自动重置顶部 Context Filter；
- Workspace 的数字页码；
- 一次滚轮动作连续翻过多个组；
- 为了 Web CSS 方便而新增无法合理映射到 Unity 的核心结构。

## 下一步任务

Workspace Browser 当前已基本稳定，后续按以下顺序继续。每个新页面在美术确认前都要同时检查 UI Toolkit 可落地性。

### 1. Archive

目标：让 `Game Group → Save Timeline → Preview` 更像城市档案而不是文件管理器。

重点：

- 强化真实城市截图；
- 降低三栏硬边界；
- 加强 Selected / Current Tone；
- 不增加低频详情常驻文字；
- Unity 中三栏优先用 Flex；大量存档时再考虑 ListView 虚拟化。

### 2. Camera / Weather

目标：减少均匀参数表感。

重点：

- 保持 Right Edge Flyout；
- 用局部 Tone 建立参数组节奏；
- 相机模式 / 天气状态成为视觉焦点；
- 继承 Settings / BuildingPlacement 控件语言；
- Unity 侧避免依赖 CSS-only 特效来维持视觉层级。

### 3. New Game

目标：从早期 Web Flow 升级为正式世界预设选择界面。

重点：

- 使用真实世界截图槽；
- 名称 + 一行真正影响选择的描述；
- `世界 / 地形 / 规则 / 开始` 保持简洁；
- 从 `App.tsx` 拆为专用组件；
- 同时规划对应的 Unity UXML 层级。

### 4. Shared Tooltip

建立正式共享 Tooltip，替换浏览器 `title` 与组件各自实现。

Unity Runtime 应对应正式 `GameplayTooltipController`。

### 5. Visual Token / CSS Cleanup

等剩余页面视觉稳定后，再建立系统级 Token 并受控整理历史 CSS。

Web Token 应能明确映射到 Unity USS / Theme Token，不要形成只在浏览器成立的一套设计值。
