# 建筑配色方案模式设计规范

## 1. 定位

建筑配色方案模式是“配色工具”的第三个内部模式，用于管理“某一栋已经存在的建筑当前使用哪套完整配色方案”。

它不是 Material Surface Editor，也不是 Material Preset Library。

职责分层：

```text
Material Preset
→ 单个材质如何表现

Building Color Scheme
→ 一栋建筑不同部位组合哪些材质 / 颜色语义

Building Appearance
→ 某栋建筑当前使用哪个 Scheme
  + Weathering
```

第一阶段 Web Prototype 只验证：

1. 场景建筑选择；
2. 左侧 Building Appearance Panel；
3. 做旧程度；
4. 当前配色方案；
5. 中央 Building Scheme Workspace；
6. Style × Source 筛选；
7. 应用方案与建筑 Rebind。

不做方案创建 / 编辑 / 删除 / Workshop 上传。

## 2. 进入方式

Building Scheme Workspace 有两条入口，共用同一方案数据与 Workspace：

1. 世界级 Color Tool 内部 Scheme Mode：用于从配色工具浏览场景建筑；
2. Building Selection 快捷入口：用于给当前已经选中的单栋建筑直接设置方案。

World Context Utility 不新增独立“方案模式”。

统一流程：

```text
World Utility
→ 配色工具
→ MaterialPaletteDock
   ├ 表面模式
   ├ 灯光模式
   └ 方案模式
```

点击“方案模式”后：

- 顶层 Tool 仍是 `material-palette`；
- `MaterialPaletteMode = scheme`；
- MaterialPaletteDock 保持挂载；
- 左下显示 Building Appearance Panel；
- Web Prototype 显示少量 Building Handle 模拟场景 Picking；
- 不自动打开中央 Workspace。

正式 Unity：

```text
Pointer / Raycast
→ Building Entity / Selection Proxy
→ SelectedBuildingId
→ BuildingAppearancePanel Rebind
```

Web Building Handle 只属于 Prototype Adapter。

Building Selection 路径：

```text
Building Selection
├ 中下「配色」Toggle
└ 左侧「配色方案」Navigation Field
        ↓
BuildingSchemeWorkspace
```

这条路径不切换顶层 Tool，也不挂载 ColorToolDock。中下“配色”保持可见并以 aria-pressed 表示 Workspace 开关；再次点击或 Esc 只关闭 Workspace，仍保持当前建筑 Selection。

## 3. 左侧 Building Appearance Panel

未选择建筑：

```text
建筑外观
请选择场景建筑

选择一栋场景建筑
点击世界中的建筑标记开始管理配色方案。
```

选中建筑：

```text
建筑外观
重檐楼阁 03

外观参数

配色方案   [ 江南素雅        › ]
做旧程度   [-] ─────●──── [+] 35%
```

稳定规则：

- Panel 复用 Shared LeftContextPanel；
- 选中另一建筑时同一个 Panel Rebind；
- 不生成第二个 Inspector；
- 第一阶段只保留“配色方案 / 做旧程度”；
- 后续建筑基础信息继续追加到该 Panel，不提前制造空 Section。

## 4. 做旧程度

第一阶段：

```text
0.00 = 全新
1.00 = 明显做旧
```

UI：

- 0–100%；
- Step = 1%；
- 使用共享 RuntimeParameterRow → NumericSliderField；
- 不创建独立 Weathering Slider。

数据：

```text
BuildingAppearance.Weathering
```

## 5. 配色方案入口

“配色方案”是参数行中的一个普通 Navigation Field：

```text
配色方案   [ 江南素雅        › ]
```

点击：

- 左侧 Building Appearance Panel 保持挂载；
- 当前建筑保持选中；
- 中央打开 BuildingSchemeWorkspace；
- 关闭 Workspace 只关闭浏览器，不退出方案模式。

## 6. Building Scheme Workspace

直接消费共享 `workspace--catalog`：

```text
Header
├ 配色方案
└ Close

Body
├ Primary Rail = Style
└ Catalog
   ├ Source Filter
   ├ 4×2 Scheme Cards
   └ Pager
```

建议宽度约 1040px，与左侧约 390px Panel 共存。

不复制 Design / Material 的 Workspace Shell USS。

## 7. 左侧 Style Rail

第一阶段：

```text
全部
素雅
沉稳
明快
华丽
自然
其他
```

这是完整建筑配色的视觉风格，不是 Material Family。

稳定 Key：

```text
elegant
restrained
vivid
ornate
natural
other
```

“全部”只作为 Filter。

Rail 顶部“收藏”使用共享 Toggle，只控制 favoriteOnly；它与 Style / Source 正交组合，不占用 Style Selected 状态。切换风格不得隐式关闭收藏 Toggle，开启/关闭收藏也不得把当前风格改回“全部”。

当前 7 项正好使用一组 Rail，不需要额外分类分页。

## 8. 顶部 Source Filter

固定：

```text
全部 | 系统内置 | 创意工坊 | 玩家方案
```

稳定 Key：

```text
builtin
workshop
player
```

Style 与 Source 正交组合：

```text
Style × Source
```

例如：

- 素雅 × 系统内置；
- 自然 × 创意工坊；
- 明快 × 玩家方案。

## 9. Scheme Card

第一阶段没有真实 Building Scheme Thumbnail，因此不制造假建筑预览。

Card：

```text
┌────────────────────────────────┐
│ 江南素雅              系统内置 │
│ ━━━━━━━━   素雅                │
└────────────────────────────────┘
```

规则：

- 继续使用 WorkspaceItemCard；
- 第一行：Name + Source；
- 第二行：低权重 Palette Accent + Style；
- Palette Accent 只用约 36×3px 三段细色线；
- 不使用大面积纯色图块；
- Current Scheme 使用共享左侧 State Line；
- 4×2，每页 8 项；
- 详细 Hover Card 直接消费全局 Hover Framework 的 Catalog Workspace 规则，固定显示在当前 Scheme Card 上方并水平居中；Feature 不重复声明 `placementMode`；
- Hover Card 保持只读与 Pointer Ignore，允许覆盖相邻目录内容，但不得遮住当前 Anchor；只做 Safe Edge / Clamp，不因左右空间变化切换方向。

未来有真实 BuildingSchemeThumbnail 时才启用 Preview Slot。

## 10. Apply / Rebind

点击 Scheme Card：

```text
BuildingAppearance.ColorSchemeId = schemeId
→ 场景建筑实时刷新
→ 左侧“配色方案”名称更新
→ Workspace 保持打开
→ Scheme Card Selected 更新
```

切换建筑：

```text
Building A + Workspace Open
→ 点击 Building B
→ Left Panel Rebind
→ Workspace 保持打开
→ Selected Card 改为 Building B 的 Scheme
```

不关闭 Workspace，不重置 Style / Source Filter。

## 11. 数据边界

```text
BuildingAppearance
├ BuildingId
├ ColorSchemeId
└ Weathering

BuildingColorScheme
├ Id
├ Name
├ Source
├ StyleFamily
└ Bindings
```

第一阶段 Web 只模拟 `Id / Name / Source / Style / Palette Accent`。

正式 Scheme Binding 可逐步扩展：

```text
BuildingColorBindings
├ RoofPresetId
├ WallPresetId
├ WoodPresetId
├ MetalPresetId
└ DecorationPresetId
```

建筑实例只保存 SchemeId，不复制整套颜色数据。

## 12. Unity UI Toolkit 映射

```text
BuildingAppearancePanel.uxml

LeftContextPanel

```

中央：


应复用：

- Catalog Workspace Shell；
- WorkspacePrimaryRail；

- Content Pager；
- LeftContextPanel；
- NumericSliderField。

## 13. UI Review

必须同时检查 Color Tool Scheme Mode 与 Building Selection 快捷路径。

Building Selection 快捷路径额外检查：

- 中下“配色”是 Toggle，打开后有 Selected 状态，再次点击关闭；
- 左侧 Inspector 显示当前方案名和做旧程度；
- 左侧“配色方案”行与中下 Toggle 打开同一个 BuildingSchemeWorkspace；
- Apply 后左侧方案名实时更新，Workspace 不关闭；
- Esc 先关闭 Scheme Workspace，不清建筑 Selection；
- Selection 右下不再重复出现配色按钮。

原 Color Tool Scheme Mode 仍必须检查：

- World Utility 不存在独立“方案模式”，只通过“配色工具”进入；
- 进入时没有自动打开中央 Workspace；
- 未选择建筑时有明确空状态；
- 选择建筑后显示当前方案和做旧程度；
- 点击配色方案后左 Panel 与 Workspace 共存；
- Style Rail 为 全部 / 素雅 / 沉稳 / 明快 / 华丽 / 自然 / 其他；
- Source Filter 为 全部 / 系统内置 / 创意工坊 / 玩家方案；
- Style × Source 可组合；
- first page 使用共享 4×2 Card Pool；
- 不出现假 Thumbnail；
- Apply 后左侧名称同步且 Workspace 不关闭；
- 切换建筑时左 Panel 与 Workspace 同时 Rebind；
- 关闭 Workspace 不退出配色工具；
- 表面 / 灯光 / 方案三个模式切换时共用同一个 MaterialPaletteDock；
- 退出 Tool 后恢复 World Utility。
