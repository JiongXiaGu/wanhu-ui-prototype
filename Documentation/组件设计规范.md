# 组件设计规范

## 1. 组件设计目标

组件不是为了网页复用而抽象，而是为了让游戏 UI 的视觉语言、状态表达和交互规则保持一致。

优先共享：

- 相同语义；
- 相同交互；
- 相同视觉状态；
- 相同生命周期。

不要为了减少文件数量，把语义不同的界面强行做成同一个万能组件。

## 2. Button

### Primary

用于当前界面最主要动作，例如：

- 应用设置；
- 载入存档；
- 开始游戏；
- 完成放置。

表现：

- 暖金作为 Focus / Selected / Primary 强调；
- 不使用高饱和大面积金色；
- 同屏原则上只有一个明显 Primary。

### Secondary

用于返回、取消、恢复默认、低优先级动作。

取消未提交工具操作不视为危险操作。

### Icon Cell

高频工具栏优先使用图标单元格，例如：

- 网格吸附；
- 网格显示；
- 撤销；
- 重做。

图标单元格必须有 Tooltip。

## 3. Segmented Control

用于互斥模式切换，例如：

- 平 / 填 / 高；
- 位 / 层 / 顶 / 面；
- 相机模式；
- 天气模式。

视觉规则：

- 不做厚重外框；
- Selected 使用暖金细线、文字或极弱暖金染色；
- 不同时使用粗边框 + 大面积金底 + 金色文字。

## 4. Parameter Row

参数行只显示完成当前操作必要的信息。

常见形式：

- Label + Select；
- Label + Toggle；
- Label + Value；
- Label + Keycap；
- Label + Slider。

不在每个参数下面常驻解释文字。

需要解释时使用共享 Tooltip。

## 5. Slider

Slider 不应被包在大型输入框内。

建议结构：

```text
参数名
────────────●────    100%
```

或在空间较紧时：

```text
参数名    ─────●──    100%
```

Value 是状态，不需要额外 Card。

## 6. Toggle

Toggle 用于明确的 On / Off 状态。

- 开关本体承担主要状态表达；
- 除非 On / Off 文本不可避免，否则不要同时显示“开启”文字和明显开关状态；
- Disabled 状态降低对比度。

## 7. Tooltip

Tooltip 是低频解释的统一承载方式。

规则：

- Hover 延迟约 400 ms；
- 统一深墨 Surface；
- 极弱边界；
- 第一行：功能或参数含义；
- 第二行可选：影响 / 快捷键；
- 不显示无意义标题；
- 不放交互控件；
- 不使用浏览器原生 Tooltip 作为最终实现。

所有 Icon-only 控件必须可通过 Tooltip 理解。

## 8. Keycap

Keycap 用于操作提示，不用于装饰。

表现：

- 小尺寸；
- 对比明确；
- 不做拟物键盘帽；
- 可与动作文字组合。

示例：

```text
[左键] 确认位置
[R]    旋转
[Esc]  取消
```

Unity 最终实现应由 Input System 实际绑定驱动显示。

## 9. Surface

Surface 是空间层级，不是 Card 装饰。

优先级：

1. 世界 / 背景；
2. 主空间 Surface；
3. 活动区域 Tone；
4. Selected / Focus。

能靠 2%～5% 明度差、留白或对齐组织时，不增加边框。

同屏避免多个同等重量的大黑面板。

## 10. Workspace Browser

建筑、围墙、城墙、桥梁、道路、装饰等内容型 Workspace 统一使用：

`Primary Rail + Context Filter + Content Grid`

### Header

Workspace 标题区使用“小图标 + 主标题”。

- 图标用于快速识别 Workspace 类型；
- 不增加英文眉题或长副标题；
- 关闭按钮保持在右侧。

### Primary Rail

位于 Workspace 左侧，负责一级内容分类。

- 使用小型线性图标 + 简短文字；
- 图标是分类符号，不是内容预览；
- Selected 使用左侧暖金细线、亮文字和极弱暖金 Tone；
- 不使用大方块分类按钮；
- 一级分类应长期稳定，例如建筑可使用 `全部 / 塔 / 殿 / 楼阁 / 屋舍 / 门 / 廊榭 / 亭 / 牌坊 / 特殊`；
- `全部建筑` 固定在 Rail 顶部，作为稳定入口；
- 其余一级分类按组分页，建筑当前每组显示 5 个分类；
- 不显示 `1 / 2` 之类页码；
- 使用左右边缘箭头与一条极弱细线表达“上一组 / 下一组”；
- 到达首组或末组时，相应方向控制弱化或隐藏；
- 不使用自由滚动条承载大量一级分类。

这种分组方式用于限制同屏暴露量，让玩家对一组类别形成稳定空间记忆，也便于手柄/键盘导航。

### Context Filter

位于内容区顶部，负责当前一级分类中的二级筛选。

- 默认使用纯文字；
- Selected 使用文字强调 + 底部 2 px 暖金线；
- 不使用图标、胶囊背景或完整 Tab 方框；
- 筛选项根据 Primary Rail 当前类别动态变化；
- 常规情况下保持单行；
- 二级筛选通常数量较少，不引入页码；如未来发生溢出，应优先使用轻量“更多”入口或不显式暴露的横向溢出方案，而不是建立第三套强分页器。

Context Filter 的语义由 Workspace 决定：

- 建筑：屋顶 / 形制变体，例如 `庑殿 / 歇山 / 硬山 / 攒尖 / 卷棚`；
- 围墙：结构或材质，例如 `直段 / 转角 / 门洞 / 端头`；
- 城墙：构件，例如 `墙段 / 马面 / 敌楼 / 城门 / 瓮城`；
- 桥梁：类型，例如 `梁桥 / 拱桥 / 廊桥 / 浮桥`。

不要为了统一外观强迫所有 Workspace 使用相同筛选词。

### Content Grid

主体用于大量真实内容的快速浏览。

建筑 Workspace 当前基准采用 **3 列横向短卡 × 2 行，每组固定 6 个内容项**：

```text
[矩形预览]  建筑名称
            核心属性
```

规则：

- 文字是主要识别信息，预览图是辅助；
- 左侧使用标准矩形预览，不使用超宽 Banner，也不使用大型方形 Icon Block；
- 右侧只显示名称 + 一条核心属性；
- 长期目标仍是真实建筑缩略图 / RenderTexture；
- Hover 使用轻提亮、约 1 px 位移和暖金细线；
- 不使用纵向自由滚动浏览大量建筑；
- 内容按 6 个一组切换，始终保持稳定的 `3 × 2` 空间结构；
- 不显示数字页码或分页点；
- 主内容左右边缘使用轻量上一组 / 下一组箭头；
- 当后面还有内容时，可在边缘露出下一组两行卡片各自的一小块缩略图边缘，形成“后面还有一组”的视觉提示；
- 这种露边必须看起来像卡片的一部分，不能形成连续竖条而被误读为滚动条；
- 切组采用约 160～200 ms 的轻量 Fade / 横向位移，不做大幅滑屏。

建筑当前默认密度为 `3 列 × 2 行 = 6 个可见条目`。其他 Workspace 可以根据条目宽度调整列数和组容量，但仍应限制同时暴露的内容量，避免把 Workspace 变成铺满屏幕的内容墙。

### 分页视觉语言

Workspace 的分页属于“组浏览”，不是传统网页分页。

- 不显示 `1 / 12`、数字页签或一排圆点；
- 不要求玩家知道精确页号，只需要知道“前面 / 后面还有内容”；
- 左侧 Primary Rail 与主 Content Grid 共用边缘方向、弱细线、短动效等视觉语言；
- 左栏通过边缘 Pager 切换一组分类；
- 主内容通过边缘箭头与卡片露边切换一组内容；
- 在第一页时上一组控制可隐藏，在最后一页时下一组控制可隐藏；
- 搜索属于未来用于大量内容精准定位的补充方式，不用页码替代搜索。

避免：

- 每张条目完整 Card 边框；
- 大型方形 Icon Block；
- 多层标签；
- 长说明文本；
- 相同占位图反复出现；
- 把一级分类和二级筛选做成相同视觉权重；
- 为了塞更多条目使用过度狭窄的 Card；
- 无限长滚动列表；
- 数字页码、分页圆点或传统网页 Pager；
- 用一整条细竖条冒充“下一页内容露边”。

### Workspace 信息层级

默认视觉权重：

`内容名称 > Primary Rail Active > 矩形预览 > Context Filter > 次级属性`

Primary Rail 负责稳定导航，Context Filter 保持轻量，内容名称承担最快识别；预览图辅助识别而不是主导整个 Card。

## 11. Archive Item

Archive 的层级是：

`Game Group → Save Timeline → Save Preview`

### Game Group

Game Group 用城市截图、城市名、年代和最近保存时间建立识别。

### Save Timeline

同一 Game Group 内的 Save 按时间组织，支持自动存档与手动存档。

时间轴是信息结构，不应做成普通文件列表。

### Preview

Preview 只显示影响识别与决策的信息，例如：

- 城市截图；
- 城市名；
- 年代 / 季节；
- 保存时间；
- 游戏时长；
- 少量关键城市状态。

世界种子、版本等低频信息放到详情或 Tooltip。

## 12. Right Edge Flyout

Camera / Weather 使用同一个右侧 Flyout 视觉语言。

- 从屏幕右边缘出现；
- Header 简洁；
- 内部参数靠分组、留白和 Tone 组织；
- 不使用英文眉题和长说明；
- 不创建无意义 Summary Card。

## 13. Pause Menu

Pause Menu 是轻量全局命令列表。

只保留：

- 继续游戏；
- 保存游戏；
- 游戏设置；
- 返回主菜单。

不要增加：

- 01 / 02 / 03 / 04 编号；
- 右箭头；
- 每项副说明；
- 无意义品牌尾标。

## 14. 动效

动效用于强化状态变化，不用于展示技术效果。

推荐：

- Hover：约 100 ms；
- Tab Active：约 120～160 ms；
- Workspace / Flyout：约 160～220 ms；
- 参数模式切换：Fade + 2～5 px 位移；
- Workspace 分组翻页：约 160～200 ms 的 Fade + 轻横移；
- Archive Preview：轻量 Cross Fade。

避免大幅弹跳、Scale 过冲、强 Glow 和长时间缓动。
