# 组件设计规范

## 1. 组件设计目标

组件不是为了网页复用而抽象，而是为了让游戏 UI 的视觉语言、状态表达和交互规则保持一致。

优先共享：

- 相同语义；
- 相同交互；
- 相同视觉状态；
- 相同生命周期。

不要为了减少文件数量，把语义不同的界面强行做成同一个万能组件。

## 2. Button

### Primary

用于当前界面最主要动作，例如：

- 应用设置；
- 载入存档；
- 开始游戏；
- 完成放置。

表现：

- 暖金作为 Focus / Selected / Primary 强调；
- 不使用高饱和大面积金色；
- 同屏原则上只有一个明显 Primary。

### Secondary

用于返回、取消、恢复默认、低优先级动作。

取消未提交工具操作不视为危险操作。

### Icon Cell

高频工具栏优先使用图标单元格，例如：

- 网格吸附；
- 网格显示；
- 撤销；
- 重做。

图标单元格必须有 Tooltip。

## 3. Segmented Control

用于互斥模式切换，例如：

- 平 / 填 / 高；
- 位 / 层 / 顶 / 面；
- 相机模式；
- 天气模式。

视觉规则：

- 不做厚重外框；
- Selected 使用暖金细线、文字或极弱暖金染色；
- 不同时使用粗边框 + 大面积金底 + 金色文字。

## 4. Parameter Row

参数行只显示完成当前操作必要的信息。

常见形式：

- Label + Select；
- Label + Toggle；
- Label + Value；
- Label + Keycap；
- Label + Slider。

不在每个参数下面常驻解释文字。

需要解释时使用共享 Tooltip。

## 5. Slider

Slider 不应被包在大型输入框内。

建议结构：

```text
参数名
────────────●────    100%
```

或在空间较紧时：

```text
参数名    ─────●──    100%
```

Value 是状态，不需要额外 Card。

## 6. Toggle

Toggle 用于明确的 On / Off 状态。

- 开关本体承担主要状态表达；
- 除非 On / Off 文本不可避免，否则不要同时显示“开启”文字和明显开关状态；
- Disabled 状态降低对比度。

## 7. Tooltip

Tooltip 是低频解释的统一承载方式。

规则：

- Hover 延迟约 400 ms；
- 统一深墨 Surface；
- 极弱边界；
- 第一行：功能或参数含义；
- 第二行可选：影响 / 快捷键；
- 不显示无意义标题；
- 不放交互控件；
- 不使用浏览器原生 Tooltip 作为最终实现。

所有 Icon-only 控件必须可通过 Tooltip 理解。

## 8. Keycap

Keycap 用于操作提示，不用于装饰。

表现：

- 小尺寸；
- 对比明确；
- 不做拟物键盘帽；
- 可与动作文字组合。

示例：

```text
[左键] 确认位置
[R]    旋转
[Esc]  取消
```

Unity 最终实现应由 Input System 实际绑定驱动显示。

## 9. Surface

Surface 是空间层级，不是 Card 装饰。

优先级：

1. 世界 / 背景；
2. 主空间 Surface；
3. 活动区域 Tone；
4. Selected / Focus。

能靠 2%～5% 明度差、留白或对齐组织时，不增加边框。

同屏避免多个同等重量的大黑面板。

## 10. Workspace Browser

建筑、围墙、城墙、桥梁、道路、装饰等内容型 Workspace 统一使用：

`Primary Rail + Context Filter + Content Grid`

三个区域职责必须稳定：

- Primary Rail：一级内容类别；
- Context Filter：独立的二级筛选维度；
- Content Grid：当前筛选组合下的真实内容。

### Header

Workspace 标题区使用“小图标 + 主标题”。

- 图标用于快速识别 Workspace 类型；
- 不增加英文眉题或长副标题；
- 关闭按钮保持在右侧。

### Primary Rail

位于 Workspace 左侧，负责一级内容分类。

建筑当前类别：

`全部建筑 / 塔 / 殿 / 楼阁 / 屋舍 / 门 / 廊榭 / 亭 / 牌坊 / 特殊`

规则：

- 使用小型线性图标 + 简短文字；
- 图标是分类符号，不是内容预览；
- `全部建筑` 是一个普通一级筛选项，不使用特殊 Card、分隔线或额外容器；
- `全部建筑` 与 `塔 / 殿 / 楼阁 / 屋舍` 使用完全相同的 Item 样式和 Selected 规则；
- Selected 使用左侧暖金细线、亮文字和极弱暖金 Tone；
- 不使用大方块分类按钮；
- 建筑当前每组显示 5 个一级筛选项；
- 一级分类组使用竖向刻度切组，不显示数字页码，也不使用传统上一页 / 下一页箭头。

一级分类组的分页使用 **竖向刻度语言**：

- 刻度放在分类列表左侧；
- 非当前组显示为弱圆点；
- 当前组显示为暖金竖向短条；
- 刻度之间可以有极弱纵向连接线；
- 刻度本身可点击切换“当前可见的类别组”；
- 切换类别组只改变 Rail 中显示哪些筛选项，不自动选择该组第一个分类，不应偷偷改变 Content Grid 的筛选状态。

这套表现表达“当前正在浏览哪一组一级筛选”，不是滚动条，也不是精确页码。

### Context Filter

位于内容区顶部，负责与 Primary Rail **正交**的二级筛选。

建筑 Workspace 当前用于屋顶 / 形制维度，例如：

`全部 / 庑殿 / 歇山 / 悬山 / 硬山 / 攒尖 / 卷棚 / 其他`

规则：

- 默认使用纯文字；
- Selected 使用文字强调 + 底部 2 px 暖金线；
- 不使用图标、胶囊背景或完整 Tab 方框；
- Primary Rail 和 Context Filter 是两个独立筛选维度；
- 切换 `全部建筑 / 塔 / 殿 / 楼阁...` 不得重置或替换当前顶部筛选；
- 选择 `全部建筑` 只表示取消一级类别限制，不改变 Context Filter 的选中状态；
- Primary Rail 与 Context Filter 的组合共同决定 Content Grid 内容；
- 常规情况下保持单行；
- 二级筛选通常数量较少，不引入独立强分页器。

不同 Workspace 可以使用自己的 Context Filter 语义，例如：

- 建筑：屋顶 / 形制；
- 围墙：结构 / 材质；
- 城墙：构件类型；
- 桥梁：桥型。

不要为了统一外观强迫所有 Workspace 使用相同筛选词。

### Search

搜索是大量内容下的精准定位入口，不应长期占据明显视觉空间。

默认状态：

```text
[搜索图标] 搜索
```

规则：

- 默认只显示轻量图标 + 短文字；
- 不显示完整 Web 输入框；
- 点击后展开为约 180 px 的轻量输入槽；
- 输入槽只使用弱 Tone 与底部细线，不使用完整矩形描边；
- Esc 或关闭按钮退出搜索；
- 搜索条件变化后内容分页回到第一组；
- 搜索与当前 Primary Rail / Context Filter 共同参与筛选。

### Content Grid

主体用于大量真实内容的快速浏览。

建筑 Workspace 当前基准采用 **3 列横向短卡 × 2 行，每组固定 6 个内容项**：

```text
[矩形预览]  建筑名称
            核心属性
```

规则：

- 文字是主要识别信息，预览图是辅助；
- 左侧使用标准矩形预览，不使用超宽 Banner，也不使用大型方形 Icon Block；
- 右侧只显示名称 + 一条核心属性；
- 长期目标仍是真实建筑缩略图 / RenderTexture；
- Hover 使用轻提亮、约 1 px 位移和暖金细线；
- 内容按 6 个一组切换，始终保持稳定的 `3 × 2` 空间结构；
- 不依赖无限长列表来承载建筑数量；
- 切组采用约 160～200 ms 的轻量 Fade / 横向位移，不做大幅滑屏。

其他 Workspace 可以根据条目宽度调整列数和组容量，但仍应限制同时暴露的内容量。

### Content Pager

主内容分页使用 **底部居中的点 / 短横语言**：

```text
·   ·   ━   ·   ·
```

规则：

- 当前内容组使用暖金短横；
- 相邻内容组使用弱圆点；
- 不显示 `1 / 12`、数字页签、文字页码或左右箭头；
- 指示项本身可点击切换内容组；
- 当页数超过 5 组时，只显示当前组附近最多 5 个指示项，窗口随当前组移动；
- 玩家只需要知道当前在内容序列中的相对位置，不需要精确记住页号。

Primary Rail 和 Content Grid 使用不同方向的分页语言：

- 左侧一级分类：竖向刻度；
- 主内容：横向点 / 短横。

二者共享暖金 Active、弱灰 Inactive、短动效等视觉基因，但不会因为表现完全相同而混淆语义。

### Wheel Paging

鼠标滚轮 / 触控板滚动是 Workspace 分页的**快捷交互**，不是取消分页视觉的理由。

规则：

- 鼠标位于主 Content Grid 时，向下滚动切下一组 6 个内容，向上滚动切上一组；
- 鼠标位于 Primary Rail 时，向下滚动切下一组一级筛选项，向上滚动切上一组；
- Context Filter 和搜索输入区不使用滚轮触发组分页；
- 滚轮切组与点击竖向刻度 / 底部分页指示器是同一状态的不同输入方式；
- 必须使用滚动距离阈值和短暂输入锁，避免高精度滚轮或触控板一次手势连续翻多组；
- 当前 Web Prototype 使用累计阈值 + 约 220 ms 锁定，每次有效滚动只允许前进或后退一组；
- 在第一组或最后一组继续滚动时保持边界，不循环跳转；
- 滚轮分页不能自动改变 Primary Rail 选中的实际筛选项。

最终 Unity 实现可以映射为鼠标滚轮、肩键或其他导航输入，但应保持“整组切换”的交互语义。

### Workspace 信息层级

默认视觉权重：

`内容名称 > Primary Rail Active > 矩形预览 > Context Filter > 次级属性`

Primary Rail 负责稳定导航，Context Filter 保持轻量，内容名称承担最快识别；预览图辅助识别而不是主导整个 Card。

### 避免

- 每张条目完整 Card 边框；
- 大型方形 Icon Block；
- 多层标签；
- 长说明文本；
- 相同占位图反复出现；
- 把一级分类和二级筛选做成相同视觉权重；
- `全部建筑` 使用特殊大按钮或独立区域；
- 切换一级分类时重置顶部 Context Filter；
- 为了塞更多条目使用过度狭窄的 Card；
- 无限长滚动列表；
- 数字页码；
- 传统网页 Pager；
- 左侧和底部同时使用相同的普通圆点分页；
- 常驻完整搜索输入框；
- 一次滚轮动作连续翻过多个内容组。

## 11. Archive Item

Archive 的层级是：

`Game Group → Save Timeline → Save Preview`

### Game Group

Game Group 用城市截图、城市名、年代和最近保存时间建立识别。

### Save Timeline

同一 Game Group 内的 Save 按时间组织，支持自动存档与手动存档。

时间轴是信息结构，不应做成普通文件列表。

### Preview

Preview 只显示影响识别与决策的信息，例如：

- 城市截图；
- 城市名；
- 年代 / 季节；
- 保存时间；
- 游戏时长；
- 少量关键城市状态。

世界种子、版本等低频信息放到详情或 Tooltip。

## 12. Right Edge Flyout

Camera / Weather 使用同一个右侧 Flyout 视觉语言。

- 从屏幕右边缘出现；
- Header 简洁；
- 内部参数靠分组、留白和 Tone 组织；
- 不使用英文眉题和长说明；
- 不创建无意义 Summary Card。

## 13. Pause Menu

Pause Menu 是轻量全局命令列表。

只保留：

- 继续游戏；
- 保存游戏；
- 游戏设置；
- 返回主菜单。

不要增加：

- 01 / 02 / 03 / 04 编号；
- 右箭头；
- 每项副说明；
- 无意义品牌尾标。

## 14. 动效

动效用于强化状态变化，不用于展示技术效果。

推荐：

- Hover：约 100 ms；
- Tab Active：约 120～160 ms；
- Workspace / Flyout：约 160～220 ms；
- 参数模式切换：Fade + 2～5 px 位移；
- Workspace 分组翻页：约 160～200 ms 的 Fade + 轻横移；
- 搜索展开：约 160～180 ms；
- Archive Preview：轻量 Cross Fade。

避免大幅弹跳、Scale 过冲、强 Glow 和长时间缓动。
