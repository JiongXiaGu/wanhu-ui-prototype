# 存档界面规范

《万户天工》的存档界面最终用于 Unity UI Toolkit。Web Prototype 用于验证信息架构、美术、交互节奏和状态反馈。

## 1. 核心信息架构

读档不是“所有存档的单层列表”。正式层级是：

```text
游戏组（一场游戏）
→ 组内存档（该局游戏的不同保存点）
→ 对指定存档执行读取 / 重命名 / 删除
```

游戏组是高层对象，单个存档是组内对象。两类对象的操作不能混在同一个底部按钮区。

## 2. 全屏布局

当前正式结构：

```text
Header
├ 页面标题

Main
├ 左：游戏组列表
└ 右：当前游戏组的存档 Card 列表

Footer Action Bar
├ 左：游戏组管理动作
└ 右：返回
```

不再使用旧的固定第三栏 Preview / Summary。

原因：

- 固定 Preview 会重复当前选中 Card 已经表达的信息；
- 三栏同时存在会让存档页更像文件管理器；
- 单个存档自己的截图、名称、时间和操作已经足够支持选择。

## 3. 游戏组列表

左侧每个游戏组使用紧凑横向短卡：

```text
[城市截图]  城市名
            年代 · 季节
            游戏时长 · 最近保存
```

可弱化显示该组的存档数量。

Selected：

- 左侧 2 px 暖金细线；
- 主标题提亮；
- 极弱暖金 Tone；
- 不使用粗金边和大面积金色背景。

游戏组 Card 本身不常驻重命名 / 删除按钮，避免左栏负担过重。

## 4. 游戏组管理

游戏组属于页面级高层对象，因此管理动作固定放到底部左侧：

```text
[重命名存档组] [删除存档组]                         [返回]
```

规则：

- 重命名存档组：进入当前组名称的内联编辑；
- 删除存档组：属于高影响操作，必须二次确认；
- 删除按钮默认不做大红块，Hover / Confirm 时才使用克制危险色；
- 返回固定在 Footer 最右侧；
- 不把游戏组管理动作塞进每一个游戏组 Card。

## 5. 单个存档 Card

单个存档使用横向内容 Card：

```text
[矩形截图]  存档名称
            游戏内时间 / 天气
            保存日期 · 保存时间                     [操作]
```

文字负责主要识别，截图用于辅助识别。

Card 不常驻说明性长文案。

## 6. 单个存档操作

单个存档的操作直接属于 Card 本身，不放到底部动作栏。

当前三个核心动作全部使用图标：

- Pencil：重命名；
- Folder / Load：读取；
- Trash：删除。

规则：

- 默认不把三个图标长期铺满整个列表；
- Hover / Focus / Selected 当前 Card 时显示操作区；
- 读取是当前 Card 的 Primary Action，使用暖金强调；
- 重命名是中性动作；
- 删除默认中性，仅 Hover / Confirm 时出现危险色；
- Icon-only Action 必须有 Tooltip / Accessible Label；
- 双击 Card 可以作为鼠标读取快捷方式，但不能替代显式读取图标。

## 7. 存档重命名

重命名使用 Card 内联编辑，不打开大型 Dialog。

```text
存档名称
↓
[ 可编辑名称________________ ]
```

- Enter：提交；
- Esc：取消；
- 失焦：提交当前有效名称；
- 不需要额外“确认重命名”弹窗。

## 8. 删除单个存档

删除图标点击后，在当前 Card 附近出现轻量局部确认：

```text
删除这个存档？   [取消] [确认删除]
```

不要让删除一个普通存档触发和“删除整个游戏组”同等重量的大型页面弹窗。

## 9. 读取流程

标准鼠标流程：

```text
选择游戏组
→ 找到目标存档
→ Hover / Focus Card
→ 点击读取图标
```

读取操作不放在 Footer。

这样可以避免：

```text
选中存档
→ 视线移动到屏幕右下角
→ 再点击读取
```

操作与对象保持空间邻近。

## 10. Fullscreen Action Bar 统一规则

全屏页面统一：

```text
左侧 = 当前对象 / 页面管理动作
右侧 = 返回 / 流程导航动作
```

当前示例：

### Settings

```text
[恢复当前分类默认值]                                  [返回]
```

### Load Archive

```text
[重命名存档组] [删除存档组]                           [返回]
```

不要为了左右视觉对称强行填充无意义按钮。

## 11. Unity UI Toolkit 落地

推荐结构：

```text
ArchiveRoot
├ Header
├ Content
│  ├ GameGroupList
│  └ SaveList
│     └ SaveCard Pool / ListView
└ FooterActionBar
```

`SaveCard`：

```text
SaveCard
├ Thumbnail
├ Copy
│  ├ Name / RenameField
│  ├ WorldTime
│  └ SavedAt
└ Actions
   ├ RenameButton
   ├ LoadButton
   └ DeleteButton
```

大量存档时优先考虑 UI Toolkit `ListView` 虚拟化；存档数量较少时也可以使用可复用 VisualElement Pool。

## 12. 禁止回退

不要恢复：

- 单层“所有存档”列表；
- 固定第三栏 Preview / Summary；
- 把读取放到底部 Footer；
- 把单个存档删除放到底部 Footer；
- 每个游戏组 Card 常驻一排管理按钮；
- 单个存档的重命名 / 读取 / 删除使用长文字按钮占据 Card 大量空间；
- 大红色常驻删除按钮；
- 过多常驻说明性小字。
