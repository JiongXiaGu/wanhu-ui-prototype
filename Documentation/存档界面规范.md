# 存档界面规范

《万户天工》的存档界面最终用于 Unity UI Toolkit。Web Prototype 用于验证信息架构、美术、交互节奏、滚动手感和状态反馈。

## 1. 核心信息架构

读档不是“所有存档的单层列表”。正式层级是：

```text
游戏组（一场游戏）
→ 组内存档（该局游戏的不同保存点）
→ 对指定存档执行读取 / 重命名 / 删除
```

游戏组是高层对象，单个存档是组内对象。两类对象的管理操作必须分开。

## 2. 全屏布局

正式结构保持全屏 Global Blocking Space，不缩成浮窗。Archive 不拥有场景图片，Main Menu / Gameplay 当前世界由父级提供，Archive 只负责 Smoked Graphite Global Material：

```text
Parent World / Main Menu
↓ Shared Global Dim / Blur
Header
├ 页面标题

Main
├ 左：游戏组列表
└ 右：存档类型筛选 + 当前游戏组的存档 Card 列表

Footer Action Bar
├ 左：游戏组管理动作
└ 右：返回
```

不使用旧的固定第三栏 Preview / Summary。

存档信息直接存在于游戏组 Card 和存档 Card，不额外增加重复详情总览区。

## 3. 游戏组 Card

游戏组只回答：“这是哪一场游戏、玩了多久、最后一次何时保存、最新存档是什么版本”。

正式字段只有：

```text
[城市截图]  游戏组名称
            46h 18m · 最后保存 2026-09-15 16:58
            最新版本 v0.8.4
```

游戏组 Card **不显示**：

- 游戏内年份；
- 月份 / 日期；
- 季节；
- 天气；
- “含旧版存档”；
- “含不兼容存档”；
- 单个存档的兼容状态摘要。

兼容信息属于具体存档，不应在游戏组 Card 上做聚合警告。

Selected：

- 左侧 2 px 暖金细线；
- 主标题提亮；
- 极弱暖金 Tone；
- 不使用粗金边和大面积金色背景。

游戏组 Card 不常驻重命名 / 删除按钮。

左侧“游戏组”栏不额外显示“12 组”等总数统计；列表本身已经足够表达数量，避免无决策价值的辅助数字。

## 4. 游戏组管理

游戏组属于页面级高层对象，因此管理动作固定放到底部左侧：

```text
[重命名存档组] [删除存档组]                         [返回]
```

规则：

- 重命名存档组：使用共享 InputDialog；
- 删除存档组：高影响操作，必须二次确认；
- 删除按钮默认不做大红块，Hover / Confirm 时才使用克制危险色；
- 返回固定在 Footer 最右侧；
- 不把游戏组管理动作塞进每一个游戏组 Card。

## 5. 存档类型与默认命名

正式存档类型只有三种：

- 自动存档；
- 手动存档；
- 快速存档。

取消“玩家存档”这一名称。

未由玩家自定义名称时使用稳定自动命名：

```text
自动存档.001
手动存档.025
快速存档.008
```

类型和名称是两个不同维度：玩家可以重命名存档，但 Auto / Manual / Quick 类型不因此改变。

## 6. 顶部筛选

右侧存档列表顶部不显示当前游戏组的重复信息，也不提供搜索和手动排序。

顶部只保留：

```text
全部   自动存档   手动存档   快速存档                 隐藏过时存档 [Toggle]
```

规则：

- `全部` 默认选中；
- 类型筛选互斥；
- `隐藏过时存档` 默认关闭；
- 打开后隐藏过时和不兼容存档；
- 不增加搜索框；
- 不增加排序下拉菜单；
- 默认数据顺序就是最终展示顺序：**最新存档在最上方，越旧越靠下**。

## 7. 单个存档 Card

存档 Card 使用横向内容布局：

```text
[矩形截图]  自动存档.001                     自动存档  v0.8.4
            游戏时间   第12年 8月17日
            保存时间   2026-09-15 16:58

                                               [重命名][读取][删除]
```

如果存档过时：

```text
过时   自动存档   v0.8.3
```

如果不兼容：

```text
不兼容   快速存档   v0.7.8
```

Card 不显示天气，也不使用“今天 / 昨天 + 小时”这种模糊现实时间表达。

必须同时显示：

- 存档名称；
- 存档类型；
- 游戏版本；
- 游戏内年月日；
- 现实保存年月日 + 小时分钟；
- 必要时的过时 / 不兼容提示。

## 8. 状态表达：文字优先

存档类型和兼容状态不使用抽象状态图标。

原因：

- 循环箭头、闪电、书签等图标对第一次进入读档页的玩家不够直观；
- 类型本身是重要决策信息，应直接可读；
- 版本与兼容状态也应与类型并排形成稳定文字状态区。

右上状态区使用文字：

```text
[兼容提示（按需）] [自动 / 手动 / 快速存档] [v0.8.4]
```

兼容提示规则：

### 当前版本

```text
自动存档   v0.8.4
```

- 正常读取；
- 不额外显示“当前版本”标签，避免冗余。

### 过时但兼容

```text
过时   手动存档   v0.8.3
```

- 可以读取；
- 使用低饱和琥珀 / 暖灰提醒；
- 不把整张 Card 染黄。

### 不兼容

```text
不兼容   快速存档   v0.7.8
```

- 读取按钮真正 Disabled；
- 重命名 / 删除仍可操作；
- 状态标签使用克制暖红；
- 可以轻微降低截图饱和度；
- 不使用整张高饱和红色警告。

兼容判断最终必须由正式 Save Migration / Version Compatibility 规则驱动，UI 不自行推断。

## 9. 时间信息

存档 Card 区分两类时间：

### 游戏时间

显示游戏世界内部的年月日，例如：

```text
第12年 8月17日
```

不在读档 Card 中显示天气。

### 保存时间

显示现实世界完整时间：

```text
2026-09-15 16:58
```

不要仅显示 `今天 16:58` 或 `昨天 22:41`，避免跨天、长期存档和截图对比时产生歧义。

## 10. 单个存档操作

单个存档的操作属于 Card 本身，不放到底部动作栏。

三个核心动作继续使用图标：

- Pencil：重命名；
- Folder / Load：读取；
- Trash：删除。

规则：

- Hover / Focus / Selected 当前 Card 时显示操作区；
- 读取是 Card Primary Action，使用暖金强调；
- 重命名是中性动作；
- 删除默认中性，仅 Hover / Confirm 时出现危险色；
- Icon-only Action 必须有 Tooltip / Accessible Label；
- 双击 Card 可以作为鼠标读取快捷方式，但不能替代显式读取图标；
- 不兼容存档的读取按钮必须真正 Disabled。

注意：**操作按钮可以使用图标，但存档类型 / 兼容状态不使用抽象图标。**

## 11. 存档重命名与删除

重命名使用共享 InputDialog；删除单个存档与删除整个游戏组都使用共享 ConfirmDialog。

原因：

- 不在每张 Card 内维护独立编辑 / 确认状态机；
- Esc / Enter / Focus 行为与 Save、Settings、Pause 保持一致；
- Danger 语义只在真正的删除确认 Dialog 中出现；
- 最终 Unity 可以统一映射到 Global Dialog Host。

## 12. 滚动与大量数据

存档是时间序列，使用纵向滚动，不做分页浏览。

左侧游戏组与右侧存档列表分别独立滚动：

- 左侧只滚游戏组；
- 右侧只滚存档；
- 顶部类型筛选固定；
- Footer 固定。

Prototype 必须故意提供大量测试数据。

当前压力测试基准：

- 至少 10 个游戏组；
- 当前游戏组至少 20 个存档；
- 必须同时包含 Auto / Manual / Quick；
- 必须同时包含当前版 / 过时 / 不兼容状态。

最终 Unity 大量列表优先使用 `ListView` 虚拟化或固定 VisualElement Pool。

## 13. 读取流程

标准鼠标流程：

```text
选择游戏组
→ （可选）按存档类型筛选
→ 找到目标存档
→ Hover / Focus Card
→ 点击读取图标
```

读取操作不放在 Footer。

## 14. Fullscreen Action Bar

统一规则：

```text
左侧 = 当前对象 / 页面管理动作
右侧 = 返回 / 流程导航动作
```

Settings：

```text
[恢复当前分类默认值]                                  [返回]
```

Load Archive：

```text
[重命名存档组] [删除存档组]                           [返回]
```

## 15. Unity UI Toolkit 落地

推荐结构：

```text
ArchiveRoot
├ Header
├ Content
│  ├ GameGroupListView
│  └ SaveBrowser
│     ├ SaveTypeFilterBar
│     │  ├ All / Auto / Manual / Quick
│     │  └ HideOutdatedToggle
│     └ SaveListView
│        └ SaveCard Pool
└ FooterActionBar
```

`GameGroupCard`：

```text
GameGroupCard
├ Thumbnail
└ Copy
   ├ GroupName
   ├ PlayTime + LastSavedAt
   └ LatestVersion
```

`SaveCard`：

```text
SaveCard
├ Thumbnail
├ Copy
│  ├ Name / RenameField
│  ├ GameDate
│  └ RealSavedAt
├ Status
│  ├ CompatibilityBadge（按需）
│  ├ SaveTypeText
│  └ Version
└ Actions
   ├ RenameButton
   ├ LoadButton
   └ DeleteButton
```

## 16. 禁止回退

不要恢复：

- 单层“所有存档”列表；
- 固定第三栏 Preview / Summary；
- 顶部重复显示当前游戏组的大块详情；
- 存档搜索框；
- 手动排序控件；
- 游戏组 Card 的年份 / 季节 / 天气；
- 游戏组 Card 的“含旧版 / 含不兼容”聚合提示；
- `玩家存档` 命名；
- 存档类型抽象图标；
- 存档 Card 天气信息；
- 模糊的“今天 / 昨天”现实保存时间；
- 把读取或单档删除放到底部 Footer；
- 每个游戏组 Card 常驻管理按钮；
- 隐藏游戏版本或兼容状态；
- 让不兼容存档看起来仍可正常读取；
- 大红色常驻删除按钮；
- 过多常驻说明性小字。


## 15. 2026-09-18 Archive Visual System Consolidation

- Load / Save 保持全屏 Global Space，不改现有信息架构；
- Archive 不再硬编码 gameplay city 背景图，必须继承父级世界 / 主菜单；
- Root Material 使用与 Settings 同一家族的 Smoked Graphite Global Surface；
- Header 使用普通 UI Typography，不再使用 Serif 海报标题；
- 游戏组总数不常驻显示；
- SaveEntryCard 保持 Load / Save 共享结构，默认减少完整 Card Box 感；
- Auto / Manual / Quick 只作为中性 metadata，不再用熟铜区分类型；
- 熟铜保留给 Selected / Active Filter / Load Primary / Toggle On；
- “过时”使用低饱和暖色，“不兼容”使用克制 Cinnabar；
- “隐藏过时存档”正式使用共享 ToggleSwitch，删除 Compatibility Bridge；
- `archive-info-refine.css` 的正式值折回 `archive-panel.css`，不再维护第二层 Archive Override。
