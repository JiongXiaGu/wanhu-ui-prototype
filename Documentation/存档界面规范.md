# 存档界面规范

《万户天工》的存档界面最终用于 Unity UI Toolkit。Web Prototype 用于验证信息架构、美术、交互节奏、滚动手感和状态反馈。

## 1. 核心信息架构

读档不是“所有存档的单层列表”。正式层级是：

```text
游戏组（一场游戏）
→ 组内存档（该局游戏的不同保存点）
→ 对指定存档执行读取 / 重命名 / 删除
```

游戏组是高层对象，单个存档是组内对象。两类对象的管理操作必须分开。

## 2. 全屏布局

正式结构：

```text
Header
├ 页面标题

Main
├ 左：游戏组列表
└ 右：存档类型筛选 + 当前游戏组的存档 Card 列表

Footer Action Bar
├ 左：游戏组管理动作
└ 右：返回
```

不使用旧的固定第三栏 Preview / Summary。

存档信息应直接存在于游戏组 Card 和存档 Card，不额外增加重复的详情总览区。

## 3. 游戏组列表

左侧每个游戏组使用紧凑横向短卡：

```text
[城市截图]  游戏组名称                  存档数量
            年代 · 季节
            v0.8.4   含旧版存档
            游戏时长 · 最近保存
```

必须能从游戏组 Card 直接识别：

- 游戏组名称；
- 年代 / 季节；
- 存档数量；
- 最新存档使用的版本号；
- 是否包含旧版 / 不兼容存档；
- 游戏时长 / 最近保存时间。

Selected：

- 左侧 2 px 暖金细线；
- 主标题提亮；
- 极弱暖金 Tone；
- 不使用粗金边和大面积金色背景。

游戏组 Card 不常驻重命名 / 删除按钮，避免左栏负担过重。

## 4. 游戏组管理

游戏组属于页面级高层对象，因此管理动作固定放到底部左侧：

```text
[重命名存档组] [删除存档组]                         [返回]
```

规则：

- 重命名存档组：进入当前组名称的内联编辑；
- 删除存档组：属于高影响操作，必须二次确认；
- 删除按钮默认不做大红块，Hover / Confirm 时才使用克制危险色；
- 返回固定在 Footer 最右侧；
- 不把游戏组管理动作塞进每一个游戏组 Card。

## 5. 存档类型

正式存档类型共三种：

- 自动存档；
- 快速存档；
- 玩家存档（手动存档）。

未由玩家自定义名称时使用稳定自动命名：

```text
自动存档.001
快速存档.008
玩家存档.025
```

类型与名称是两个不同维度：玩家可以重命名一个存档，但它的 Auto / Quick / Manual 类型不会因此改变。

## 6. 顶部存档类型筛选

右侧存档列表顶部不显示当前游戏组的重复信息，也不提供搜索和手动排序。

顶部只保留：

```text
全部   自动存档   快速存档   玩家存档                 隐藏过时存档 [Toggle]
```

规则：

- `全部` 默认选中；
- 类型筛选互斥；
- `隐藏过时存档` 默认关闭；
- 打开后隐藏旧版和不兼容存档；
- 不增加搜索框；
- 不增加“排序”下拉菜单；
- 默认数据顺序就是最终展示顺序：**最新存档在最上方，越旧越靠下**。

存档顺序由真实保存时间决定，不允许为了 UI 浏览临时改变语义顺序。

## 7. 单个存档 Card

单个存档使用横向内容 Card：

```text
[矩形截图]  自动存档.001                      [类型图标] v0.8.4 [状态]
            第十二年 · 秋 · 晴
            今天 · 16:58

                                                [重命名][读取][删除]
```

文字负责主要识别，截图用于辅助识别。

Card 不常驻说明性长文案。

### 右上状态区

Card 右上角是稳定的状态区，负责显示：

- 存档类型图标；
- 版本号；
- 兼容性状态。

类型图标建议：

- 自动存档：循环 / 自动保存语义图标；
- 快速存档：闪电；
- 玩家存档：书签 / 文件语义图标。

自动存档图标不再挤在名称旁边，应放在右上状态区。

## 8. 存档版本与兼容状态

每个游戏组和每个存档都必须可识别版本信息。

当前视觉原型区分三种状态：

### 当前版本

```text
v0.8.4
```

- 正常读取；
- 不额外增加醒目标记。

### 旧版但兼容

```text
v0.8.3   旧版
```

- 可以读取；
- 使用低饱和琥珀 / 暖灰提醒；
- 不把整张 Card 染黄。

### 不兼容

```text
v0.7.8   不兼容
```

- 读取按钮不可用；
- 重命名 / 删除仍可操作；
- 状态标签使用克制暖红；
- Card 可以轻微降低截图饱和度和内容亮度；
- 不使用整张高饱和红色警告。

兼容判断最终必须由正式 Save Migration / Version Compatibility 规则驱动，不能在 UI 中自行猜测。

## 9. 单个存档操作

单个存档的操作直接属于 Card 本身，不放到底部动作栏。

三个核心动作全部使用图标：

- Pencil：重命名；
- Folder / Load：读取；
- Trash：删除。

规则：

- Hover / Focus / Selected 当前 Card 时显示操作区；
- 读取是当前 Card 的 Primary Action，使用暖金强调；
- 重命名是中性动作；
- 删除默认中性，仅 Hover / Confirm 时出现危险色；
- Icon-only Action 必须有 Tooltip / Accessible Label；
- 双击 Card 可以作为鼠标读取快捷方式，但不能替代显式读取图标；
- 不兼容存档的读取按钮必须真正 Disabled，而不是只变灰。

## 10. 存档重命名

重命名使用 Card 内联编辑，不打开大型 Dialog。

```text
存档名称
↓
[ 可编辑名称________________ ]
```

- Enter：提交；
- Esc：取消；
- 失焦：提交当前有效名称；
- 不需要额外“确认重命名”弹窗。

## 11. 删除单个存档

删除图标点击后，在当前 Card 附近出现轻量局部确认：

```text
删除这个存档？   [取消] [确认删除]
```

不要让删除一个普通存档触发和“删除整个游戏组”同等重量的大型页面弹窗。

## 12. 滚动与大量数据

读档页与 Building Workspace 不同：存档天然是时间序列，因此使用纵向滚动，不做分页浏览。

左侧游戏组列表与右侧存档列表分别独立滚动：

- 左侧只滚游戏组；
- 右侧只滚存档；
- 顶部类型筛选固定，不随存档列表滚走；
- Footer 固定。

Prototype 必须故意提供大量测试数据，不能只用 2～3 个样本假装滚动逻辑已经验证。

当前压力测试基准：

- 至少 10 个游戏组；
- 当前游戏组至少 20 个存档；
- 必须同时包含 Auto / Quick / Manual；
- 必须同时包含当前版 / 旧版 / 不兼容状态。

最终 Unity 中大量项目优先使用 `ListView` 虚拟化或固定 VisualElement Pool。

## 13. 读取流程

标准鼠标流程：

```text
选择游戏组
→ （可选）按存档类型筛选
→ 找到目标存档
→ Hover / Focus Card
→ 点击读取图标
```

读取操作不放在 Footer。

## 14. Fullscreen Action Bar 统一规则

全屏页面统一：

```text
左侧 = 当前对象 / 页面管理动作
右侧 = 返回 / 流程导航动作
```

### Settings

```text
[恢复当前分类默认值]                                  [返回]
```

### Load Archive

```text
[重命名存档组] [删除存档组]                           [返回]
```

不要为了左右视觉对称强行填充无意义按钮。

## 15. Unity UI Toolkit 落地

推荐结构：

```text
ArchiveRoot
├ Header
├ Content
│  ├ GameGroupListView
│  └ SaveBrowser
│     ├ SaveTypeFilterBar
│     │  ├ All / Auto / Quick / Manual
│     │  └ HideOutdatedToggle
│     └ SaveListView
│        └ SaveCard Pool
└ FooterActionBar
```

`SaveCard`：

```text
SaveCard
├ Thumbnail
├ Copy
│  ├ Name / RenameField
│  ├ WorldTime
│  └ SavedAt
├ Status
│  ├ SaveTypeIcon
│  ├ Version
│  └ CompatibilityBadge
└ Actions
   ├ RenameButton
   ├ LoadButton
   └ DeleteButton
```

## 16. 禁止回退

不要恢复：

- 单层“所有存档”列表；
- 固定第三栏 Preview / Summary；
- 顶部重复显示当前游戏组的大块详情；
- 存档搜索框；
- 手动排序控件；
- 把读取放到底部 Footer；
- 把单个存档删除放到底部 Footer；
- 每个游戏组 Card 常驻一排管理按钮；
- 单个存档操作使用长文字按钮占据 Card 大量空间；
- 自动存档类型标记挤在名称旁边；
- 隐藏版本号或兼容性状态；
- 让不兼容存档看起来仍可正常读取；
- 大红色常驻删除按钮；
- 过多常驻说明性小字。
