# 保存界面规范

## 1. 页面职责

保存游戏与读取游戏是两个独立流程，不使用同一个页面状态模型。

- 读取游戏：游戏组 → 具体存档 → 读取。
- 保存游戏：当前游戏已经确定 → 新建手动存档或覆盖已有手动存档。

因此正式结构应分别实现：

- `LoadGameSpace`
- `SaveGameSpace`

两者可以共享缩略图、图标按钮、确认提示、底部动作栏等基础组件，但不得共享页面级流程状态。

## 2. 当前游戏与存档组名称

进入保存游戏页面时，当前游戏已经唯一确定，不显示游戏组列表，也不允许切换到其它游戏组。

顶部仅保留当前游戏的最低必要信息：

- 当前存档组名称
- 当前游戏版本
- 总游玩时长

不显示天气、人口、资源、世界种子等与保存动作无直接关系的信息。

当前游戏所属存档组名称允许修改。修改入口固定放在 Footer 左侧，点击后顶部名称原地进入编辑状态：

- Enter / 失焦：提交名称；
- Esc：取消本次编辑。

## 3. 保存页只管理手动存档

保存页只显示和管理手动存档。

自动存档与快速存档由系统机制管理，可以在读取游戏页面中浏览，但不作为玩家手动覆盖目标出现在保存页面。

默认手动存档名称采用：

`手动存档.001`

玩家可自行重命名；未修改名称时继续使用自动编号名称。

## 4. 新建存档

`新建存档` 是保存页主体顶部的固定入口，始终容易访问。

操作流程：

1. 点击新建存档。
2. 进入内联名称编辑状态。
3. 默认填入下一可用的 `手动存档.xxx` 名称。
4. Enter 或“保存”创建。
5. Esc 或“取消”退出创建状态。
6. 新建成功后，新存档按最后保存时间排序到列表最顶部。

## 5. 手动存档 Card

每个手动存档 Card 常驻显示：

- 矩形城市截图
- 存档名称
- 游戏内年月日
- 现实保存时间（年月日 + 小时分钟）
- 存档版本号

旧版本手动存档可显示低强调的 `旧存档` 状态，但不能因为版本较旧而禁止覆盖。

## 6. Card 操作

操作与具体存档对象绑定，不占用全屏 Footer。

Card 操作统一使用图标：

- 重命名
- 覆盖
- 删除

默认低存在感；Hover / Focus / Selected 时显示。

### 重命名

直接在 Card 中内联编辑名称。

- Enter：提交
- Esc：取消

### 覆盖

覆盖属于不可逆操作，需要一次局部确认。

确认后：

- 使用当前游戏状态替换目标存档；
- 游戏日期更新为当前游戏日期；
- 保存时间更新为当前现实时间；
- 版本更新为当前游戏版本；
- 该存档因保存时间最新而移动到列表顶部。

旧版本手动存档允许被当前版本覆盖。

### 删除

删除单个存档需要局部二次确认。

## 7. 排序与滚动

不提供搜索和排序控件。

存档列表固定按现实保存时间倒序排列，最新保存始终在顶部。

保存页使用纵向滚动列表。原型应保留足够多的手动存档测试数据，用于验证滚动条、Hover、选中态与长名称表现。

## 8. Footer

保存页 Footer 使用统一 Fullscreen Action Bar：

- 左侧：`更改存档组名称`
- 中间：留空
- 右侧：`返回`

不放新建、覆盖、删除或单个存档重命名等对象级操作。

Esc 与“返回”语义一致；但若当前正在修改存档组名称、重命名单个存档、新建、覆盖确认或删除确认，Esc 优先关闭当前子状态，不直接退出页面。

## 9. Unity UI Toolkit 落地

正式 Unity 版本建议独立实现 `SaveGameWorkspace.uxml`。

页面主体可映射为：

- Header
- CurrentGameSummary
- CreateSaveEntry
- ScrollView / ListView of ManualSaveCard
- FullscreenActionBar

单个 Card 可映射为：

- Preview Image / RenderTexture
- SaveName Label / TextField
- GameDate Label
- SavedAt Label
- Version Label
- Rename IconButton
- Overwrite IconButton
- Delete IconButton
- LocalConfirmLayer

网页原型只用于视觉、密度、状态和交互手感验证，最终运行时逻辑以 Unity UI Toolkit + 游戏存档系统为准。
