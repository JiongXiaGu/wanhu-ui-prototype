# 保存界面规范

## 1. 页面职责

保存游戏与读取游戏是两个独立流程，不共享页面级状态模型。

- 读取游戏：游戏组 → 类型筛选 → 具体存档 → 读取。
- 保存游戏：当前游戏已经确定 → 快速保存 / 命名保存 / 覆盖已有手动存档。

正式结构分别实现：

- `LoadGameSpace`
- `SaveGameSpace`

两者共享 `SaveEntryCard` 等视觉组件，但不得重新合并成 `mode="load" | "save"` 的单一页面流程。

## 2. 当前游戏与存档组名称

进入保存游戏页面时，当前游戏已经唯一确定，不显示游戏组列表，也不允许切换到其它游戏组。

顶部仅保留：

- 当前存档组名称
- 当前游戏版本
- 总游玩时长

不显示天气、人口、资源、世界种子等与保存动作无直接关系的信息。

Footer 左侧提供 `更改存档组名称`。点击后顶部名称原地进入编辑：

- Enter / 失焦：提交；
- Esc：取消。

## 3. 类型筛选

保存页与读取页保持一致的浏览语言，顶部提供：

- 全部
- 自动存档
- 手动存档
- 快速存档
- `隐藏过时存档` Toggle，默认关闭

不提供搜索和手动排序。所有类型固定按现实保存时间倒序排列，最新存档在顶部。

## 4. Footer 保存动作

保存操作集中在底部 Fullscreen Action Bar，而不是页面顶部。

- 左侧：`更改存档组名称`
- 中间：`快速保存`、`保存存档`
- 右侧：`返回`

### 快速保存

点击后立即创建新的快速存档，不打开弹窗，不要求玩家输入名称。

默认名称：

`快速存档.xxx`

创建成功后：

- 使用当前游戏日期；
- 使用当前现实保存时间；
- 使用当前游戏版本；
- 新存档进入列表顶部；
- 显示短时 Toast，例如 `已创建 快速存档.009`。

原型中快速存档最多保留 10 个；超过上限时淘汰最旧的快速存档。

### 保存存档

点击后打开轻量命名弹窗。

弹窗只包含：

- 标题 `保存存档`
- 存档名称输入框
- `取消`
- `保存`

默认填入下一可用名称：

`手动存档.xxx`

玩家可以直接确认默认名称，也可以改为自定义名称。

- Enter / 保存：创建；
- Esc / 取消：关闭弹窗；
- 创建成功后进入列表顶部并显示短时 Toast。

页面主体不再存在 `+ 新建存档` 或顶部内联创建入口。

## 5. 共享 SaveEntryCard

读取页与保存页必须复用同一个 `SaveEntryCard` 视觉组件。

共享内容：

- 矩形截图
- 存档名称
- 游戏内年月日
- 现实保存时间（年月日 + 小时分钟）
- 存档类型标签
- 兼容状态
- 游戏版本
- Hover / Focus / Selected 视觉
- Action Slot
- Local Confirmation Slot

页面通过 Action Slot 注入不同业务动作，Card 自身不得决定读取或保存流程。

## 6. 保存页 Card 权限

### 手动存档

允许：

- 重命名
- 覆盖
- 删除

重命名仍使用 Card 内联编辑。

覆盖属于不可逆操作，需要局部确认。确认后：

- 使用当前游戏状态替换目标存档；
- 游戏日期、现实保存时间更新；
- 版本更新为当前游戏版本；
- 兼容状态恢复为当前版本；
- 因保存时间最新而移动到列表顶部。

旧版本甚至不兼容的手动存档仍允许被当前游戏状态覆盖，因为这是替换目标文件而不是读取旧数据。

### 快速存档

快速存档由 Footer 的 `快速保存` 动作创建和轮换。

Card 不提供重命名或覆盖；允许删除。

### 自动存档

自动存档由系统生成。

Card 不提供重命名或覆盖；允许删除。

## 7. 兼容状态

保存页继续展示版本和兼容状态，使玩家知道现有存档的来源版本。

- 当前版本：正常显示版本号；
- 过时：显示 `过时`；
- 不兼容：显示 `不兼容`。

`隐藏过时存档` 打开后隐藏 `过时` 与 `不兼容` 项。

保存页中的兼容状态主要用于识别，不限制删除；手动存档覆盖行为按第 6 节执行。

## 8. 滚动与数据密度

使用纵向滚动列表，不做分页。

网页原型必须同时保留自动、手动、快速三类测试数据，以及当前版本 / 过时 / 不兼容状态，用于验证：

- 类型筛选；
- 隐藏过时；
- 滚动条；
- Hover / Selected；
- 不同操作数量下的 Card 布局。

## 9. Esc 优先级

正常状态：Esc = 返回暂停菜单。

如果当前存在子状态，Esc 只关闭最上层子状态，不退出保存页：

- 修改存档组名称；
- 单个手动存档重命名；
- 保存存档命名弹窗；
- 覆盖确认；
- 删除确认。

## 10. Unity UI Toolkit 落地

正式 Unity 版本建议独立实现 `SaveGameWorkspace.uxml` 与 `LoadGameWorkspace.uxml`，并共享 `SaveEntryCard.uxml` / 对应 VisualElement 组件。

保存页可映射为：

- Header
- CurrentGameSummary
- SaveTypeFilterBar
- ListView / ScrollView of SaveEntryCard
- FullscreenActionBar
- SaveNameDialog
- ToastLayer

`SaveEntryCard` 可映射为：

- Preview Image / RenderTexture
- SaveName Label / TextField
- GameDate Label
- SavedAt Label
- SaveKind Badge
- Compatibility Badge
- Version Label
- ActionSlot
- LocalConfirmLayer

网页原型用于验证视觉、密度、状态和交互手感；正式运行时存档创建、自动淘汰、兼容性与文件写入由 Unity 存档系统负责。
