# 弹窗系统规范

## 1. 定位

Dialog / Modal 是覆盖当前空间的 **Elevated Blocking Surface**。

它用于确认、输入、精确数值、按键捕获和安全显示回滚。它不是另一个全屏页面，也不是 Gameplay Glass。所有页面只提交业务请求，统一由全局 `DialogProvider → DialogHost → DialogFrame` 渲染。

最终 Unity UI Toolkit 必须保持同样职责边界：全局 Modal Layer 负责弹窗，业务页面不得各自维护私有弹窗皮肤。

## 2. Unity 约束与核心材质规则

正式约束：

> **Dialog 不依赖实时 Blur。**

原因是 Unity UI Toolkit 中，前景 Dialog 无法可靠地再次模糊已经绘制完成的背景 UI。Web 原型如果依赖 `backdrop-filter` 才成立，迁移后会产生明显视觉偏差。

因此：

- `.ui-modal-backdrop` 只负责半透明 Dim，不使用 Blur；
- `.ui-dialog` 本体使用自稳定的半透明 Smoked Graphite；
- Dialog 自身通过稳定 Tint / Edge / Shadow 保证可读性；
- 不允许依赖后方 UI 被模糊后才能阅读；
- 不建立 Dialog 专属绿色、蓝色或黑色 Theme；
- Aged Brass 只用于 Focus / Primary / Listening / Current；
- Cinnabar 只用于真正不可逆的 Danger Action。

当前正式所有权：

```text
wanhu-theme-tokens.css
        ↓
wanhu-surface-system.css
        ↓
dialog.css
        ↓
DialogSystem.tsx
```

- Theme Token：Dialog Dim / Surface / Edge / Shadow；
- Surface System：Dialog Material；
- `ui-control-system.css`：Text Input 等共享基础 Control Material；
- `dialog.css`：Geometry / Typography / Dialog-specific Control Layout，不重新绘制共享 Text Input；
- `DialogSystem.tsx`：状态、键盘行为、校验与业务回调；Text / Number 输入直接消费 `Controls.tsx::TextInput`。

## 3. 统一结构

```text
.ui-modal-layer
├ .ui-modal-backdrop
└ .ui-dialog
   ├ .ui-dialog__tone-line
   ├ .ui-dialog__header
   │  ├ Title
   │  └ Optional Message
   ├ .ui-dialog__body
   │  └ Variant Content
   └ .ui-dialog__actions
      ├ Secondary
      └ Primary / Danger
```

所有阻断式弹窗必须使用同一个 `DialogFrame`。不得复制第二套 Shell。

## 4. 视觉基线

1080p 基线：

- Dialog 宽度约 `560px`；
- Radius：`12px`；
- 输入 / Button Radius：`10px`；
- Surface：中性 Smoked Graphite，半透明但可独立阅读；
- Dialog 本体不使用可见颗粒噪点，避免“磨砂 / 脏玻璃”观感；
- Header 与 Body 形成轻微层级，类似 Workspace 的结构感，但更克制；
- Edge：弱 Paper Edge；
- Shadow：负责 Elevated 高度，不使用 Glow；
- 不使用粗金框、木纹、卷轴、云纹；
- 标题 Paper Primary；
- 说明 / Helper 使用 Paper Secondary / Muted。

Dialog 与 Settings / Load / Save / New Game 使用同一 Palette，但空间角色不同：Global Space 可以弱化世界背景；Dialog 属于 UI-over-UI，不申请第二次实时 Blur。


## 5. Header 语义 Tone

Dialog 只允许三种标题栏语义：

### Neutral

用于普通输入、绑定、一般确认。

- Header 只比 Body 略有层级；
- 无语义图标；
- 无彩色状态线；
- 标题保持 Paper Primary。

### Warning

用于存在风险、但仍可恢复或可取消的操作，例如：

- 15 秒显示设置确认；
- 覆盖存档（Warning）；
- 其它需要玩家注意但不是永久破坏的确认。

表现：

- Header 使用极弱 Aged Brass Tint；
- 顶部 2px 熟铜状态线；该状态线使用真实子元素 / VisualElement，不依赖 `::before` / `::after`；
- Bare Warning Icon 使用熟铜；
- Body 仍保持中性 Smoked Graphite；
- 不允许整块高饱和黄色标题栏。

### Danger

用于不可逆删除、严重错误或明确危险操作。

表现：

- Header 使用极弱 Cinnabar Tint；
- 顶部 2px 朱砂状态线；同样复用共享真实 Tone Line 元素；
- Bare Error / Danger Icon 使用弱朱砂；
- Danger Action Button 才使用红色语义；
- Body 仍保持中性，不把整个 Dialog 染红。

重要：

> Tone 只表达语义，不改变 Dialog 的材质家族。

## 6. Confirm Dialog

适用于：

- 返回主菜单；
- 退出游戏；
- 覆盖存档；
- 删除存档；
- 删除存档组；
- 其它需要玩家明确确认的操作。

动作顺序固定：

`取消 / 安全动作 → 确认 / 主动作`

规则：

- 普通确认使用 Primary；
- 不可恢复的数据删除只把 Danger 语义放在危险按钮上；
- 整个 Dialog Surface 不染红；
- 危险删除默认 Focus 放在取消按钮；
- Esc 永远取消，不能执行危险动作；
- Enter 只执行当前允许的确认动作。

## 7. Text Input Dialog

用于：

- 城市名称；
- 新建存档命名；
- 重命名单个存档；
- 更改存档组名称；
- 后续蓝图 / 方案等持久名称。

规则：

- 页面只显示当前值与 Value Button；
- 打开后自动 Focus；
- 修改已有值时默认全选；
- Enter 确认；
- Esc 取消；
- 空值 / 校验失败时 Primary Disabled；
- Helper / Validation 固定在输入框下方；
- 输入框直接使用共享 `TextInput`，Dialog 只调整宽高等 Geometry；
- 输入框 Default 中性，Focus 才出现弱熟铜 Ring；
- 不恢复页面内长期 TextField。

## 8. Number Input Dialog

用于：

- `NumericSliderField` 精确输入；
- 需要 Min / Max / Step / Precision 校验的数值；
- 随机种子等有明确数字约束的字段。

规则：

- 与 Text Input 使用同一 Shell；
- 页面不自己实现数值输入皮肤；
- 校验失败时显示 Error，并禁用确认；
- 范围 / 步进使用 Muted Helper；
- 提交后回写原 Control。

## 9. Binding Capture Dialog

用于 Settings 按键绑定。

规则：

- 打开即进入 Listening；
- Listening 只使用弱熟铜状态，不大面积染金；
- Esc 取消；
- Backspace / Delete 清除；
- 冲突使用明确 Validation；
- 列表内不直接进入 Listening；
- 清除 / 取消 / 保存仍使用统一 Dialog Action Grammar。

## 10. Timed Confirmation

用于可能造成 UI / 显示不可操作的重要显示设置：

- 分辨率；
- 显示模式；
- HDR；
- 刷新率；
- UI Scale。

语义：

`临时应用 → 倒计时 → 保留设置 / 自动恢复`

额外内容只有：

- 设置变化摘要；
- 倒计时；
- 自动 Rollback。

Surface / Actions / Typography 与其它 Dialog 完全相同。

## 11. Toast / Notification

Toast 是非阻断式结果反馈：

- 不抢 Focus；
- 不创建 Modal Backdrop；
- 自动消失；
- 不替代需要决策的 Dialog；
- 使用同一中性 Smoked Graphite 家族；
- Success / Warning / Error 只允许在小图标与必要边缘状态中表达，不大面积染色。

## 12. 当前迁移范围

已进入统一 `DialogHost`：

- 主菜单退出确认；
- Gameplay 返回主菜单确认；
- 保存 / 覆盖 / 删除相关确认；
- 城市名称；
- 随机种子；
- 存档与存档组重命名；
- `NumericSliderField → NumberInputDialog`；
- Settings Binding Capture；
- Settings 15 秒 Safe Display Confirmation；
- Load / Save / Settings 等结果 Toast。

## 13. 禁止

禁止新增：

- 页面私有 `xxx-confirm-layer`；
- 页面私有 `xxx-name-dialog`；
- UI-over-UI 的第二次实时 Blur；
- Dialog 专属绿色 / 黑色 Root Theme；
- 大面积高饱和黄 / 红标题栏；
- 用明显颗粒 Noise 制造“磨砂玻璃”感；
- Card 内临时确认条替代正式 Dialog；
- 页面私有 Toast 样式；
- 多套不同按钮顺序；
- 常驻粗熟铜边框与 Glow。

新增确认、输入或提示时，优先扩展统一 Dialog API，而不是在业务页面新增独立 Modal DOM。


## ChoiceInput Dialog 与 Action Toast

### ChoiceInput Dialog

当一次操作必须同时输入短文本并选择一个小规模枚举项时，使用共享 ChoiceInput Dialog，不在业务 Workspace 内自行拼临时表单。

结构：

```text
Title
Text Input
Choice Label
Inline Choices
Actions
```

当前首个使用场景：材质“保存配色”的名称 + 木头 / 瓦片 / 墙面分类。

规则：

- Choice 使用共享 Dropdown-like Listbox，不横向铺开枚举项；
- 适合 Material Family 这类 5–15 项稳定枚举；
- Dropdown 菜单可内部滚动；
- 文本继续使用共享 TextInput 与 validate；
- Enter 在菜单关闭且表单合法时提交；
- Esc 优先关闭展开的 Choice Menu，再取消 Dialog；
- Unity 对应 Modal + Popup/ListView，不依赖 HTML Select。

### Action Toast

Toast 可以携带一个短生命周期 Action，例如“撤销”。

规则：

- Action 只能有一个；
- 不用于需要确认的危险操作；
- Action 本身执行业务 Command，不让 Toast 持有业务状态；
- 典型使用：移动材质分类后的“撤销”。


### Choice Layout

共享 ChoiceInput Dialog 支持两种呈现：

- `dropdown`：枚举较多或需要紧凑显示；
- `grid`：枚举数量少且需要高可见性时直接平铺。

Material Preset 的 9 个 Material Family 固定使用 `grid`：

- 3 列 × 3 行；
- 使用 Flex Wrap，不依赖 CSS Grid；
- 选中项使用熟铜轻边框与极弱 Surface Tint；
- Save / Edit 共用同一 ChoiceInput Dialog；
- Unity 对应 Radio-like Button Grid / Flex Rows。
