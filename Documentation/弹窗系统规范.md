# 弹窗系统规范

## 1. 定位

Dialog / Modal 是覆盖当前空间的 **Elevated Blocking Surface**。

它用于确认、输入、精确数值、按键捕获和安全显示回滚。它不是另一个全屏页面，也不是 Gameplay Glass。所有页面只提交业务请求，统一由全局 `DialogProvider → DialogHost → DialogFrame` 渲染。

最终 Unity UI Toolkit 必须保持同样职责边界：全局 Modal Layer 负责弹窗，业务页面不得各自维护私有弹窗皮肤。

## 2. Unity 约束与核心材质规则

正式约束：

> **Dialog 不依赖实时 Blur。**

原因是 Unity UI Toolkit 中，前景 Dialog 无法可靠地再次模糊已经绘制完成的背景 UI。Web 原型如果依赖 `backdrop-filter` 才成立，迁移后会产生明显视觉偏差。

因此：

- `.ui-modal-backdrop` 只负责半透明 Dim，不使用 Blur；
- `.ui-dialog` 本体使用自稳定的半透明 Smoked Graphite；
- Dialog 自身通过 Tint / Noise / Edge / Shadow 保证可读性；
- 不允许依赖后方 UI 被模糊后才能阅读；
- 不建立 Dialog 专属绿色、蓝色或黑色 Theme；
- Aged Brass 只用于 Focus / Primary / Listening / Current；
- Cinnabar 只用于真正不可逆的 Danger Action。

当前正式所有权：

```text
wanhu-theme-tokens.css
        ↓
wanhu-surface-system.css
        ↓
dialog.css
        ↓
DialogSystem.tsx
```

- Theme Token：Dialog Dim / Surface / Edge / Shadow；
- Surface System：Dialog Material；
- `dialog.css`：Geometry / Typography / Dialog-specific Control Layout；
- `DialogSystem.tsx`：状态、键盘行为、校验与业务回调。

## 3. 统一结构

```text
.ui-modal-layer
├ .ui-modal-backdrop
└ .ui-dialog
   ├ .ui-dialog__header
   │  ├ Title
   │  └ Optional Message
   ├ .ui-dialog__body
   │  └ Variant Content
   └ .ui-dialog__actions
      ├ Secondary
      └ Primary / Danger
```

所有阻断式弹窗必须使用同一个 `DialogFrame`。不得复制第二套 Shell。

## 4. 视觉基线

1080p 基线：

- Dialog 宽度约 `560px`；
- Radius：`12px`；
- 输入 / Button Radius：`10px`；
- Surface：中性 Smoked Graphite，半透明但可独立阅读；
- Edge：弱 Paper Edge；
- Shadow：负责 Elevated 高度，不使用 Glow；
- 无顶部装饰金线、粗金框、木纹、卷轴、云纹；
- 标题 Paper Primary；
- 说明 / Helper 使用 Paper Secondary / Muted。

Dialog 与 Settings / Load / Save / New Game 使用同一 Palette，但空间角色不同：Global Space 可以弱化世界背景；Dialog 属于 UI-over-UI，不申请第二次实时 Blur。

## 5. Confirm Dialog

适用于：

- 返回主菜单；
- 退出游戏；
- 覆盖存档；
- 删除存档；
- 删除存档组；
- 其它需要玩家明确确认的操作。

动作顺序固定：

`取消 / 安全动作 → 确认 / 主动作`

规则：

- 普通确认使用 Primary；
- 不可恢复的数据删除只把 Danger 语义放在危险按钮上；
- 整个 Dialog Surface 不染红；
- 危险删除默认 Focus 放在取消按钮；
- Esc 永远取消，不能执行危险动作；
- Enter 只执行当前允许的确认动作。

## 6. Text Input Dialog

用于：

- 城市名称；
- 新建存档命名；
- 重命名单个存档；
- 更改存档组名称；
- 后续蓝图 / 方案等持久名称。

规则：

- 页面只显示当前值与 Value Button；
- 打开后自动 Focus；
- 修改已有值时默认全选；
- Enter 确认；
- Esc 取消；
- 空值 / 校验失败时 Primary Disabled；
- Helper / Validation 固定在输入框下方；
- 输入框 Default 中性，Focus 才出现弱熟铜 Ring；
- 不恢复页面内长期 TextField。

## 7. Number Input Dialog

用于：

- `NumericSliderField` 精确输入；
- 需要 Min / Max / Step / Precision 校验的数值；
- 随机种子等有明确数字约束的字段。

规则：

- 与 Text Input 使用同一 Shell；
- 页面不自己实现数值输入皮肤；
- 校验失败时显示 Error，并禁用确认；
- 范围 / 步进使用 Muted Helper；
- 提交后回写原 Control。

## 8. Binding Capture Dialog

用于 Settings 按键绑定。

规则：

- 打开即进入 Listening；
- Listening 只使用弱熟铜状态，不大面积染金；
- Esc 取消；
- Backspace / Delete 清除；
- 冲突使用明确 Validation；
- 列表内不直接进入 Listening；
- 清除 / 取消 / 保存仍使用统一 Dialog Action Grammar。

## 9. Timed Confirmation

用于可能造成 UI / 显示不可操作的重要显示设置：

- 分辨率；
- 显示模式；
- HDR；
- 刷新率；
- UI Scale。

语义：

`临时应用 → 倒计时 → 保留设置 / 自动恢复`

额外内容只有：

- 设置变化摘要；
- 倒计时；
- 自动 Rollback。

Surface / Actions / Typography 与其它 Dialog 完全相同。

## 10. Toast / Notification

Toast 是非阻断式结果反馈：

- 不抢 Focus；
- 不创建 Modal Backdrop；
- 自动消失；
- 不替代需要决策的 Dialog；
- 使用同一中性 Smoked Graphite 家族；
- Success / Warning / Error 只允许在小图标与必要边缘状态中表达，不大面积染色。

## 11. 当前迁移范围

已进入统一 `DialogHost`：

- 主菜单退出确认；
- Gameplay 返回主菜单确认；
- 保存 / 覆盖 / 删除相关确认；
- 城市名称；
- 随机种子；
- 存档与存档组重命名；
- `NumericSliderField → NumberInputDialog`；
- Settings Binding Capture；
- Settings 15 秒 Safe Display Confirmation；
- Load / Save / Settings 等结果 Toast。

## 12. 禁止

禁止新增：

- 页面私有 `xxx-confirm-layer`；
- 页面私有 `xxx-name-dialog`；
- UI-over-UI 的第二次实时 Blur；
- Dialog 专属绿色 / 黑色 Root Theme；
- Card 内临时确认条替代正式 Dialog；
- 页面私有 Toast 样式；
- 多套不同按钮顺序；
- 常驻粗熟铜边框与 Glow。

新增确认、输入或提示时，优先扩展统一 Dialog API，而不是在业务页面新增独立 Modal DOM。
