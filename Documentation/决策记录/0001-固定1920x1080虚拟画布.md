# 固定 1920×1080 虚拟画布

## 决策

UI Prototype 使用固定 `1920 × 1080` 逻辑画布，再根据浏览器窗口整体等比缩放。

## 原因

这个项目的目标是验证游戏 UI 空间关系，而不是制作普通响应式网页。

固定画布可以稳定验证：

- HUD 与世界画面的关系；
- ToolOverlay、Workspace、Dock、Flyout 的绝对空间占用；
- 1080p 下字号、间距和信息密度；
- 后续映射到 Unity UI Toolkit 的布局关系；
- Playwright Visual Review 的截图一致性。

## 约束

- 不以手机 / 平板响应式为目标；
- 不因为浏览器窗口变化重新排版主要 UI；
- 小窗口只整体缩放；
- 浏览器 viewport、浏览器缩放比例、设备像素比不得改变虚拟画布内部的布局结构；
- 不允许用 `@media (max-width: ...)` / `@media (min-width: ...)` 改写虚拟画布内部组件的宽度、列数、间距或信息密度；
- 如历史 CSS 已存在此类媒体查询，必须由固定画布规则覆盖或清理，不能让它们影响实际原型；
- 4K 适配应在最终 Unity 项目中通过 UI Scale、分辨率策略和实际运行环境继续验证。

## 实现约定

网页原型的窗口适配只发生在最外层 `1920 × 1080` 画布缩放上。内部页面和组件按同一套 1080p 设计尺寸渲染。

为防止历史响应式样式误触发，项目允许使用 `fixed-canvas-guards.css` 作为最后加载的保护层；新增代码应优先直接避免 viewport media query，而不是继续向保护层堆叠规则。
