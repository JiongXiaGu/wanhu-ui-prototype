# 《万户天工》UI 设计原则

## 1. 核心原则：常驻 UI 必须极度克制

常驻 UI 只显示玩家**此刻完成当前任务所必须知道的信息**。

不要为了“解释清楚”“填满空间”或“显得完整”而常驻显示说明性副文案、重复摘要、英文标签、统计摘要、装饰性编号或无操作价值的 Preview。

默认判断规则：

1. 玩家不看这行文字，是否仍然知道这个控件是什么、能否正确操作？如果可以，删除。
2. 这条信息是否只是把标题换一种说法重复一次？如果是，删除。
3. 这条信息是否只在第一次理解功能时有价值？如果是，移动到 Hover Tooltip / Help。
4. 这块区域是否没有新的决策、状态或反馈，只是在占空间？如果是，删除整个区域。
5. 同一事实是否已经在同屏另一位置出现？原则上只保留一次。

## 2. 说明文本的承载方式

解释性信息默认不常驻显示。

优先级：

- 一级：控件名称本身能够表达含义，不增加说明。
- 二级：鼠标悬停约 400 ms 后显示 Tooltip。
- 三级：复杂机制使用专门 Help / 详情说明。
- 仅当信息会直接影响玩家当前决策时，才允许常驻副文案。

例如：

- `自动保存数量` 下方的“每个游戏组保留的自动存档历史”不应常驻；Hover 时再解释。
- `游戏` Tab 下方的“存档与提示”不应常驻。
- `操作提示` 下方再次解释 `GameplayOperationHints` 不应常驻。
- 参数错误、冲突、危险结果等会影响当前决定的信息，可以临时常驻。

## 3. 禁止的装饰性信息

除非承担明确导航或状态意义，否则不要使用：

- `01 / 02 / 03 / 04` 等装饰编号；
- 无必要的 `>` / `→` 箭头；
- `OPTIONS`、`GAMEPLAY`、`DISPLAY OUTPUT` 等仅为气氛存在的英文眉题；
- 重复的页面副标题；
- 为填充空白创建的 Preview / Summary / Statistics；
- 无交互价值的品牌尾标；
- 每个项目都包一层 Card。

## 4. 信息层级

每个 UI Space 建议最多保留三层信息：

1. **当前空间/任务**：页面标题、当前工具、当前城市等。
2. **当前可操作项**：按钮、参数、模式、列表。
3. **必要状态反馈**：选中、错误、危险、进度、不可用原因。

解释、教程、背景知识不属于常驻第四层，应进入 Tooltip / Help。

## 5. Surface 与留白

留白本身就是设计，不要因为存在空白就增加内容。

- 世界画面优先于 UI 填满屏幕。
- 大面板内部允许明显留白。
- 同屏最多一个重面板。
- 能用 Divider / 对齐解决层级时，不再增加 Card / Box。
- 不为了“视觉平衡”增加没有信息价值的右栏。

## 6. Tooltip 规范

用于图标、缩写、低频参数和解释性细节。

- Hover 延迟约 400 ms。
- 默认纯文本，不重复预览图。
- 第一行说明“是什么 / 做什么”。
- 必要时第二行补充影响或快捷键。
- Tooltip 不可成为完成基本操作的必需步骤；核心控件仍应可识别。

## 7. 审查清单

每次新增或修改 UI 前检查：

- [ ] 是否存在标题与副标题重复表达？
- [ ] 是否存在控件下方不必要的解释小字？
- [ ] 是否存在同一信息重复出现？
- [ ] 是否为了填空增加 Preview / Statistics / 装饰？
- [ ] 是否存在无意义编号、箭头、英文眉题？
- [ ] 是否能把低频解释移动到 Tooltip？
- [ ] 当前状态是否只强调一处？
- [ ] 页面是否仍让主要游戏内容成为视觉主体？
- [ ] 删除 20% 的文字后是否仍然完全可用？如果是，应删除。

## 8. 当前项目设计基调

- 黛墨底、浅纸文字、暖金只用于 Selected / Focus / 高价值状态。
- 细边框、弱阴影、小圆角或近直角。
- 世界是视觉主体，不使用繁复古风装饰。
- 共享控件保持统一语言：Icon Cell、Segmented Control、Parameter Row、Keycap、Tooltip。
- 功能语义优先于视觉填充；宁可留空，也不要增加无意义信息。
